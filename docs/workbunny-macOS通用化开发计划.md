# WorkBunny macOS 通用化开发计划

2026-10-30 · 0.13.0 候选版实施记录（保留 r2 设计与验收要求）。连接、语音兼容、HTTP TTS、迁移和打包架构已实现并完成本机隔离调试；公开包现仅带明确许可资源；跨机及旧系统实机验收仍有边界。日常安装和正式资料未被替换。实施状态见第13节，证据见 `workbunny-0.13.0-验收.json`。

## 1. 目标与范围

交付一个普通用户下载后可以安装、连接自己的 WorkBuddy、使用语音并保留长期关系的 Apple Silicon 应用。继续沿用当前对话、预测、记忆、Dream、自我理解、兴趣目标、Secretary 和授权体系；本轮解决环境适配与交付，不重写陪伴核心。

| 项目 | 本轮约定 |
| --- | --- |
| 平台 | 仅 Apple Silicon，单一 arm64 安装包；不按 M 系列代数设门槛 |
| 系统 | 本体以 macOS 13 Ventura（2022）为最低兼容目标，覆盖 14、15、26；新增系统分别验收 |
| 模型与工作 | 必须安装并登录兼容版本的 WorkBuddy；LLM、后台整理、搜索、任务监督沿用其账号通道 |
| 识别 | 26 优先持续端侧识别；13～15 默认按次识别；失败不妨碍本地设置、文字输入与资料管理 |
| 发声 | 系统默认音色、本地 Qwen、标准 CHP、自定义 HTTP 四种入口；只有一个当前使用的入口 |
| Qwen | 内存至少 16 GiB，不按芯片代数锁定；效果由安装后试听决定，不设置 24 GiB 硬门槛 |
| 回声 | Bunny 自动管理；无可靠消除能力时采用播放期间暂停识别，用户不配置 AEC |
| 角色 | 随包提供四个官方角色及完整配套资源；不打包个人导入模型 |
| 数据库 | 默认当前用户应用数据目录下的 `vault`；允许改位置并迁移完整资料库 |
| 发布 | 开源、站外下载、自签名发行，不把苹果开发者账号或公证作为本轮前置条件 |

要求对应：WorkBuddy → G2；低系统/自动回声处理 → G1/G3；四种发声与通用配置 → G3/G4/G5；16 GiB → G5；数据库改位置 → G6；四角色、设备信息清理、自签名开源发行 → G7。G8 验证它们组合后的实际行为。

不新增云端服务、第二套记忆库、插件市场、多账号资料库、任意脚本执行器、全双工音频重构、自动更新服务或 Intel 支持。WorkBuddy 保持复杂任务执行者的定位；连接成功不产生新的桌面或主动联系权限。

## 3. 收敛后的结构

保留现有主进程组合方式，只补有限的边界模块，不建立通用插件框架。

```text
界面 / preload
    ↓ 窄 IPC，状态与操作分开
主进程启动与生命周期
    ├─ runtime-capabilities：OS、内存、辅助程序与可用语音模式
    ├─ workbuddy-connection：发现、认证、模型目录、监督连接与失效处理
    ├─ asr.js / tts.js：现有语音入口 + 旧识别 / 自定义 HTTP 适配
    ├─ data-location：解析 Vault 位置、迁移、恢复
    └─ 现有 MemoryService / Dream / Secretary / 成长与授权
```

建议新增 `runtime-capabilities.js`、`workbuddy-connection.js`、`data-location.js`、`tts-http.js`、`tts-http-profile.js` 和 `native/asr-legacy.swift`；以现有入口为主，只有职责独立时才拆文件。外部 TTS 的配置与结果仍经过 `config.js`、`tts.js`、`tts-session.js`，不再建立第二套播放器或设置保存机制。

能力状态使用固定枚举和原因码，例如可用、待配置、待授权、不支持、暂不可用；界面显示下一步动作。系统版本、硬件条件与运行探测分开，不用一个 `ready` 布尔值混合“已登录”“有模型”“有语音权限”和“可以操作桌面”。

## 4. 启动与 WorkBuddy 一键连接

### 4.1 用户流程

首次显示“连接 WorkBuddy”。自动检查已有安装和登录状态；已就绪时直接连接，按钮承担重新连接与诊断。缺少安装时提供官方下载入口；已安装未运行时唤起；登录由用户在 WorkBuddy 中完成。登录后自动继续连接，无需重复填目录或密钥。

连接依次完成：

1. 按应用标识发现、必要时启动 WorkBuddy；不固定安装路径。
2. 发现当前用户 broker，使用现有挑战认证与动态 pipe，检查协议和调用能力。
3. 获取账号模型目录，确认至少一个可用文本模型；保留仍有效的原选择，新用户自动选择可用默认项。
4. 接入当前用户任务目录。目录尚未产生时显示“等待第一项任务”，不冒充连接失败。
5. 发布模型、监督两个独立状态；需要时由用户点击“测试回答”发起一次可见、可能计费的短请求。

没有兼容 WorkBuddy 时暂停模型调用、自动学习和工作监督，展示安装/登录/升级动作；本地设置、记忆查看、加密备份、数据库迁移仍可使用。连接检测不持续调用 LLM，不为探测而生成任务或改写 WorkBuddy 配置。

### 4.2 失效与模型策略

- WorkBuddy 是本轮唯一 LLM 来源，前台与后台共用连接状态；旧外部 LLM 设置只作兼容保留，不被继续调用或写入人格。
- 抽取、Dream、成长提案、搜索、桌面规划、结果核验及前台对话都检查连接代次；不只在聊天按钮入口拦截。设置与 IPC 也不能通过旧 `provider/baseURL` 绕到外部 LLM。目录探测不产生 LLM 调用。
- 新用户按目录选择可用文本模型，显示账号计费信息；已有有效模型不被重新推荐覆盖。后台维持“只调用目录确认免费的模型”，无免费模型时暂停并明确说明，不自动切付费。
- pipe 撤销、退出登录、账号切换、网络故障分别报告。使旧请求失效，停止新的后台调用，暂停依赖它的桌面动作与监督，清空当前监督视图和旧目录缓存，重新认证后从真实状态恢复；不自动重发用户消息、创建任务或重复发送外部消息。账号切换不清空 Bunny 自己的资料库，不新增按云账号分库。
- broker 票据只在内存使用，每次重连重新发现；不进入设置、导出、日志、界面或提示词。
- 任务观察保留原场景过滤、来源与历史事件去重。辅助功能、屏幕录制只在实际桌面操作需要时申请；连接按钮不自动启用自主授权。
- 本地 broker 和任务日志是版本相关契约。支持的 WorkBuddy 版本以功能探测和实测结果标记，不凭安装成功宣布兼容。

## 5. 系统与语音能力分级

### 5.1 单包、多能力

应用声明及基础辅助程序目标为 macOS 13。当前 `asr` 作为 26 专用程序保留，新增 13 基线的 `asr-legacy`。启动器先读系统版本，13～15 绝不运行 26 程序；26 仍检查语言和模块可用性，不可用时退到旧识别。

两种识别共用 `auth / ready / partial / utterance / final / level / error / end` 事件；保留真实采集心跳、进程代次、取消、锁屏退出和失败退避，避免重写对话轮次。能力结果增加 `mode: continuous|single|unavailable` 与可操作原因，区分授权、语言资产与引擎可用性。`ready` 仍要求真实音频和识别链路就绪。保留用户持续聆听偏好，临时降级不永久改写该偏好；按次模式不进入现有常驻识别重启循环。

| 情况 | 行为 |
| --- | --- |
| 新识别可用且用户开启持续聆听 | 沿用持续收听、静音切句与当前轮次协议 |
| 13～15，或新识别不支持该设备/语言 | 默认点击开始/结束，单次最多 45 秒，不无限重启任务模拟持续监听 |
| 旧识别支持端侧语言 | 强制端侧识别；缺少资源或系统听写条件时显示准备/修复入口 |
| 旧识别只能联网 | 明确说明音频处理方式，用户选择允许后才启用；否则保持文字输入 |
| 拒绝麦克风、无输入设备、识别不可用 | 有限退避并显示状态，不反复弹权限或进入重启循环 |

按次识别保留手动“说完了”动作；停止时只有最终文本进入一次对话，取消不提交。第一次使用语音再请求权限，启动连接向导不自动开麦。系统默认输入随设备变更重建链路，不保存运行期设备数字 ID，不靠环境音量自动挑选用户的麦克风。

### 5.2 回声与播放

本轮基线是自动半双工：合成时允许继续采集，真正播放前关闭识别输入，播放完成/取消/错误/设备变化后恢复。沿用现有播放队列，统一生命周期，避免各引擎自己控制麦克风。

现有系统 AEC 只能在有真实回声参考链路且验证有效时启用；`setVoiceProcessingEnabled(true)` 返回成功不等于回声已经消除。当前原生输入和渲染器播放分离，不为本轮承诺通用全双工。无可验证 AEC 时自动半双工，不向用户暴露调参项。

修正与新语音入口牵连的播放超时：长音频仍在播放时不能被固定 25 秒“开麦自救”提前恢复识别；主进程与原生程序使用同一播放代次/状态，超时应停止失效播放再恢复识别，不能在音频仍输出时开麦。手动停止、换引擎、锁屏、断开设备或渲染器失败均只收尾当前代次，不影响新播放。合成超时与播放超时分别管理，新的 HTTP 入口不得落入目前“其他引擎 30 秒”的错误分支。

### 5.3 系统语音与本地 Qwen

- 新用户 `voice` 使用“系统默认”语义，不再指定固定中文人名；用户明确选过且仍存在的音色保留。按系统语言列出本机音色，不把默认音色固定到中文列表。
- Qwen 仅以物理内存 `>= 16 × 1024³` 字节为硬件门槛；本体、系统语音和外部 TTS 不受此限制。检查同时作用于下载、预热和启用，避免迁移设置绕过。
- 保留当前模型、校验和运行时配对；内置运行程序，权重仍由用户下载。试听展示冷启动/预热、首音等待、生成时间与音频时长，不宣称 16 GiB 已有流畅性保证。
- 不因一次慢试音禁用满足门槛的设备。失败可回到系统语音，保留模型文件及用户配置。
- 当前运行程序最低 15：先用固定源码尝试构建 13 目标并验证动态依赖和真实合成。若不可行，本体仍支持 13，13/14 明确提示本地模型当前不可用，提供系统/外部语音；不得修改 Mach-O 声明假装兼容。此差异必须进入发布说明和验收记录。
- macOS 13 截图用 SCStream 取一帧，14 以上用现有 SCScreenshotManager。补齐窗口像素缩放、无阴影、坐标转换和权限差异测试，保持原窗口/收件人核对边界。

## 6. 统一 TTS 配置与自定义 HTTP

### 6.1 用户流程与边界

设置仅显示“系统语音 / Qwen 本地 / CHP / 自定义 HTTP”，不列参考厂商品牌。

CHP 沿用“填地址和访问密钥 → 获取服务信息 → 选择可用音色 → 试听”。严格读取服务声明的端点、规则、音色、格式和默认项；只有一个服务端加载模型时显示该模型，不提供无效的客户端切模型动作，不内置任何私有设备名称、地址或运维方式。

自定义 HTTP 使用一个当前配置：选择通用模板或导入配置 → 填地址、凭据及必要资源参数 → 获取或填写模型和音色 → 试听 → 保存。首版内置“HTTP 直接音频”“HTTP JSON 音频分片”两个不含地址/密钥的起始模板，后者覆盖参考 V3 的请求与返回形状；SSE 可由受约束配置选择。普通用户不必从空白 JSON 开始，模板也不按网址推测协议。允许高级用户编辑受约束的配置文件，但本轮不做可视化协议编辑器、cURL 命令解析器或可执行插件。切换模板只修改草稿，不覆盖已保存连接。

目录发现是可选能力：有查询接口就获取并映射列表；没有时用配置提供的候选或手填 ID，显示来源。模型、资源与音色不是同一个字段，模型项可携带资源 ID 并约束适用音色；手填组合由试听验证。合成凭据不保证拥有目录查询权限；不因此额外索要云账号管理密钥，也不抓取控制台网页。

### 6.2 声明式配置

`workbunny-tts-http/v1` 只描述以下内容：

| 区域 | 必要能力 |
| --- | --- |
| 请求 | HTTP/HTTPS POST、固定地址、受限请求头、JSON body；本地 HTTP 可用，云端示例使用 HTTPS |
| 参数 | 文本、音色、模型、资源 ID、语言、语速、每请求 UUID；按完整值绑定，禁止拼接 JSON 源码 |
| 凭据 | API Key 或多项请求头凭据；值留主进程，配置公开视图只返回“已填写” |
| 返回 | 音频二进制、单个 JSON、逐行 JSON、SSE；支持字段内严格 Base64 音频 |
| 状态 | JSON 字段路径、允许的分片/结束状态、错误判定；HTTP 200 不直接视为合成成功 |
| 音频 | 首版支持 PCM16LE 与 WAV，要求 24 kHz 单声道；其他格式给出可操作的不支持提示 |
| 目录 | 可选模型/音色请求、条目 ID/名称字段映射，或静态候选；缺失可手填 |

占位符只允许有限的参数和凭据引用，UUID 由主进程生成；路径只支持键/数组位置，不支持表达式、函数、脚本或任意执行。输入由 JSON 解析和结构校验处理，导入文件不执行命令。未知必填字段、重复头、换行头和越界参数在发请求前拒绝。

首版配置的最小形状如下。`$param`/`$secret` 是只能完整替换一个值的绑定，普通文字不会被二次解释；`requestId` 为每次请求新生成的 UUID。实际凭据和参数值保存在当前用户的私有配置中，不进入此文件。

```json
{
  "format": "workbunny-tts-http/v1",
  "url": "https://tts.example.invalid/api/v3/tts/unidirectional",
  "headers": {
    "X-Api-Key": { "$secret": "apiKey" },
    "X-Api-Resource-Id": { "$param": "resourceId" },
    "X-Api-Request-Id": { "$param": "requestId" }
  },
  "body": {
    "req_params": {
      "text": { "$param": "text" },
      "speaker": { "$param": "voice" },
      "audio_params": { "format": "pcm", "sample_rate": 24000 }
    }
  },
  "response": {
    "framing": "jsonl",
    "audioPath": ["data"],
    "statusPath": ["code"],
    "chunkCodes": [0],
    "doneCodes": [20000000],
    "audio": { "encoding": "base64", "format": "pcm16le", "sampleRate": 24000, "channels": 1 }
  }
}
```

`framing` 固定为 `binary|json|jsonl|sse`，音频编码固定为 `binary|base64`。二进制以成功 HTTP 和合法音频完成；JSON/分片接口明确配置结束码或允许 EOF 完成，不猜测业务码。`chunkCodes` 对应的无音频字幕事件可忽略，未知状态或错误必须失败。可选 `catalogs.models/voices` 使用受限 GET/POST、条目数组路径和 ID/名称/关联资源字段映射；本轮不支持多步登录、HMAC 签名或通用抓取引擎。新版单头与旧版双头合成鉴权均在本轮范围内。

参考 V3 合成接口必须能仅靠上述配置表达：`X-Api-Key`（或旧版双头凭据）、`X-Api-Resource-Id`、请求 UUID，嵌套 `req_params.text / speaker / audio_params`，以及从 `data` 读取 Base64 音频、忽略字幕事件、以声明的结束状态完成。适配器里不得按域名或品牌写特例。

### 6.3 复用音频链路

- 新适配器接收 AbortSignal，返回现有 `tts.synthesize` 格式的 24 kHz/单声道/PCM16 WAV 和脱敏元数据。
- 本轮先完整读取一条句子的 HTTP 分片，再复用播放器播放；接收 SSE 不等于承诺首分片即播放。保留已有 Qwen 流式，不新增外部 WebSocket 二进制协议或媒体转码程序。
- 逐行 JSON/SSE 按协议边界解析，不能把 TCP 分片当作完整 JSON；UTF-8 跨包、空行、多事件、字幕、结束码和错误码都覆盖。新 HTTP 默认上限：每句 2000 字符、32 MiB 响应、60 秒解码后音频、30 秒首音数据等待、90 秒合成总时间；目录请求 15 秒。配置只能调低上限，不靠心跳包无限续命。统一取消后不再回调旧结果，不自动重试可能计费的合成请求。
- 试听必须返回实际使用的引擎、音色与失败原因。测试外部配置时不自动用系统语音冒充成功；只有真实请求、合法音频、带试听 ID 的实际播放回执都成功才标记“试听通过”。试听沿用播放代次与回声处理，但不写成主人对话、不产生预测或触发记忆学习；错误回执不能被上一段播放覆盖。
- 普通对话失败使用现有系统语音降级；重试目标配置由用户显式恢复，避免每句重复撞超时。旧请求不能覆盖新的引擎或音色设置。
- 将规范化配置版本、请求地址、模型/资源、音色、格式和凭据摘要纳入统一缓存标识；沿用现有哈希缓存，不在文件名或日志暴露密钥。修改配置或系统默认音色变化时使相关缓存失效，覆盖普通合成、预取和 `InteractionAudio`，避免换接口后播放旧声音。
- 主界面只有实际输出引擎与可操作原因，不显示内部协议流水账；日志不得打印文本、凭据、原始响应或带鉴权的 URL。

### 6.4 配置安全与兼容

沿用现有私有配置文件、权限和原子写入，本轮不增加第二套密钥仓库；这意味着配置凭据继续受本机私有文件权限保护，不能宣称它们已全部加密。新增自定义头的自由填写值默认按敏感值处理，公开参数仅通过显式参数绑定展示；不能只复用目前针对 `apiKey` 字段的浅层过滤。配置导出剔除所有凭据；目录结果也只接收白名单字段。

导入上限 128 KiB、32 个请求头、12 层 JSON 嵌套；目录最多接受 500 项。拒绝原型污染键、控制字符和凭据进入 URL，禁止改写 Host、Cookie、Content-Length 等传输控制头。非法配置在保存/发送前给出字段级错误；私有配置仍以 0600 原子替换。

凭据不会从 WorkBuddy 复制到 TTS，CHP 与 HTTP 不共享密钥。外部请求禁用自动重定向，不将凭据自动转发到其他域名；目录地址和合成地址独立声明各自凭据绑定。不接收服务端返回的可执行配置，不把接口错误原文送入 LLM。

保留现有 `tts.engine=remote` 与地址/音色等字段，不强制重设既有服务；新增 HTTP 子配置与版本。未编辑字段、原 Qwen 路径和已选音色不被初始化向导覆盖。保存失败继续使用上一份有效配置。

## 7. 数据库位置与迁移

### 7.1 只移动资料库

```text
稳定应用目录（当前用户 Application Support/workbunny）
    config.json、model-catalog.json、日志、缓存、models/
    storage-location.json     # 只记录资料库位置及格式版本
    storage-migration.json    # 一次迁移的阶段、两端位置、校验清单
    vault/                    # 默认资料库，现有用户原地继续使用

用户选择的父目录/
    vault/                    # 自定义位置，保持目录名及钥匙标识
```

当前聊天、记忆、人格、成长、任务、监督、联系人等均在同一个 `companion.db`，迁移完整 `vault`，包括 `key-envelope`、`key-provider.json` 等解密所需文件；未来增加库文件也必须进入同一迁移清单。配置、模型权重、缓存及授权创作目录保持原位置，从而不改任务文件引用、不扩大路径授权。界面明确称“数据库位置”，避免用户误认为同时移动全部下载内容。

路径解析集中在 `data-location`，MemoryService 与两套钥匙调用都使用同一个解析结果。仅从未迁移且指针真正不存在时使用原 `vault`；指针损坏、已有迁移记录但指针缺失、目标不可读或钥匙冲突均进入恢复界面，不默默创建新库。目录/文件链接在迁移前检查，不跟随其复制到其他位置。

### 7.2 迁移事务

用户操作“迁移并重启”，显示实际目标、资料量和保留旧快照的行为。只允许在本机解锁后执行。

1. **检查目标：**确认新旧不是相同目录或相互嵌套，校验实际路径、可写性、空闲空间及文件权限；目的 `vault` 必须不存在，不自动合并或覆盖其他库。首版支持可正常加锁的本地目录和外置磁盘，不承诺网络盘、多设备共享库或云同步并发。
2. **暂停与排空：**单实例与资料库迁移锁防止两个 Bunny 同时写；停止输入提交、后台整理和自主活动，取消未落盘请求，暂停 Bunny 代办并保存真实状态，等待串行写入排空。WorkBuddy 正在执行的工作不被擅自停止，也不因重启重派。
3. **一致关闭：**新增显式 checkpoint/关闭握手，确认 WAL 已归并且原生库进程正常关闭，不能把 `VaultDB.close()` 超时强杀等同于成功。失败立即中止，原位置继续有效。
4. **复制到目标临时目录：**保留原库和钥匙文件；复制清单全部文件，处理过程不重建密钥、不导出明文、不调用恢复接口重写记录。
5. **验证：**文件哈希、库完整性、记录 ID/数量、原始密文、钥匙标识与来源关系一致；用专门只读校验入口检查能用原钥匙解密，禁止创建库文件或调用 MemoryService 的初始化、回填和恢复写入。校验分批进行，避免全库明文常驻内存。失败清理本次临时目录，不修改原库。
6. **提交：**验证完成后先将原权限写入日志、把已关闭的原库设为只读快照；失败则中止。再将临时目录在目标磁盘内改名为 `vault`，持久化后原子写位置指针；原子指针是生效依据。记录迁移阶段并有序重启，禁止旧进程继续写两端。
7. **新位置启动：**先核对目标身份和可读性，再开放正常写入。旧目录继续作为迁移时只读快照，用户确认后另行清理，本轮不自动删除。旧版软件不识别位置指针，软件降级前必须先迁回默认位置或按备份恢复流程处理。

迁移日志按 `checked → quiesced → copied → verified → activated` 记录，两端路径、事务 ID、校验和、原权限均写入稳定应用目录；位置指针原子提交是唯一切换点。指针提交前失败须恢复原权限并重启原库，或提示重启恢复；不能让半初始化服务继续接收输入。提交后崩溃按指针恢复，不因日志最后一行尚未更新而重做迁移。临时目录只清理本事务明确拥有的内容。

新位置开始产生新记录后，不自动切回旧快照，避免丢失新经历或产生两份分叉资料。第一次新位置验证失败且确认尚未有新写入时才可回到原库；无法确认时进入恢复界面。外置盘拔出时锁定写入并提示重新连接，记忆启用状态下不得继续形成仅存 RAM 的隐形历史。

同机改目录继续使用同一 Keychain 账号；跨机仍使用现有独立密码加密备份，不能把移动目录当作跨机钥匙迁移。

## 11. 自审、优化与重构结果

已在首稿后按需求、现有调用链和故障恢复重新审查，并将结论直接合并到前面章节；本节只记录改变设计的要点，不保留互相冲突的备选架构。

| 自审发现 | r2 的确定决策 |
| --- | --- |
| “通用化”容易扩大成外部 LLM 平台与插件系统 | WorkBuddy 唯一 LLM；只补连接状态和有限适配器，G0～G8 共用现有核心 |
| 移动整个应用数据目录会牵连模型、创作权限与绝对路径 | 只移动完整 Vault，稳定位置文件留在原应用目录；迁移后有序重启 |
| 只检查复制成功，仍可能丢 WAL 或产生新旧库分叉 | 显式 checkpoint/关闭、只读验证、原子指针、只读旧快照；新写入后不自动回旧库 |
| 默认目录回退可能把拔盘或坏指针误判成首次安装 | 有迁移痕迹就进入恢复，不新建；双实例和看门狗纳入迁移状态 |
| “获取模型/音色”不能覆盖所有服务权限 | 查询可选，支持静态/手填并标明来源；以真实试听核对资源和音色组合 |
| 要求用户先编写配置文件会偏离简单连接流程 | 提供无品牌通用起始模板；协议细节仍是一份受约束配置，不增加可视化协议编辑器 |
| 新接口只改网络请求会遗漏缓存和假试听成功 | 规范化配置进入所有音频缓存键；严格试听不允许系统回退冒充成功 |
| 持续识别、AEC、外部流式播放一起重写会扩大风险 | 旧系统按次识别；自动半双工为基线；先拼接 HTTP 分片，保留既有 Qwen 流式 |
| 私有配置脱敏只检查 `apiKey`，新自定义头可能泄露 | 敏感值只留主进程，所有公开/导出路径白名单化；配置仅声明，不执行 |
| 签名便利回退、改应用名和开发身份可能破坏钥匙 | 无有效自签名即停止构建，两条原生父进程链同步校验；开发资料独立 |
| 编译成功容易被写成旧系统/云服务兼容已完成 | 分开编译、模拟、实际旧系统、真实账号、新机下载证据；未验证不升级措辞 |
