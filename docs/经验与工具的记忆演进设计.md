# 经验与工具的 Dream / Deepdream 演进设计

日期：2026-11-03。本文为设计与实施规划，基于当前工作区 0.24.6 源码，**不表示功能已经实现**。它细化[整体架构设计](整体架构设计.md)中的记忆系统，并与[任务系统重构计划](2026-11-03-统一任务编排重构计划.md)共同实施。

## 1. 概念和选择

经验是主要服务任务执行的特殊记忆，记录某类目标下的方法、适用条件、实际结果和可借鉴的教训；工具是经验引用的可用资源。软件技能可以是经验中的分类，或按软件、用途等标签筛选出的一组经验，而非另一套独立的知识库。一条经验可以没有专用工具，也可以引用多个工具；一个工具可以被多条经验共享。工具可以是内置能力、主人或外部提供的资源，也可以由 Bunny 在已有授权内为任务创造或改进。经验提供思路，Bunny 仍根据现实自主判断、尝试和学习。

采用**一套记忆整理调度、两类按需处理方式**：

- **Dream** 从对话、任务过程、操作结果和工具使用反馈中提炼经验候选及工具引用。
- **Deepdream** 将新经验与已有经验、工具资源及历史证据关联，整理重复、冲突、适用条件、工具版本和失效情况，形成可复用、可修正的理解。
- 保留现有对话记忆处理方式；为任务经验和工具引用增加专用输入、验证与整理逻辑，可称为经验/工具专用变体，但仍使用同一 `MemoryMaintenance` 调度、预算、状态和加密来源体系。是否把相关材料放在同一次模型调用中由上下文和来源范围决定，不要求混成一个大提示词，也不另建常驻进程或平行记忆系统。
- **Doze** 继续形成对话 Summary；任务经验的提炼和经验关系整理分别属于 Dream 和 Deepdream。实时任务不等待后台整理才能继续，也不依赖固定次数的历史成功才能尝试新方法。

## 2. 现有代码依据与缺口

| 代码 | 当前能力 | 需要补齐的地方 |
| --- | --- | --- |
| [`memory-maintenance.js`](../src/main/memory-maintenance.js) | 统一调度 Doze、Dream、Deepdream，已有场景分区、分批、预算、状态、水位和来源快照检查。 | Dream 当前以 `message` 为主要输入，候选来源和引文按消息正文校验；不能直接把操作回执伪装成对话消息。 |
| [`deepdream.js`](../src/main/deepdream.js)、[`semantic-dream.js`](../src/main/semantic-dream.js) | 按分区增量和历史样本整理普通 `memory`，检查关系与引用证据。 | 当前主要读取 `memory` 并以消息来源校验；尚未覆盖存于其他记录类型的任务经验、技能知识及工具资源。 |
| [`agent-learning.js`](../src/main/agent-learning.js) | 形成技能知识候选、按真实任务累计证明；部分完成任务可从失败与恢复中提炼方法，并有失效/回退逻辑。 | 经验形成与验证分散在任务回调，覆盖场景有限；持续任务可能长期不进入 `completed`，不能只等任务结束才学习。 |
| [`experience-memory.js`](../src/main/experience-memory.js) | 从验收过的任务保存经验和带文件指纹的工具索引，并按范围检索；当前历史工具主要作为资料提供，不能据此宣称已可自主执行。 | 需要统一接入经验记忆及其工具资源引用，并让任务系统在已有授权与工具契约下按需使用。 |
| [`agent-tools.js`](../src/main/agent-tools.js)、[`software-skill-package.js`](../src/main/software-skill-package.js) | 前者提供工具契约与当前技能工具清单校验，后者加载带清单和 hash 的内置软件经验。 | 将技能方法从硬性工具清单中解耦，让已授权的通用工具和实际创建的新工具可以被合适任务使用；维持真实能力校验。 |

当前 `AgentLearning` 经验、历史任务经验和工具索引分别使用不同记录形态。首先为它们增加兼容读取和来源适配，再逐步收敛；不假定已有记录已在同一个表或相同 schema 中。

当前 `software-skill-package.js` 按清单将内置 Markdown 拼为指引，`SkillRegistry` 中的技能还包含 `run`、能力和工具清单；尚不存在统一的“经验标签视图 + 按需组装”功能。软件知识需逐步适配成可查询经验；既有执行入口、版本校验及在途任务要保持兼容，不能把可执行适配器直接当作纯记忆删除。

## 3. 经验、工具资源和证据

### 3.1 经验是记忆

一条经验应能回答：适用于什么目标和环境、遇到什么情况、有哪些可参考的方法或替代方法、使用了哪些工具、实际发生了什么、是否存在限制或待核实处。至少保留可追溯的经验标识、来源、场景范围、版本、适用条件、相关工具引用及证据状态。失败经验和未解决的问题同样有价值；模型推测、主人传授、隔离验证、单次真实成功及更广验证分别表达，不能把一次结果推广为普遍规律。

相似经验可以相互关联，一条经验可引用另一条经验或多个工具；合并时保留各自条件和证据，不覆盖主人原话、真实任务记录或不同环境下的替代方案。可以先支持现有记录字段与适配器，不因概念统一就强制新增数据库表或全量改写旧数据。

可按软件、用途、问题、环境等分类或标签组织经验；标签可以来自内置资料、主人传授或 Dream 提炼，并随实际反馈修正。标签支持组合查询，同一经验可属于多个软件或用途；标签不足或不准确时仍可按目标和内容相关性发现经验。标签只帮助检索，不能改变来源权限、验证状态或工具授权。

### 3.2 工具是经验引用的资源

工具资源目录记录身份、用途、可调用方式、输入输出与副作用、依赖、版本或文件指纹、来源、适用范围和实际验证结果；程序文件留在经授权的位置，经验保存引用而不复制每个文件。一个工具可被多条经验引用，更新工具不应悄悄改写历史经验所引用的旧版本。

资源可以先于经验登记：内置通用工具、外部提供的工具或新建工具即使暂时没有成熟经验，也应能被检索，并在已有授权内按实际影响试用；试用后的结果可形成新经验。不能为了满足数据形式虚构经验，也不能把经验里的工具引用当作新的权限。调用时由任务系统重新检查对象、实际能力、版本及现有授权。

### 3.3 什么算证据

Dream 接收的输入要区分主人明确传授、外部内容、实际观察、工具结果、任务回执和模型假设。任务成功、失败、未发令、效果未知和已核验结果分别记录；结果未知不能被总结成成功或失败。结构化任务证据应引用真实动作、阶段、操作版本和回执；对话提炼仍沿用真实消息来源校验。工具文件的存在、内容指纹、能否执行和本次任务是否成功是不同事实，各自核验，不凭模型自评提升状态。

对于会持续更新的长任务，应以已提交的不可变动作结果或阶段证据快照作为经验依据，并关联原任务与必要来源；不要用整条持续变化的任务记录的内容指纹作为该动作的永久证据。源记录被删除、权限改变或证据失效后仍须按来源规则失效或重核验。

### 3.4 经验如何进入任务上下文

上下文组装器根据任务目标、软件、操作阶段、当前环境和遇到的问题，先按场景与来源权限过滤，再结合分类/标签、内容相关性、适用条件、时效、可信状态和近期结果选择经验。同一软件中可只取当前所需方面；缺少准确标签或遇到新软件时，继续检索相关经验和已授权通用工具，不让标签成为行动门槛。

简单情况可提供概要；每条概要需保留会影响选择的适用条件、证据/可信状态、主要方法或替代方案和必要资源引用。需要操作细节、排查失败、处理冲突或模型请求更多信息时，再按引用取得完整经验和必要证据。概要不能把推测改写成事实、遗漏关键限制或抹掉不同条件下的替代方法。组装器按模型预算选择条数、粒度与内容，阶段或环境变化时按需刷新，不必为每次筛选额外调用模型。

内置、外部提供和任务中学到的经验统一通过兼容适配器查询，保留各自来源和验证状态；经验引用的工具信息可按需附上，任务系统也能独立发现可用工具。实际调用继续由宿主检查版本、参数、对象与授权。经验检索和后台整理不可用时，使用现有上下文及可用能力继续任务，不为等待检索而无故停顿。

## 4. Dream：把经历变成经验和工具引用

1. **触发**：主人传授或纠正、一次动作得到真实结果、失败后找到方法、创建/更新工具，或任务完成时，留下最小的可追溯学习线索。持续监听任务每完成一个有意义的动作或恢复片段，也可触发；不能只依赖整个任务结束。
2. **选择材料**：在已有调度器中按来源类型、任务目标、场景和可见范围分批选择必要记录。对话经验使用原消息及适用上下文；任务经验使用状态、动作、尝试、结果和证据；工具资源使用真实版本、来源和验证记录。语义相关且权限一致的材料可以联合分析，其余分别处理。
3. **按类型提炼**：对话型输出用户传授或观察；任务型提炼问题、适用条件、方法、结果及可能的工具引用；工具型识别已存在或已创建的资源及其适用性。模型只提出候选和依据，不直接执行工具、修改授权或声称候选已经被验证。
4. **程序核验和入库**：对消息、任务回执和工具文件分别使用适合各自来源的验证器；核对来源仍有效、权限范围不降低、版本/指纹与结果一致。通过后以新版本或关联记录保存候选及工具引用，并与本批处理水位一致提交；模型输出与真实证据不符就保留原材料，重新分析或跳过不可靠候选。
5. **即时行动与后台学习分开**：任务进行中可在授权内直接尝试并修正新方法，记录真实结果；Dream 后续提炼可迁移经验。Dream 排队、服务繁忙或模型不可用不应阻塞任务回复和交付。

建议采用共享流程加**按来源类型的处理配置**，复用批处理、模型接入、来源快照和隐私逻辑；保留对话专用的原文引证规则，为任务回执和工具资源增加各自的证据适配。不要将真实任务结果硬转成 `role=message`，也不要把所有内容塞入一次模型请求。

## 5. Deepdream：让经验和工具持续变好

- **关联与整理**：按目标、软件、环境、具体问题和所用工具寻找相关经验；合并重复表述时保留原来源，条件不同的方法保持可选择的替代关系。标明“相同问题不同环境”“新观察与旧结论冲突”“旧方法仍适用”等关系。
- **从结果中修正**：对比经验被引用的任务、真实验证及失败原因，更新适用范围和可信状态；网络故障、用户取消或无关程序错误不自动归咎于某个工具。主人纠正和新的实际结果能触发重新评估。
- **管理工具引用**：检查关联资源的版本、指纹、依赖及可用性；文件变化、被移动或失效时标记当前状态，并让 Bunny 重新查找、修复、创造或切换工具。历史经验仍指向当时版本，新的有效版本形成新引用；不要自动删除用户文件。
- **形成改进建议**：发现工具缺口、重复操作或经验冲突时，生成有依据的候选方法或工具改进建议；如果已有任务或自主活动的授权允许，交由任务系统选择是否创建/改进、实际验证并回写结果。记忆整理本身不直接执行外部写入。
- **提升、修正与回退**：按实际影响、证据类型和适用范围选择试用和验证强度；低影响候选可在现有授权内主动尝试，不设无意义的统一成功次数门槛。证据足够时提高可信状态；失败或失效时修正、降级或回退，不因为一个错误假设永久放弃任务。

## 6. 调度、持久化与运行效率

- 继续由 `MemoryMaintenance` 统一调度 Doze、Dream、Deepdream；经验/工具只是它们按需选择的处理配置。独立的来源类型和场景/可见范围应有各自水位、进度和失败状态，避免普通对话水位推进后漏掉任务结果，也避免某个材料类型堵住其他整理。
- 任务达到可学习检查点时，在现有事务与来源约束允许的情况下，与对应任务状态/回执一起持久化轻量学习事件或等价的可靠待处理标记；以稳定事件标识去重。现有来源须先存在，不能假定新任务与引用它的事件可以直接在同一写入中创建；必要时使用可恢复的两阶段或待处理记录并验证崩溃窗口。崩溃、重试、预算退避和重复通知后应可继续处理，不漏掉已提交结果、不重复产生同一候选。长期任务按动作和恢复片段逐步产生反馈。
- 现有 Vault 更新同一记录时保留原 `ingestionSeq`（见 [`native/vault.swift`](../native/vault.swift)）；因此不能只扫描任务记录的入库序号来发现它之后的新进展。可通过新增的稳定学习事件或经验证的版本/变更游标接入；任务状态与事件的原子性、现有来源约束和迁移方式须在实现时实测。
- Dream/Deepdream 的候选、来源验证和水位更新须与现有加密存储的事务及快照校验一致；任务或来源变化时重新读取，不用旧快照覆盖新状态。经验版本、来源和工具资源引用保持无环；运行中的任务不依赖由自身刚派生的结果而形成循环来源。
- 前台对话、正在执行的动作和及时核验优先；整理任务增量、分批、可中断并能恢复，限制不必要的模型和文件读取。达到本轮资源预算时保留进度，条件合适后继续，不能让后台整理或经验提炼拖慢正在执行的任务。
- 默认只把完成分析所需的脱敏事实、引用和必要上下文送入模型；凭据不进入经验正文或普通日志。经验/工具的可见范围不低于来源；主人删除或修订来源时，依赖它的经验、工具引用及缓存按现有来源规则失效或重新核对。

## 7. 实施顺序和验收

1. **固定基线**：记录现有 Doze、Dream、Deepdream、`AgentLearning`、已验收任务经验与工具索引的输入、输出、来源和调用方；保留真实用户数据与现有验收口径。
2. **先接入任务经验 Dream**：为已确认动作、失败/恢复和持续任务片段增加可靠事件与类型化来源校验；保留现有对话 Dream 水位和结果。学习不阻塞原任务。
3. **接入经验 Deepdream 和工具引用**：实现相似经验关联、条件/冲突处理、工具版本状态及来源失效；沿用当前记录与加密存储，兼容旧技能经验和历史工具索引。
4. **接入组装器与软件经验视图**：用兼容适配器读取内置、外部和习得经验，支持分类/标签与相关性检索、概要/完整内容按需加载；将现有软件运行适配器与可参考经验逐步分离，保留在途任务和原有授权校验。组装器可先接入现有已存经验，再随第 2、3 步接入新增来源；双方可以分步实施，不必互相等待全部完工。
5. **连接任务工具演进**：在已有授权下支持按需检索、组合、创建或改进任务工具，记录版本和验证反馈；再把实际使用结果回送 Dream。正式应用内置契约的升级继续通过现有开发、验证和安装流程。
6. **逐步切换和收敛**：按来源类型与场景分批接入；过渡期间避免旧学习回调和新 Dream 对同一事实重复产生记录。验证新路径后才清理确认无调用方的重复逻辑；不中断原任务、不重置用户资料，可按功能关闭并安全读取已有记录。

验收应至少覆盖：普通对话 Doze/Dream/Deepdream 无回归；长期任务中途完成动作后能形成经验；失败恢复与未知结果不被误标成功；同一经验可按多个标签发现，组装器按软件和阶段选择概要或按需取得完整内容，并保留限制、证据与替代方案；标签缺失时仍能找到相关经验或自主探索；工具创建、验证、版本更新、失效和回退；同一工具被多条经验共享；主人纠正、来源删除、场景隔离和重启恢复；重复事件和并发整理不重复记录或丢水位；未见过的任务能按经验与工具自主调整方法。离线夹具、真实应用与长期表现分别验证，记录 CPU/内存、模型次数、整理延迟、命中与纠错情况，并对比前台任务的响应时间。
