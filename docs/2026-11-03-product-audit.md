# 产品审查与真实场景验收

本轮在任务系统重构基础上覆盖软件操作、交互、统一主题和底层异常恢复。每项区分逻辑回归、真实界面夹具、已安装软件/真机验收；夹具不作为真实微信收发证明。

## 已定位的问题及本轮改动

| 问题 | 改动 | 验证重点 |
| --- | --- | --- |
| Alice 普通消息被旧测试规则忽略 | 移除实时任务的测试标签与固定回复限制 | 原消息被识别但明确忽略的账本证据已保留；重新测普通消息 |
| 监听修改把自己的下游汇报加入来源，形成环 | 只链接本次主人原始指令；修改副本先持久化 | 真实加密 Vault 更新与续办回归 |
| 新消息排队和重复识别拖慢响应 | 默认局部 5 秒、活跃 3 秒，新事件立即处理；忙碌未发送按 3 秒重试 | 识别/决定/提交/核验时间分别记录 |
| 双语 OCR 重复行让同文草稿核对失败 | 同一画面位置去重后逐字核对 | 保留数字差异，真实旧截图重放可匹配 |
| 填好草稿后等待模型规划发送而超时 | 标题、完整草稿与唯一发送按钮均确认后直接键鼠提交 | 仍保存提交前画面，提交过的动作不重复 |
| 发送后模型给出不相关判断便结束 | 仅观察，最多两次回退全屏重新定位与核对 | 无额外输入、无重复发送；失败仍保留待核对 |
| 多任务没有统一额度 | 一个运行时提交段，5 项业务任务上限 | 并发 8 项、排队持久化、手动启动、不自动补位 |
| 停止只停 Bunny 跟进，外部工作可能继续 | 绑定 WorkBuddy 会话与轮次，操作实际停止控件 | 真实主状态条 ×，停止前控件 1 个、之后 0 个 |
| 前台切换妨碍停止 | WorkBuddy 匹配会话优先后台 AX，键鼠兜底仍核对前台 | 不退出或杀应用进程 |
| `Interrupted by user` 被当作完成 | 统一标记已停止，历史重放同样识别 | 不播报完成、不提供完成对钩 |
| “需要处理”没有可理解的原因/动作 | 区分草稿中、发送待确认、授权、窗口不可见等；单一主要操作 | 主人一键请求核对，现有恢复循环空闲后处理 |
| 状态条跳到通用面板，找不到任务 | 向上展开同一任务组件；暂停轮播，左右手动切换 | 操作、结果、原因与任务面板共用组件 |
| 任务期间悬浮界面被强制鼠标穿透 | 区分任务 UI 与自动化点击区域 | 用户的任务按钮保持可操作，GUI 事件仍有租约 |
| 面板视觉语言不一致、列表嵌套滚动 | 统一主题、Switch、沉浸分组；任务/技能随内容展开 | 设置、任务、记忆、自我理解、动作和关于页面 |
| 控制台仍依赖旧 Electron 数字级别 | 共用当前事件格式的日志整理函数 | 正确标记 warning/error，并抑制常规日志 |
| 停止授权等待任务后提示残留 | 停止原任务同时清理该任务的授权指引 | 不开启开关、不执行命令；真实界面复测 |
| “停止全部”把解释指令的内部任务也停止 | 控制指令排除自身，仅处理业务任务 | 原指令能够回报实际停止结果 |
| 重新定位失败却返回继续成功 | 原样返回定位失败，保留原待处理任务 | 不继续发送、不误报恢复 |
| 慢画面识别后立即再次轮询、静止时检查时间不更新 | 从识别完成时计算下一周期，记录每次稳定采样时间 | 慢识别不形成紧密轮询，静止画面不重复调用模型 |
| OS 窗口定位丢失便判定无法观察 | 一次外部全屏采集与 OCR 核对后再报告定位障碍 | 不激活、启动、登录或输入；后续可手动重新定位 |

## 0.23–0.24 文件实验与视觉工具修正

- 入站附件已通过 Alice 手机真实转发到 Mac，但 **尚未完成保存和实际字节读回**。两次实验的失败/暂停记录保留，不能作为接收能力通过的证据。
- 系统菜单超出主窗口底边，原局部截图遗漏“另存为”。0.23 使用应用所属窗口与弹出菜单的联合区域，首次从外部全屏重定位后裁切，后续复用区域。真实只读证据：`/tmp/bunny-popup-expanded-real.png`。
- 后续实验中模型把正确的像素位置换算成了错误的归一化坐标，误开“删除”确认框。未确认删除；取消后独立全屏核对确认文件卡片仍在，证据 `/tmp/bunny-wechat-after-safe-cancel.png`。这是实际缺陷，不能只靠提示词解决。
- 另一问题是菜单关闭后，宿主可能复用旧菜单图像却更新了父窗口坐标。0.24 在区域形状变化时强制取得新图，并用唯一 `frameId` 关联图像、预览尺寸和操作。文字控件统一由 `label` 经本地 OCR 定位；图标、空白和右键使用预览图整数像素。拒绝旧引用，在输入前再次检查窗口/菜单是否仍在。
- 微信文字发送保留唯一会话出口；通用动作不能点击发送、删除、退出和资金控件。实际键鼠工具增加登录提示的只读检查，文字定位与认证检查复用一次新截图，减少重复采集。
- 发现旧异常提醒路径仍有“一键登录”点击分支，已移除。主操作、会话和异常提醒共用同一微信可用状态检查，微信激活只能用于已运行进程。尚无证据证明该旧分支触发了本轮登出。
- 重新定位只由本机显式操作触发；成功后清除旧错误。窗口变化后重建来信基线，不自动重新绑定主人入口；结果不明的旧发送不能跨窗口继续。
- 自适应任务的步数仍保留全局递增操作键；主人明确继续或修改目标后才开放下一轮探索，避免“继续”立即撞上同一个上限。未执行的失败步骤明确显示正在调整方法，不再误报已取得结果。
