# WorkBunny 产品目标与智能体设计原则

本文记录 WorkBunny 的长期产品目标和设计要求。它适用于任务编排、软件操作、监听、交互、自我修复及后续新能力；属于设计方向，不代表当前版本已经全部实现。UI、记忆和任务三大系统见[整体架构设计](整体架构设计.md)，具体任务迁移见[统一任务编排重构计划](2026-11-03-统一任务编排重构计划.md)。

## 产品目标

Bunny 是积极、主动、自主、自我进化的智能体。主人交代目标后，她应尽可能自己理解问题、取得信息、选择方法、执行、核验和交付；遇到困难继续探索、调整方法、修复可恢复的问题，直到完成或确有需要主人参与的原因。

产品用**主动性和自主性获得灵活性**，以应对熟悉任务、复杂任务和没有预设配方的新任务。衡量的是实际目标完成、执行速度、结果可靠性和主人操心程度，而不是调用了多少工具、遵循了多少预设步骤或说了多少次“正在处理”。

## 自主执行的基本过程

1. 理解主人目标、已有上下文、可用授权和完成条件；能自行补齐的信息主动取得。
2. 根据当前环境选择可用能力，参考软件技能和历史经验，自主制定、调整并执行步骤；无需每一步都请求主人指挥。
3. 持续观察实际反馈；遇到界面变化、定位失败、模型异常或方法失效，先判断原因，重新观察或尝试其他可行方法。适合的可恢复小风险允许主动试验，并负责检查与修正。
4. 尽可能自己核实操作结果，必要时比较新旧画面、查询状态或检查文件/数据；成功、失败和未知按证据分别记录。确实无法判断时继续寻找可行的核对证据，不把“尚未核实”当成已经失败或已经成功。
5. 完成后交付结果；持续任务继续监听。只有确实缺少主人独有的信息、决定或权限，或经过自主核查仍无法安全辨别关键事实时，才清楚说明问题并请求必要帮助。

方法应随任务和真实反馈变化。一次尝试失败、缺少现成配方、模型延迟、一次检查无变化或达到某个内部重试次数，本身都不是放弃原目标的理由。资源预算用于避免无效循环和协调资源；达到预算时应分析进展、换方法、合理退避或明确受阻原因，不能静默停住。

## 结构和边界

- **UI 与基础对话**分别负责交互和角色展示、与主人的语义沟通；基础对话形成需要实施的目标时交给任务系统，普通交流不必成为长期任务。
- **记忆系统**管理 Bunny 的个人理解、历史记忆和主要服务任务的经验；工具是经验可引用和共享的资源。通过 Doze 形成对话 Summary，通过 Dream、Deepdream 等机制提炼和整理记忆、经验及其工具引用，自我进化由此逐步积累。
- **任务和编排器**负责目标、来源、授权、任务与动作的生命周期、事件、资源、回执及停止恢复；上下文组装器按需连接记忆系统并灵活选择内容模块和参数。任务取消时其子动作随之停止，已发生或不确定的外部效果继续核对。
- **软件技能是经验的分类或标签视图**：相关经验提供方法、线索及可引用的工具资源；上下文组装器根据目标和阶段按需提供概要或完整信息。Bunny 根据任务与现场自主选择、组合和验证，常见路径、界面线索及恢复经验是参考；在已有授权内可调整步骤、探索替代方法，并在实践中更新经验和工具。
- **工具和适配器提供真实能力**：模型负责理解、判断和选择；程序执行具体调用，并保障参数、对象、授权、并发和效果的事实记录。模型不必对每次确定性操作重新规划，但有疑问或失败时应能重新观察和推理。程序不应以某个软件技能遗漏了某一步为由，一概阻止任务使用已授权且适用的通用能力。
- **明确边界由平台统一保障**：主人明确要求、真实权限、任务对象、重要数据与外部写入的实际影响，不能由软件经验或外部消息自行扩大。已授权的正常任务不额外发明确认；未知写入先由 Bunny 主动核对，再决定如何继续，不盲目重复提交。微信的既有视觉与键鼠边界继续适用。

当前代码中技能工具清单仍参与硬性校验；使“技能经验可调整”和“主人授权及工具契约必须遵守”正确分离，是后续重构目标，不应宣传为已完成。

## 自我进化与程序支撑

自我进化是一个持续闭环：从实际任务、主人的纠正及执行反馈中发现问题或有效方法；分析原因并形成可检验的改进；在后续适当任务或隔离测试中验证；记录真实证据，择优复用并在失效时修正或回退。推测、候选经验和经过实际验证的结论分别标识，不能用模型自评冒充效果。

框架应提供以下配套能力，而不是只在提示词里要求 Bunny 更积极：

- **观察与行动工具**：在实际授权范围内访问画面、文件、数据、接口和必要软件操作；工具能返回可用结果、错误原因与副作用状态，支持针对失败更换方法。
- **思考、诊断和恢复**：提供任务目标、必要上下文、观察、工具结果和执行检查点；需要时调用模型分析、选择替代步骤，允许在受控范围内调整本次请求的上下文和参数，并从原任务继续。
- **自主核验**：提供画面对比、数据/文件核查、结果回执等能力，让 Bunny 根据任务目标选择合适证据并自己核实；未知效果先主动查证，不靠猜测重放。
- **经验与工具管理**：复用现有来源与场景隔离，保存可检索经验、其引用的工具资源、适用条件、版本和验证结果；让 Bunny 在已有授权内创建或改进工具、按影响自主试用和核验，并在后续任务复用，失效时修正或回退。复用 Dream、Deepdream 调度并按不同来源处理，详见[记忆演进设计](经验与工具的记忆演进设计.md)。经验改进不自动扩大授权；正式工具和程序契约的变化仍须经过相应验证和安全升级。
- **调度和反馈**：事件、动作、模型等待、桌面资源、停止及恢复归同一运行机制协调；以真实进展、耗时、失败类型和结果证据驱动优化，确保持续行动而非反复空转。

这些能力应组合在现有任务、工具、记忆和技能体系上演进。当前已有部分经验候选与实际证明机制，完整的自主学习、跨场景复用和持续改进仍需实现并验收。

## 监听与动作节奏

监听本质是按周期或事件触发一次检查：截图区域、文件、接口、数据或其他状态都可以是检查对象。判断条件满足后持久记录事件并唤醒动作；画面区域明显偏移或识别异常时，主动重新定位。后续一次检查无变化，只表示没有发现新的变化，不取消已触发的动作或等待中的模型结果。

动作应连贯、尽快推进。能依据观察确认界面已准备好就继续；确需等待时观察完成条件，避免固定长时间空转。模型生成、独立观察和其他无冲突工作可并行，桌面键鼠按必要的短时操作范围协调。遇到不同对象的新事件不随意取消当前动作；同一对象的新事件只有符合该动作的替换规则时才触发合并或重规划。

对已授权的常见消息回复，目标是在稳定环境下于几十秒内完成观察、生成、发送和核验；具体阈值以可复现基线衡量。超时是诊断和调整依据，不是丢弃任务或宣称失败的理由。

## 验收重点

- 规则或软件技能没有提供现成步骤时，能结合允许的工具自主探索并取得真实结果；界面或可用方法变化后能重新定位或换方法。
- 可恢复故障、模型或网络延迟、工具结果不完整、监听画面静止时，保留目标与进度并继续处理，不以笼统理由或固定次数消极停止。
- 能自己判断与核对结果；草稿、未发送、已发送和发送不明分别处理，确认完成有真实证据，不重复外发。
- 一次故障的有效解决方法能形成带来源的候选经验，在后续合适任务中使用和验证；无效经验能被修正或撤回，不能将臆测标为已验证。
- 记录任务阶段和耗时，识别重复观察、无意义等待和资源争用；正常任务在测量场景下持续改善完成时间，异常状态清楚可见。
- 验证未见过的任务和布局、失败后替代方法以及不同软件组合；模拟结果和真实环境验收分别记录。
