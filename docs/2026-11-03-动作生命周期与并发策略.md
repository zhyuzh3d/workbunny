# 动作生命周期与并发策略

本文记录当前单次工具调用的生命周期策略；其中的“动作”在实现上尚不等同于由多个工具和 LLM 步骤组成的完整业务动作。后续将按[统一任务编排重构计划](2026-11-03-统一任务编排重构计划.md)上提为可持久恢复的业务动作实例，并继续复用工具级保护和回执。任务停止或取消时，其子动作也停止；重构目标是让同一任务内无依赖且不冲突的业务动作独立推进，实际桌面输入仍由共享租约串行。

任务负责目标、授权、事件队列和停止；每次工具动作拥有独立的动作标识、取消信号和持久化状态。任务暂停、停止或授权失效会传递给其子动作，不影响其他任务。不同任务可异步推进，实际桌面键鼠使用共享 GUI 租约串行化；有依赖关系的动作仍按顺序执行。

## 生命周期

动作先保存意图，进入准备阶段。工具按自身业务定义执行前核对、截图定位、输入、结果核验和可恢复的重试。对于工具明确声明且已证明未执行的临时失败，动作可在自身生命周期内等待、重新观察并有限重试；不确定是否执行时不重放。涉及外部写入时，动作在可能产生草稿或其他副作用前进入保护阶段，提交前进入已提交阶段；成功须保存实际回执。结果不明保留意图并核对，不盲目重放。重启时，仅对明确受保护的自动回复协议、且持久状态证明尚未输入回复草稿或提交消息的准备阶段动作恢复为未执行；旧版动作或其他工具仍按未知结果处理。

## 新事件与替换

默认策略是动作独立：无关事件、其他目标消息和未变化的画面不会停止动作。工具可声明同一作用域内的新事件替换策略；目前只对自动会话回复启用。事件先保存再触发替换判断，作用域包括任务 ID、任务场景、应用及联系人；普通单次发送、成果交付和其他动作不会因新消息被替换。

事件触发后的模型调度和动作继续属于该事件：后续采样没有变化不构成取消条件。确有必要时，应在模型返回后单独核对相关画面和业务前提；前提已改变则保留事件并重新规划。未来动作实例与事件归属的统一持久化、故障恢复属于重构计划，不表示当前所有技能都已具备。

会话事件处理期间有独立、只读的目标会话观察。模型生成回复时出现同一联系人新消息，先合并新旧消息再重新生成；回复尚在准备且尚未输入时，可以停止旧动作并重新规划；输入或提交前还会独立重新观察同一会话。动作已有草稿时在安全检查点停止提交并保留草稿；如果无法证明草稿可安全替换，则等待核对。提交标记已经写入时不得假定发送未发生：原动作继续核验或进入结果待确认，新事件排队等待处理。只有经过视觉确认的新来信才触发正在准备中的动作替换；不能因视觉不清、画面静止或其他联系人消息取消它。

仅变更任务检查周期不会中断正在执行的动作。主人明确暂停、停止任务或修改任务目标、权限和身份时，按现有控制规则处理；发送结果不明仍需要先核对。

## 验证范围

覆盖同目标和跨目标并发、规划等待期间新消息、草稿及提交前后边界、任务停止、周期变更、恢复及重复发送保护。模拟测试不能代替真实微信消息、语音和网络不稳定情况下的现场验收。
