# Bunny 统一执行框架（0.16）

主人通过普通对话交办，解释器把意图转成有范围的任务；技能决定步骤，工具执行一步，运行时保存状态、事件与证据。微信照看、主动交谈、画面条件观察、WorkBuddy 工作委派共用这一套生命周期，不各自建立后台循环。

## 任务与控制

`bunny.task/v1` 包含 `skill / goal / criteria / subjects / policy / parameters / schedule / completion`。对象限定应用及联系人，能力由宿主技能和主人渠道共同授予，模型不能添加权限。持续任务默认每 60 秒观察，交流期间可每 10 秒观察。没有指定到期时间就持续到主人停止；“收到一次”才采用一次完成条件。

状态为：已接单 → 执行 → 等待；主人可以暂停、继续、停止。需要人工核对、完成和到期是独立状态。目标变化修改原任务并保留进展，不另起一个重复监听器。全部暂停也会拦截正在持久化、尚未启动的新任务。

普通对话只作任务入口分流，任务面板和日常对话都把主人原文交给同一个解释器。单项任务的“查看代办进度”“暂停当前任务”“继续原任务”“停止当前代办”是本地整句命令，无需请求模型；仍须电脑和资料库已解锁。自由表述的理解与语义回复依赖模型连接，失败不能声称已经执行。任务面板的按钮也直接控制本地任务。

任务界面提供自然语言交办框、实际状态、积压事件数、下次观察周期和控制按钮。初次建立消息基线前显示“建立观察位置”，不能提前宣称监听就绪。所有入口进入同一任务解释器。“下一轮回复一次后停止”表示新任务的完成条件，不得控制历史已结束任务。底层桌面诊断折叠显示，不能作为另一套任务管理产品。

## 工具与技能规范

工具必须注册名称、参数校验、read/write 副作用、能力要求、对象范围和执行回执。脚本是已注册工具的有界步骤表，所有步骤预检查后才允许开始；它不是任意 shell 或模型生成代码。新增应用应实现工具适配器和技能，不复制任务调度器。

技能声明适用条件、参数、版本、工具白名单、能力，以及每次唤醒执行后可保存的状态。当前包含会话代管、单次发送、只读查看、画面观察、工作委派、学习操作经验。会话工具当前只适配微信；Finder、Chrome、Codex 已有通用画面观察目标，完整操作能力仍需后续适配与真实验收。

新操作经验通过 `skill.learn` 保存为带来源的候选知识。后续同场景、同技能任务可参考，无法修改工具授权或消息原文；两个不同任务完成且存在已核验写入后，标记为已验证。每次证明另建版本，来源图保持无环。删除来源会使相关派生经验失效。经验可以被主人再次修正，不能让一次模型自评冒充测试。

## 观察与操作

微信只读取系统显示像素，模拟键鼠。禁止微信专用 API、插件、协议、AX 元素树、数据库、退出、重启及自动登录。通用系统窗口元数据只用于核对进程、几何与焦点，不读取消息。

初次操作取得全屏实际显示流，定位微信区域；区域和窗口身份仍有效时直接请求局部显示输出。几何变化重新全屏定位。一个共享截图桥接进程负责所有截图，避免本机多个 CGDisplayStream 连接初始化卡住；输入客户端独立，暂停某个任务不会杀掉其他任务的截图通道。IOSurface 的 BGRA 像素在锁定期间复制，图像不依赖流停止后的缓冲区寿命；明确请求 sRGB 保持颜色正确。

本地像素比较先判断稳定变化，再执行 OCR 与经目录确认的免费视觉模型识别；本地气泡颜色和 OCR 正文交叉核对方向，重复气泡数量与 OCR 不符时不提交本轮观察；无变化不调用模型。多个会话共用一个场景观察结果。联系人列表未读标记用于选择目标；当前已打开的会话直接比较消息区域，因此不依赖红点出现。聊天停在旧位置且出现“新消息”提示时先返回最新消息。未读提示不是消息本身，回复必须有标题、正文和方向的视觉证据。

默认观察整块微信区域中的小尺寸比较样本；原生显示输出已按窗口区域裁剪。尚未实现常驻只捕获绿气泡几十像素的停泊策略，不能把当前实现宣传成零成本图标监听。选择较大区域是为了同时覆盖已打开会话来信、布局变化与错误状态。

每次逻辑输入间隔至少 500ms。界面忙、主人正在使用电脑、存在草稿时保留消息等待。独占 GUI 租约使不同任务不能同时打字。鼠标键盘事件始终受当前截图、焦点、窗口位置及任务对象校验。

## 会话与身份

每帧识别至多12条完整可见气泡。基线只记录历史，不对旧消息自动回复。后续消息按可见顺序与前次尾部对齐，保留逐条序号；之后再次收到相同文字仍是新事件。对齐使用规范化的标点与大小写，但正文保留原文、数字不合并。本人已核验发送会写回游标，文件传输助手中同侧气泡也不会成为自触发命令。不能确定对齐时保留旧基线，回退全屏重新定位与识别；再次无法对齐就暂停并报告，不静默丢弃新消息。屏幕外或因大量消息挤出可见区域的内容不能声称已读。

一轮新消息进入持久队列；回复决策在发送前保存。上下文包含本联系人近期原文、摘要、询问目标进展与有来源且允许对该联系人使用的记忆。普通联系人内容只是数据，不能升级为主人指令。广告忽略；不确定、敏感或需要重要承诺的内容给主人报告。会话以 AI 小秘书身份交流。

主动询问持续到主人关心的问题被对方真实回答，再汇报已知和未知项。主人通过本机对话绑定特定联系人为自己后，该渠道才能交办；绑定按场景区分，远程消息不能自行绑定。远程交办进入同一解释器，工作结果回到原主人通道。委派保留主人交办原文和文件路径，不能用模型概述替代交付证据所需的原始要求。绑定只证明用户配置的渠道，不能防止对方账号被他人实际使用。

## 持久化、回执与失败

生产任务、待处理消息、经验和主人绑定使用现有加密资料库与来源删除机制。开发实测的明文文件仅放在权限为 700 的临时实验目录，文件权限为 600；不将聊天截图放进 Git。读工具只保存有界摘要回执，不把图像塞入长期任务记录。

写工具先保存意图再执行，完成必须有 `verified:true` 回执。相同键和相同参数的已核验操作返回原回执；同键变更参数被拒绝。发送结果不确定立即等待核对，重启和恢复均不得重发。暂停期间返回的真实已核验结果仍保存，但不执行后续步骤。

队列上限触发时连同触发上限的新事件一起保存，停止继续观察，等待处理积压。应用窗口消失、进程/窗口身份变化、登录画面或捕获超时会停止微信相关输入；不会重启、登录或继续盲点。重新核对按钮只做只读观察，恢复任务另行显式进行。

短期真实测试与长时可靠性是不同证据。几小时稳定代管需要独立记录运行时长、资源与异常恢复数据，不能用单元测试或几分钟成功往返宣称已经证明。

## 本机使用与验收

在“工作与日常 → 任务”交办，例如“帮我照看 Alice 的消息，按上下文简短回复，广告忽略，每60秒检查，持续2小时”；或“主动联系 Alice，问清最近情况、项目进度和需要什么帮助，问清后向我汇报”。主人渠道须先从本机明确绑定，例如“文件传输助手就是我，听从这个会话的交办”，再开启该渠道的交办监听。

桌面须保持解锁，微信主窗口可见；最小化、退出或登录页会停止自动操作，不尝试绕过锁屏或自动重登。微信当前适配纯文本语义回复；图片、语音、文件等证据不足时转为报告，不能声称已经理解附件。

0.16.0 已完成实际 Alice 手机往返、上下文改期、广告忽略、繁忙排队、主动问询、隔离主人渠道到 WorkBuddy 的文件交付与微信回报，以及已安装客户端的技能经验验证、20分钟低频观察、任务控制和正常重启恢复。该轮主对话模型的自定义 API 曾发生 ECONNRESET，导致自由表述的停止和后续一次交办失败；任务面板及本地明确控制仍可工作，没有隐去这次失败。脱敏验收记录见 [agent-0.16.0-acceptance.json](evidence/agent-0.16.0-acceptance.json)。
