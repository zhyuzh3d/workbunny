本文记录当前源码的早期 Beta 架构与实现边界，核对日期为 2026-11-12。另见[产品需求](product-requirements.md)与[执行流程](flows.md)。

## 1. 分层与依赖

WorkBunny 使用 Electron 主进程、隔离的 renderer/preload 和 Swift 原生辅助程序。主进程装配 UI、对话、记忆与任务服务；外部模型提供语义判断，工具执行真实操作。

产品有 UI、记忆、任务三大系统，基础对话是独立机制。感知、身份权限、模型传输、时间与资源协调是共同支撑能力，不再各自建立任务编排器或独立经验数据库。

## 2. 对话、渠道与权限

本地渠道为 `local`。外部渠道由应用、账号与收件对象确定稳定标识，记录人物、场景、修订、已消费事件及临时主人授权。人物不是权限凭证；群聊可以有多个人物，但授权属于整个渠道。

`DialogueChannels` 负责输入去重、实际消息认证、渠道历史、Summary、权限快照和待发送回复引用。任务提供可信渠道定位，模型接收事实后判断内容；模型输出不能改写渠道绑定。

同一渠道的消息按序处理，各渠道可以独立等待视觉证据和模型判断。渠道状态与事件回执在同一 Vault 写事务中保存，提交后才公开新权限。撤权同步递增渠道修订，随即安排持久化，迟到的识别结果会重新核对修订。

外部代发标识 `［ᕱᕱ］` 在 [`shared/external-message.js`](../src/shared/external-message.js) 中统一定义，供主进程的消息/附件处理和设置界面共同引用。标识幂等添加，原样进入发送正文和效果回执，不参与身份授权；不为旧标识增加迁移或兼容逻辑。

认证快照包含 `channelId/account/owner/scene/revision/keyVersion/expiresAt`。回复、任务交办与执行检查当前快照；改密钥或关闭认证先同步使旧权限失效，再持久保存。外部消息中的命令、历史认证截图和昵称均不能创建宿主授权。

当前身份程序遵循默认关闭、实际新消息精确匹配、超过 60% 的来源绑定候选交给 Bunny 判断、一小时渠道授权及即时撤销。视觉消息独立读取实际文字，识别结果与期望值分开。匹配机制及群聊授权是产品明确选择，不是强身份认证服务的通用替代。

普通渠道只取得允许的当前会话与非主人私密资料；认证渠道可以切换场景并按需检索。Task 只记录执行所需内容、来源与返回渠道，私聊回复正文通过渠道持有的引用传递，不成为 Task 的私聊记忆检索入口。

主人任务经对话先回应，确认回复后用 `owner.dispatch` 等现有交办工具进入原编排器。请求标识与效果账本防止重试创建重复任务。进度查询按需读取 `task_status`，不会再次派发原目标。

身份密钥由统一对话输出边界替换，必要内部上下文不提前删掉。第三方正文与附件另经敏感内容策略；附件检查真实路径、哈希和内容。记忆允许保存敏感信息，不等于允许普通外部渠道读取或发送。

## 3. 动态上下文

`assembleContext` 接受用途、片段定义、配置、取消信号和总预算。每个片段声明 `id/required/description/load/parameters/maxLimit` 等信息；参数包含 `include/detail/limit/maxTokens`，对话可选模块还可声明 `query/refresh`。

请求的 `inputBudgetTokens` 是本次输入的 token 天花板，组装的 `maxTokens`、模块条数与概要/全文控制实际取回量，两者分开。程序允许上限为256000 token，最终还须取模型已知 input/context 限制、完整输出预留、15%估算误差余量及1024 token协议余量后的较小值。未知容量回落32768上下文，不因调大额度而假定模型更大。默认对话可选组装6000、任务16000，无参数片段默认6条/1800估算token；提高请求上限不会自动加载更多资料。Bunny可沿既有只读上下文工具或任务重组参数增减本次额度和取回量，最终传输再次校验模型边界。

必需事实优先，历史、记忆、经验和尝试记录有界加载。预算不足时缩减可选内容或明确报错，不静默删去目标、当前来信、权限或已确认效果。概要与正文分开，按需读取经验及工具接口，不把所有历史版本放入上下文。

可选文本先选择完整段落；确需片段时按实际内容的token估算寻找Unicode安全前缀，不用固定“token乘字符数”换算，也不拆断代理对。这个片段选择仅用于可回查的可选经验，不能用来截断当前交办原文。

`createContextSession` 向模型提供 `workbunny_context_configure`：模型可在同一轮回复中只读选择模块、重新搜索或展开，再继续回答。模块加载按配置复用，权限变化和取消使迟到结果失效；重复配置或相同资料显式标记，交由模型改变方法。任务默认只提供简短概况，详细监控作为可选 `task_status` 模块。

通用组装器保留可选预规划入口；任务的可调整片段白名单与参数范围由宿主定义。不是所有调用都先额外问一次模型，也不是任意模块都允许 Bunny 改写。最终模型请求仍经过统一预算及传输协议。

## 4. Task 与编排器

当前契约为 `bunny.task/v4`，主要字段为目标、验收条件、对象、调度周期、完成方式、授权、来源、场景、上下文、事件队列、Action 记录、Operation 账本和结果。0.25.0 按新资料库验收，任务恢复使用当前契约及其索引。

`AgentService` 装配执行器、工具、渠道、学习、恢复和结果回传。`AgentRuntime` 管理准入、到期调度、事件选择、worker、取消、状态保存与恢复。`SkillRegistry` 登记 `conversation.manage/system.operate/work.delegate` 等任务执行协议。

Task 状态为 `queued/ready/running/waiting/waiting_permission/paused/needs_attention/stopping/completed/stopped/expired`。当前最多启动五个占用名额的任务，队列需要显式启动，不是自动无限补位。任务持久化共享加密 Vault，但运行状态由编排器拥有。

事件具有稳定 key 与对象 scope。入队、已消费和溢出合并分别记录，历史消息基线与实际新消息分开；观察任务不能因重启或滚动把历史反复当新消息。不同对象可有独立 Action，同对象的冲突事件按声明策略处理。

任务保存按任务 ID 排队，只有事务成功才发布事件入队或目标修改。目标更新保留在途 Operation 的记录，旧 worker 取消后仍能保存已经核实的回执。接续 WorkBuddy 会话时，原任务退场与新任务准入共享同一次写事务。

监听是执行器按 Task 的周期或实际事件进行检查，支持截图区域和其他工具检查；它不等于一个全局“画面变化才能继续”开关。变化产生事件后，后续静止帧不撤销已触发 Action 或有效模型结果。模型回传时如需最终核查，单独取得当前证据并判断。

当前条件和循环主要由执行器及自适应任务组合实现，尚未提供任意通用节点图的可视化编辑器。`DesktopService`、`Secretary` 和具体软件适配器仍承担执行与监督职责，不能把“统一编排入口”描述成所有内部执行循环已消失。

`workOrder/workMessage` 共用交办正文生成：从解释后的 `workRequest`、目标、必要背景与规则组织说明，只附本轮验收和必需的唯一关联标记，不附固定授权、宿主分工或其它软件禁令。具体工作边界来自本轮真实约束；整理方法留在软件经验中。首次、主人续办及自动修订不读取私有原文作为正文兜底，也不附原始历史；敏感任务附件同样只由整理后的正文生成。原文与历史留在 Task 私有来源和授权字段；自动修订由 Bunny 整理具体差项。未知提交恢复仍匹配原先保存的同一草稿，不为正文策略升级改写或重发旧草稿。

`result.links` 独立承载成果入口：在绑定答复截断前提取完整候选，同一轮验收按源候选ID选择实际成果，不能重写URL。短摘要、完整正文与入口分开；本地报告、持久化outbox、加密对话历史和微信正文携带入口，TTS只读摘要。角色气泡、历史及任务卡使用同一链接控件；打开时只提交Task标识和序号，主进程重新校验当前任务、场景、代次和HTTP(S) URL。旧结果缺links时可从已存正文展示，不改写原任务或自动重发旧报告。

入口提取识别成对 Markdown 展示边界，保留网址内的查询参数、编码、片段和字面星号；修正旧候选须有对应原答复的边界证据。去掉展示格式由本地整理完成，不单独触发执行方修订，链接可用性仍由 Bunny 核查。

进入任务入口的交办先持久化为内部 `task.resolve`，解释后才采用具体技能与业务目标；它也可解析为聊天、澄清或已有任务控制。内部记录结束后不再占据业务列表；列表空闲本身不能证明输入丢失。接收回执保持中性，业务采用和无执行的解释结果通过阶段日志分开记录，只保留任务标识、决策类型、技能和状态，不记录正文、联系人或路径。日志失败不得影响执行。话题切换与缺目标的判断仍由统一语义解释负责，不添加固定句式拦截或把换话题当作取消授权。

基础对话的可选认知协议失败时，降级只移除认知元数据，重新生成并严格校验核心回复和原本允许的动作；不从坏输出中提取动作，也不把格式失败报告成任务服务不可用。主对话进入任务解释时，使用带宿主来源绑定的 `bunny.task-context/v1` 交接近期消息与已组装的召回正文，保留角色及主人身份元数据；完整证据存于宿主私有状态，随采用和续办保留。澄清短答案只补充或更正有效需求，不替换前轮目标、约束与交付条件；解释仍在同一轮模型调用中完成。召回资料、助手承诺和操作经验不提供新增授权，发给执行软件的正文仍只由整理后的业务字段组成；验收读取同一证据并经过敏感值保护。

适配器定位缺失或歧义是方法失败，只有已证未发生输入或提交时才允许沿原操作切换到前台/视觉。诊断跨原生桥、执行器、效果账本和任务恢复保留操作、方法及候选数量，不靠错误文案正则判断；只记录元数据。视觉输入须附同一当前截图的完整前置条件证据，目标窗口或截图变化后重新观察。真实草稿/工作位置冲突保留，未知输入/提交仍走原效果核对；不因换方法扩大权限、改写旧草稿或创建重复任务。恢复预算不增加，安装恢复不自动重放 needs_attention；主人明确继续时复用原 Task、物理操作、正文和关联标记。

交办还保留输入未知、草稿已确认、提交未知和已绑定的阶段视图，完整交办不会因“仅草稿已写”被改记为完全未执行。已确认原草稿且无提交证据时，恢复只允许读回完整匹配、Bunny结合当前画面判断后聚焦/提交一次，禁止Fill、type、清空或新建；初次提交未知而尚无会话绑定时，只接受精确正向回执，缺少记录不能变成未提交证明。提交前拒绝明确记录本次not-dispatched并恢复旧标志，历史未知提交不清除。恢复授权仅在当前进程生效，重新加载后needs_attention可被动核对、输出脱敏阶段诊断，但未经本次明确恢复不触发GUI。

续办在填稿前保存独立轮次、原消息基线和起始时间，本轮检查点只投影该轮输入与提交；前轮真实回执留在 `priorSubmission`，不确认新草稿。观察、只读对账及恢复接收共用轮次边界。当前续办阻断按工作、轮次和时间绑定，优先显示当前原因；失败历史保留来源，原操作或原 Action 成功后标记已解决。界面“核对已结束”仅确认控制请求返回，不声明业务 Task 完成。

`submission-draft` 提供确证未派发补充的独立恢复机制。证明绑定任务、轮次、完整草稿 hash 和输入步骤；有效提交意图、已派发或新消息回执都优先阻断。旧记录只有完整匹配的正向回执、填稿、派发前拒绝和暂停日志链才可取得该证明，错误码或消息缺失不够。`reviewPriorResult` 请求在同一验收中让 Bunny 结合完整主人证据、前轮成果与补充稿明确选择保留或放弃；只有原目标已满足且明确选择放弃，才先持久化完整草稿归档，再沿前轮真实回执交付。它不发送或清空执行软件编辑器，不把本轮标成已接收，也不改原 confirmed 操作。每组不变证据只自动复核一次；人工暂停不自动恢复，来源、控制代次、草稿或成果变化会拒绝迟到采纳。界面仅在宿主证明有效时提供“保留补充草稿，重新核验原成果”。

完成事实通过同一 `session/messageKey` 核对并同步状态、实际正文、完整链接和时间，不把进入 review 当成已保存完成回执。旧补充恢复先证明未派发，再只读核对原消息的完成事实，补齐深克隆候选及前轮 snapshot 后严格判资格；候选不提前改写执行记录，正式归档使用同一份复核事实。单任务记录、经验、回执或报告恢复异常不阻断其它任务；脱敏诊断仅记录阶段、任务标识、固定原因类别、错误码和代码位置，不记录错误正文或私人路径，同一未变化诊断不反复输出。

宿主控制器的 `suspend` 与用户/业务 `stop` 分开：退出仅持久化 typed `host-suspend/process-exit`，保留业务阶段、草稿和未知步骤；其它宿主暂停保留原阶段并暂停输入。真正停止记录 typed terminal，后续挂起不覆盖它。控制器挂起幂等且写入有序，旧代次取消回调不能释放新租约或覆盖新任务；普通启动取消不伪装成用户停止。checkpoint 去重包含有限业务状态与生命周期事实，Vault 拒绝保留有限原生错误码和宿主请求操作，不记录请求参数。旧版无结构化意图的 `stopped` 即使有完整未派发证明，也只展示明确重验入口；该许可绑定当前进程、控制代次、任务、草稿和五分钟时窗，不能凭“应用退出”文字自动恢复，不能覆盖 Task 终态或 typed 用户停止。

规划模型返回not_applied只保存为未验证解释，不得清除submitAttemptedAt、原提交截图或已派发步骤，也不能把已commit的Action回退到preparing。无可靠回执时以E_SUBMISSION_UNCERTAIN停止本轮、保留未知；只有真实派发前拒绝或独立完整核对路径才可继续。临时标志丢失时，持久提交步骤仍恢复写入屏障。初次交办的精确正向回执匹配涵盖最早未解提交尝试，后一次历史重试不能把较早成功回执排除；续办各轮的时间与消息边界不放宽，重复标记仍视为歧义。

独立结构化通道可记录预期/实际应用与进程；纯视觉仅记录实际画面的身份/区域、帧令牌、阶段和操作回执，不查询前台或窗口来判断失焦，文案不猜是谁切换。显示点坐标与图像像素坐标分别换算，不混用。宿主只对有效几何已证命中的Bunny交互区域阻止原始指针派发，不关闭人工停止界面、不使用hover猜任意屏幕点，也不声称已验证所有第三方遮挡。软件中如何改用合适操作方法仍由经验与Bunny判断。

`operation-diagnostics.js` 统一关联 Task/Action/Operation、控制器、视觉会话、截图和 native 请求：记录 UTC、进程内单调时钟及序号，区分意图、请求派发、原生回执、取消、超时和未知结果。字段白名单只保留类别、长度、坐标、像素摘要与散列引用，不记输入正文、联系人、模型识别原文或目标程序资料。错误中的 `operationTrace` 引用沿现有 diagnostic/lastFailure 链流转，不参与恢复预算指纹。视觉变化只是已有显示像素的几何/区域变化；不可见、登录或安全提示由同一次 VLM 观察分类，不能据此推断应用退出时刻或责任方。

可选共享像素来源通过启动环境 `WORKBUNNY_DISPLAY_PIXEL_SOURCE` 显式接入。`shared-display-pixels.js`读取本机私有manifest及Unix socket，校验HMAC、请求ID、像素digest、显示几何、来源类型和时效，整个请求不超过1.5秒并可取消；断源不回退创建第二条显示流。普通默认路径保持独立。共享模式只允许通用displayCapture，不兼容的旧窗口采集明确拒绝；键鼠仍经原生层核验后派发。独立录屏源持有唯一CGDisplayStream，Bunny和录屏消费者只读取它的普通显示像素，不取得目标应用信息。隔离协议/编码验证与真实同机并发、音轨验收分开，正式录制前须完成本次短样。

元数据异步写入本机 `userData/operation-diagnostics`（目录0700、文件0600），最多8个2MiB滚动日志；队列256KiB、内存512事件，写盘超时或丢失明确标记，不等待磁盘才能感知或输入。只复用正常观察已采的像素，内存最多4帧、每帧4MiB、30秒；同一capture优先复用已经产生的原分辨率视觉区域/输入预检裁切，记录来源尺寸、实际尺寸及区域，不为留证降采样；仍超限则记缺口。异常可保留最近2帧及随后10秒内正常采到的关联帧，总共最多4次留存尝试，不新增截图、模型调用或目标程序查询。图像以 Vault 钥匙派生独立密钥，通过异步AES-GCM加密，元数据头也受认证；无钥匙、超限或队列忙则记录缺口，绝不明文回退。密文最多24份/64MiB，7天清理在启动及后续写入时执行。取证文件不进入记忆经验、模型上下文或公开发布；仅脱敏引用进入错误链。`readTimeline()` 有界读取本机元数据并区分最近关联输入、已确认输入与未知回执；覆盖不完整、未观察区间及日志缺失永不作为未发生输入或精确退出时间的证明。`readEvidence({session,incidentId,captureId},{authorize})`默认拒绝，接受宿主已有明确授权并精确只读一帧，解锁后使用本机Vault钥匙、限制密文字节数并验证AES-GCM及像素digest，返回图像而不返回钥匙或路径；锁定、缺失、撤权及有界超时如实报告。受信本机设置窗口可经preload的operationEvidence入口明确触发，同一授权不逐帧弹窗，读取不会自动上传。该机制仍不能观察暂停期间未采到的画面、证明事件接收效果或外部平台因果；隔离测试不等同于真实应用验收。

### 本地停止与外部清理

`AgentRuntime.stop` 立即以独立快照替换正在执行的 Task，保存 `stopRequest`、终态 `stopped` 与清理截止时间，取消控制器并发布状态。旧闭包持有旧对象；代次、对象所有权、效果发令与检查点共同阻止其改写当前记录、继续输入、上报、交付或恢复。结束任务不再占用五项启动名额。批量停止先同时封住各 Task，再等待清理；任务接续退役也使用独立快照。停止保存失败仍取消执行，并明确报告持久化缺口；停止回执不依赖全局准入或慢写入队列，外部清理到时结束，最终记录保存只再等待有界确认期。

任务卡片、任务栏 X 和任务面板走相同控制链；两处渲染复用 `task-controls.mjs`，提供处理中、慢响应、成功、不可执行和失败反馈，重复点击复用在途命令，刷新保留提示。主进程记录命令入口、请求标识、目标和结果，不记录交办正文。状态流立即确认本地停止，IPC 后续结果补充外部清理信息。

`TaskResources` 保存任务资源身份、状态与逐项 `cleanupLog`，统一清理本地控制器、适配器绑定的外部工作、独立终端进程组和应用。命令记录真实 PID、进程组、内核启动时间、用户与可执行路径；应用记录 PID、Bundle ID、启动时刻和共享归属。重启缺少活句柄时须重新比对身份，PID 或进程名本身不构成停止权限。原进程退出但遗留进程的当前归属不明时保留并报告；自行脱离进程组、任意脚本在其它服务中产生的工作不能承诺完整追踪。

停止只进行一轮清理；`stopRequest.version=2` 与资源 `cleanupAttemptedAt` 保证失败、超时、迟到身份和重启都不重复发起。旧版未完成停止在恢复时迁移为终态，保留原错误和身份。清理总时限30秒，外部资源并行核对，软件操作仍遵守 GUI 租约。到时取消清理、记录未确认项，本地 Task 始终 `stopped`。原生资源操作在发令前校验请求期限；迟到执行结果不能复活 Task。共享或原先已运行的应用保留，正常退出等待真实进程结束，不以已发出退出请求当作完成。WorkBuddy 对话停止属于执行适配器能力；未绑定的新轮次不能借旧回执宣称已终止。委派宿主没有独占应用证据时按共享应用登记，只核对对应工作，不退出宿主软件。

`software.recover` 提供通用诊断与有界恢复能力，由 Bunny 结合任务、经验和真实错误决定何时使用。它要求两次有时限的接口探测确认无响应，并确认当前或已停止 Task 的专属启动归属、没有其它 Task 共用，再尝试正常退出。失败后，原生层重新核对持续无响应、精确身份以及完整窗口列表的未编辑标记，才允许受限强制终止；状态不可读不能当作无未保存数据。重开后需取得实际响应证据，同一任务对一个软件最多两次恢复意图，步骤和拒绝原因保存在 `recoveryLog`。软件窗口路径、按钮步骤和使用技巧仍由可修订经验提供，通用机制不内嵌某个演示的流程。

## 5. Action 与 Operation 效果

Action 有独立取消信号、对象 scope、事件 key、策略、阶段与进度。`independent` 独立推进；`newer-event` 仅在同对象新事件时替换或重规划。父 Task 取消传播到 Action，无关对象不会隐式取消它。

逻辑阶段为 `preparing → protected → committed`：准备时可安全替换；保护阶段已有草稿或相关操作，需要在检查点处理；提交后保留实际效果并核对。阶段名称不直接代表业务完成。

Operation 账本区分三种事实：

| 状态 | 含义与恢复 |
| --- | --- |
| `intent` | 已登记意图；若发令情况不明，则不能盲目重放写入 |
| `not_dispatched` | 明确未发令，可重新规划；同逻辑步骤的新参数形成新尝试并保留替代关系 |
| `confirmed` | 取得工具实际结果，保存回执；写入重试复用该记录，不重新执行 |

`OperationLedger` 在进入异步授权前预留逻辑操作标识，并一次保存发令意图和初始阶段。权限或期限变化会在工具发令前复核。微信发令、草稿处理和发送核对共用同一条桌面会话执行队列。

0.26.45 中，桌面原生桥的退出、断管和异步写入失败统一进入停止路径。请求在对应 BOPER scope 释放完毕前仍登记在 pending 中，按原 `ownerId + scopeId` 去重清理，最多等待 2.5 秒；超时明确保留 `releaseConfirmed:false` 与未知输入结果，不凭请求拒绝认定输入已停，也不重放。清理期间禁止启动替代原生桥；旧进程退出不取消新 scope。BOPER 的续租成功/失败回调均核对原活动会话，旧租约失效不污染后来的会话，当前租约真正失效仍停发并进入故障。

工具回执确认不等于业务目标已完成。Bunny 按任务目标取得页面、消息、文件或数据证据，自主决定 Action/Task 完成。程序只验证协议、对象、权限、来源、文件稳定性和真实调用事实。

通用视觉 Action 可基于关联的提交前后证据提出 `not_applied` 解释，但不能单凭模型解释改写账本或退回准备阶段。恢复依据必须对应原 Task、已核实视觉身份与会话；其它联系人画面不能解除未知发送。仍不确定则继续核对，保留账本，不自动重发。

## 6. 时间、资源与恢复

全局 `bunny-principles` 与 Action 指导把怀疑、历史反思、探索和补救作为可组合的认知职责。Bunny 按情景联合或分别审视一个或多个关键疑点，以已有材料、新观察或安全探索区分解释；必要时二次、三次评估，不固定串行步骤和核查次数。确认障碍后仍回顾历史步骤与错误后果，随反馈修订认识与策略。软件技巧继续由经验提供。

`action-recovery` 保留同一恢复 episode、累计成本、证据和操作账本。任务脑只有明确判断卡住且自身无法突破时，才登记 `selfSuspension`；预算耗尽单独以资源信号升级，不能冒充业务判断。`MainReview` 是 `AgentRuntime` 的调度组件：待办只存于原 Task/Action 的 `mainReview`，使用原 `schedule/tick`，不建立第二任务队列或执行账本。整任务自挂起映射为带来源的 `paused` 并释放名额，单 scope 挂起不阻止其它 scope；独立的审阅选择器仍能选择它，主人或保护性暂停不能自动恢复。

Action 在异步来源核对后建立时，会重新安排同一个调度器的唤醒，保证首次工具或模型调用尚未返回期间仍有主动督导检查；不依赖该调用先完成，也不另建监测定时器。

主脑通过 `SelfSystem.reviewTask` 读取与对话同源的先天设定、角色、相关记忆、Summary、经验、近期有效情景和相关任务简报。它不走 `think({internal:true})`，不拥有对话的 busy/controller、ASR/TTS、UI、消息数组或 GUI lease。角色与记忆读取由 `prepareContext` 同源装配，Summary 和经验按实际 token 预算选择并标明缺项；主脑只返回可修订的认知指导，原任务负责落实和验收。

指导以 reviewId、episode、scope、目标/控制/授权与写入效果版本校验，沿原任务保存串行区提交，提交后再唤醒。普通只读操作 ID 和心跳不使建议机械失效，相关新观察以 `observationDelta` 交给原任务复判；目标对象、权限、停止、写入及未知效果变化仍阻止旧建议。`continue` 在原 scope 的安全边界消费；只有明确提出检查点重启、命中失效执行信号且没有其它活跃 scope 时，才隔离唯一旧 worker。其它 scope 的正常计算和在途写入不被督导取消。

有效策略在同一 episode 获得有界新窗口，保留累计尝试、planRevision、真实效果和未知写入。默认每局部窗口三次、每个 resourceCycle 最多三次主脑调用与十二次局部调度；同一 guidanceId 幂等，内部新策略不续开资源周期、不清零累计账本。主人明确继续可开启新的 resourceCycle，保留同一 episode、lifetimeAttempts/lifetimeReviewCalls、旧周期摘要及原操作账本，避免返回已继续却立即因旧额度再次耗尽。主脑最终业务决定记录为 `state.disposition`，不覆盖原 `state.resolution`。普通 notify/澄清、主人控制和即时权限/未知效果保护仍沿原路径处理。可信新证据对自挂起或主脑暂缓只触发复评，不越过主脑自动唤醒。

`ModelAdmission` 在同一传输层保留四个物理调用槽，后台最多三槽，为主人对话留一槽；没有无界模型队列。`E_MODEL_BUSY` 是普通资源等待，不消耗恢复或督导预算。调用取消/超时后，未确认结束的物理请求仍占原槽，直到实际 settle。上下文、审阅模型和初始保存等待都有界；实际保存串行区不会因逻辑超时提前释放，挂住的指导提交只阻止本任务的提交链，不占全局审阅槽。底层 Vault 全局不可用仍会限制持久化，不能据此声称业务失败。

`taskSupervision.enabled` 可关闭新增督导；`proactive` 关闭主动异常干预。回退保持已有自挂起、暂缓、停止及未知效果，不自动回落到旧重试。已绑定 WorkBuddy 的异常监测进入原 Task 督导并合并旧通知，外部自行创建的 WorkBuddy 工作继续沿原提醒渠道。普通 Skill 继续沿既有视觉能力、免费模型与受控 fallback 的校验传输；仅困难反思使用独立 `reasoningRequest`，主脑督导使用配置的统一自我模型。组合软件、系统、会话和屏幕判断通过同一 `ctx.recovery` 消费指导；WorkBuddy 验收在宿主上下文消费指导，内部反思不原样传给受托软件。

延时复试复用原任务调度器，不持有 worker 或另建周期轮询；Action 自身期限独立于其它事件改变的任务周期，重启保留未到期等待，新消息可按 scope 继续调度。默认单轮执行调用上限六分钟，恢复判断与保活判断各十二秒；底层工具原有更短期限仍有效。这些限制不限制整个 Task 的正常业务耗时。达到调用时限或用户暂停时替换当前 Task 对象并隔离旧闭包，取消信号、对象所有权和操作预留代次共同封住旧调用；实际已发令且不确定的写入继续保存为 `intent`。迟到结果仅可合并与当前 intent 的 ID、工具、参数摘要完全匹配的已核实写入回执，不能合并旧状态、报告、计划或复活任务；旧操作结束也不能释放新操作的同名预留。另一事件完成不能掩盖尚未解决的 Action 或未知写入。

`ActionProgress` 记录累计时间、阶段时间、模型/工具耗时、等待条件及重复证据。时间戳变化、相同截图和新的模型措辞不视作外部进展。耗时与重复触发 Bunny 的恢复思考；宿主的诊断预算仍有界，不应宣传为无限自动重试。

来源授权检查区分‘实际来源已失效’和‘暂时未能读取来源’：前者保持授权阻断，后者以 `E_TASK_JOURNAL_UNAVAILABLE` 进入有界恢复；未取得新的有效来源证据前不发令。视觉会话历史复用同样要求双方都有有效且相同的视觉账号标识；缺失身份或旧 PID/窗口记录不能因两个空值相等而混入历史，原记录仍保留。

连续技能可通过 `activeAction(task)` 返回稳定阶段键，把建立观察基线、主动开场等有限准备接入同一逻辑 Action；返回空值后退休该准备动作，正常被动监看不累计停滞。准备阶段的进度和恢复建议经 Operation 生命周期传给嵌套视觉执行器，物理执行编号变化及规划超时重试不重置逻辑计时。重复失败且耗时明显时复用既有停滞判断，恢复服务不可用时有界停止并保留任务；暂停或取消使迟到建议失效。实际模型请求保留重复证据反馈及恢复建议，不只在注入测试规划器时传递；这些信息不能扩大权限或解除未知发送屏障。

`SelfRepair` 分类上下文超额、Schema/协议、输出截断、响应过大、未知异常及停滞。以最简上下文调用模型，建议压缩可选上下文、修正本轮格式请求、调整输出预算、再观察或换方法；本地契约限制可调整范围。网络等待与权限等交给既有恢复路径，不全都归为同一种异常。

响应体过大应缩减本轮输出/推理预算，输出截断可扩大输出额度，两者分开处理。只读模型规划尚未产生 Operation 时可以请求级恢复，避免为纯传输问题重开整个任务。已确认和未知写入继续遵守效果账本。

输入额度折半仅能是单次请求中的显式减量，不能写入持久修复 profile，也不能由输出压缩隐式触发；旧 `budgetScale` 不再作用于新阶段。Bunny已经明确调过组装配置时，旧 `contextLevel` 不得在组装后再次裁剪其选择，使元数据与实际请求不一致。恢复计数仍受既有边界限制，不因估算尺寸漂移重新续期。

同一目标和事件的恢复计数不因错误码、文案或步骤调度序号递增而清零；新的外部事实可触发新一轮恢复决策，失败方法和错误描述变化不续期进展时钟。暂未找到可安全调整时仍可在预算内重新核对；耗尽恢复预算后，执行也转入 `needs_attention` 并报告缺口，保留原目标、事件和效果，不在停止诊断后继续定时重放失败步骤；主人明确恢复可以重试原任务。未发令的 GUI/采集资源竞争保持原计划等待，不消耗错误恢复预算；未知写入继续只读对账。

权限维护与未知写入核对复用原来的三秒维护入口，彼此独立推进，权限检查等待不阻塞对账。恢复状态保存排队、核对、等待空闲、待补证、实际检查时间及退避后的下一时点，界面不再用普通任务周期冒充恢复节奏。WorkBuddy 对账除查找新回执外，可在完整绑定日志已读到当前文件边界、原会话与原文草稿匹配后，由 Bunny 综合画面判断 `not_applied` 并同次选择恢复操作。权限核查后再次检查新回执、原文和目标，只允许聚焦原编辑器及一次提交；不重写正文、不增加轮次。迟到回执优先，未知判断按证据缓存，同一正文与轮次最多两次恢复发令，随后保留待补证。

`AgentRuntime` 用一个定时器选择最近的检查、到期或保活时刻，空队列和结束态无需周期唤醒。达到指定时长会取消正在运行的 worker 并保留写入证据。`TaskKeepalive` 在工作空闲一分钟且没有 worker、模型请求或有效等待时，按原 Task/Action 上下文提醒继续思考，每个作用对象只保留一条在途提醒。提醒的计时与业务进展计时分开。

GUI 准入在未持有资源时检查连续空闲五秒及 lease；动作已持有 GUI 后不再用 HID 空闲时间判断“人正在干扰”，因为自己的输入也会更新时间。准入诊断仅记录当前就绪、lease 空闲、HID 空闲毫秒和固定原因，不记录持有者身份，也不凭 HID 数值归因实际操作者；主脑督导失败复用脱敏恢复诊断记录固定错误码，便于区分模型、本地资料与超时。桌面输入串行，语义工作及无冲突动作独立推进；屏幕采集连接复用并有界缓存。

锁屏轮询经独立 `sessionState` 原生入口只读取 `CGSession` 锁屏状态，不再为此调用整包权限查询或 AX／屏录／键鼠授权检查。轮询周期和有界请求时限不变；该入口在系统会话字典不可得时抛固定错误，读取失败或返回非布尔状态均按锁定处理，锁屏事件与关闭会使旧读取结果失效。原输入／采集共用的锁屏函数未改。已有锁屏隐私清理、任务暂停及解锁后的恢复流程保持原入口。此变更已通过离线生命周期测试和 Swift 类型检查，未据此宣称微信退出原因或实机验收结果。

全局自主生活、主线程健康检测、外部进程看门狗和任务保活各自独立。任务调用和恢复判断的异步等待有界；阻塞 JavaScript 主线程的同步代码或基础存储/进程故障仍依赖原来的进程健康与底层超时机制，不能据此宣称绝对无故障。

## 7. 感知契约

`bunny.perception/v1` 伴随原有内容字段传递：

| 字段 | 内容 |
| --- | --- |
| `channel/sensor` | 采集渠道与实际感知器 |
| `originalFormat/format` | 来源形态和转换后形态 |
| `transforms` | 实际有序转换，如 `asr/ocr/vision` |
| `level` | `direct`、`converted` 或 `inferred`，由转换链推导 |
| `observationId` | 可选观察标识，不表示原音频一定保存 |
| `evidenceId/evidenceFormat` | 可选实际证据引用与形态，读取时检查是否仍存在 |
| `sourceChannels` | 组合来源或记忆派生的上游渠道 |

感知器登记、规范化与有界 `EvidenceStore` 位于 `perception.js`。键盘、本地 ASR、屏幕 OCR/视觉和微信语音转写已接入。微信转写仍以实际转写画面为证据，不能冒充取得原始音频。

本地语音采集由 `AVAudioEngine` 读取原始麦克风；启用回声消除时，私有、unmuted 的 CoreAudio 全局输出 tap 提供扬声器混音参考，经固定版本 WebRTC AEC3 处理后再按识别器要求转换格式。VAD、ASR 和声纹特征读取同一份最终 PCM。该链不启用 AGC、不修改设备音量或默认设备，也不启用带系统默认 ducking 的 VPIO VoiceProcessing。参考权限拒绝、初始化超时或断流时有界降级为未经 AEC 的采集并持续收音；参考恢复受控重试，设备打开却始终没有首个回调也受首包截止保护，拒绝权限不反复触发请求。`active` 只表示参考新鲜且 DSP 调用成功，不能证明物理回声已消除；转换帧时轴及实际扬声器效果仍须验收。实现见 [`speech-echo-cancellation.swift`](../native/speech-echo-cancellation.swift) 和 [`echo-cancellation.cpp`](../native/echo-cancellation.cpp)。

噪声抑制使用 WebRTC APM 的上游默认配置，所有输入设备共用同一路径；不围绕本机样本调等级，不增加文本音频门控或第二套识别引擎。设备配置变化只异步请求采集恢复，通知回调不获取采集锁或同步销毁引擎。独立控制队列合并同 capture epoch 的恢复、忽略失效通知并在执行前重新核对健康状态，沿原 helper 退出与 host 重连路径恢复。缺少新鲜采集归 transport/code22；采集仍新鲜而 VAD 失效才保留 code25。空会话只提示重连，有尚未交付的文字才提示重说；固定非文本 `capture-health` 记录分类和时间差，host 收到有效恢复认领后立即退休该进程的业务输入，迟到文字不能趁退出间隙再发起对话。

物理音频流通过 [`audio-pcm-stream.swift`](../native/audio-pcm-stream.swift) 统一管理转换缓存和时间：同采样率的声道、类型转换不走有隐含分块的 SRC 接口；异率转换以首输入采集时间加累计输出样本计时，不能把缓存中的旧音频重新标为当前回调时间。AEC 的参考配对保留有界的短捕获缓冲，使必要的参考先行进入算法，输出仍保留原始采集标签。传给 WebRTC 的缓冲延迟按同一 host clock 计算 `(renderAt-analyzedAt)+(processedAt-captureAt)`，包含参考帧领先与实际调用间隔，不能把参考领先的正延迟反向截为零；`aecBufferingDelayMs` 与 AEC 内部延迟缓冲统计 `aecDelayMs` 分开记录，后者不等于独立测得的声学传播时间，不能相减据此调整参考对齐；参考丢失释放原始输入，显式停止排空真实尾部，不靠补零、裁去主人声音或关闭聆听获得消回声效果。普通 Analyzer 切句不重置物理转换器。默认诊断只保存既有处理后 PCM；额外的原始麦克风和精确算法参考仅可由显式诊断参数启用，共用已有时间、字节和私有目录边界。

本地 SpeechAnalyzer 装配 SpeechTranscriber 与 SpeechDetector，使用 `volatileResults + fastResults` 增量输出，按音频范围合并修订并用真实 finalizer/drain 确认整句。移除 fast 的真实录音对照首结果约11.7秒，恢复后约2秒。SpeechDetector 提供持续收音时的人声门控；默认中档，听力面板提供低/中/高声音敏感度，低敏感度映射更激进过滤、高敏感度映射更宽松过滤。更激进可能漏轻声，不能以识别字数少判断质量好。相同3.072秒旧噪音片段，无门控会识别为 you，中档正常空结果；轻声片段中档仍保留原字。以上是已有样本验证，不保证所有设备及声场。

#### 语音热词管理开发计划与实现

范围：扩展现有系统识别的上下文词表，不更换识别引擎，不增加 LLM 纠错请求，不改变 AEC、VAD、600ms 断句、流式结果和打断/提交机制。

- [x] 配置与迁移：保留 `asr.wakeAliases`，将入口移到“设定”的名字下；新增可由用户和 Bunny 共同编辑的 `asr.hotwords`，缺失时默认 `WorkBunny`、`Workbuddy`，显式空表不恢复默认。统一校验短语、去重和总库合计512项上限，系统上下文独立最多100项。
- [x] 识别接入：每段识别的词表为正确名字、用户昵称、额外热词的并集，独立于近音唤醒容错变体；启动参数和运行时更新共用相同组装。更新排队到下一自然识别段，不取消当前输入或重启采集，原生回执区分已接收、已提交上下文和失败，不声称已提高识别准确率。
- [x] 自主管理：统一服务提供读取及添加/修改/删除额外词的原子补丁、版本检查和真实保存回执。主对话通过已有 action 提交门执行，任务通过现有工具和 OperationLedger 执行；仅管理额外词，不赋予修改身份、任意设置或普通联系人写入权限，不新增后台维护模型轮。
- [x] 界面同步：听力页提供额外热词输入框，用户与 Bunny 共用一份保存数据；外部更新刷新无草稿控件，有草稿时保留用户编辑，并保持组件间距。
- [x] 验证与交付：旧配置/清空/去重、增改删和并发冲突、取消/未确认语音不写入、任务权限和工具回执、界面布局/保存同步、原生词表切换及既有语音回归通过；产品要求、流程和受保护基线已同步，本地签名安装并启动。正式进程参数包含名字与两个默认词，原生日志持续返回3项上下文的 `submitted` 回执。

实现入口为 `hearing-hotwords.js`（统一词表、版本及同步原子补丁）、`hearing-hotword-tools.js`（动作和任务窄工具）、`speech-context.swift`（自然段边界的只读快照）。设置与 Bunny 共用一份持久配置，清空默认词不会复活；仅损坏或超限的历史配置在加载时安全修复。额外词热更新不重启采集；名字、昵称的修改仍沿既有识别器重启路径同步唤醒名称，新进程重新组装完整词表。主对话当前词表直接随既有请求提供，更新动作在语义接纳与副作用提交门之后落盘并返回实际回执；任务写入沿 OperationLedger 记账，未声明权限的 actor 和普通联系人不能写入。

USB 手机外放测试使用独立诊断接收器及生产 `Asr`/`asrOpts`/原生代码，不将测试转写送入对话或任务。无热词与5项热词分别得到每段 `submitted` 回执，未出现上下文错误；运行中由3项更新为5项得到 `queued revision=1`，下一 Analyzer 段得到相同版本的 `submitted`，采集进程未重启。同一份手机实际录音再做有/无热词对照，最终转写完全相同，仍将目标角色名误转为其他词；两次现场外放中单字“停/亭”的差异不能归因于热词。结论仅证明词表调用和更新路径，不证明当前 SpeechTranscriber 获得了准确率增益，也不承诺系统对所有设备或词都有效。

原生独立调用对照与公开证据均未找到可复现的 SpeechTranscriber 中文词表增益。[Apple 开发者论坛采纳回答](https://developer.apple.com/forums/thread/811083)称 contextual strings 目前只帮助 DictationTranscriber；回答者身份不作为已核实的官方承诺。[ListenToMe 的公开对照](https://github.com/tomqwu/ListenToMe/blob/main/docs/vocabulary-biasing-evaluation.md)在 macOS 27.0.1 / iOS 27.0 上确认 setContext 成功、prepare 后仍保留100项词，SpeechTranscriber 的英语目标得分仍为36/64，运行中更新的16组有效配对也无增益；其英语样本不能外推所有中文。[FoxTake 开发者的中文测试报告](https://dev.to/deskfox/on-device-video-captions-with-speechanalyzer-on-ios-26-what-worked-and-what-didnt-2g65)同样称添加脚本上下文前后输出不变，属于有限的第一手样本。以上支持当前不更换引擎、不把上下文提交当作生效，不能断言所有未来系统版本永久不支持。

补充理解路径在现有一次对话调用内完成：`think` 读取同一 `hearing-hotwords.snapshot`，将只读、去重且有界的名字、昵称和额外词作为 `voiceContext.vocabulary` 随 `microphone-observation` 提供；ASR 专用经验第8版要求结合词表、句法、语义和近期对话理解近音误识别后直接回答，不新增纠错请求，不重复附一份系统词表。词表只是解释线索，不作为本轮原话、指令、识别证据或权限。原始转写保留，合理普通词句不强行替换，关键操作对象和授权不臆补，skip 仍完全静默。实际 `think`/`requestReply` 请求夹具验证词表和规则同包、原文不变且仅一次模型调用；不把此集成验证等同于真实模型每次均能正确理解。 已有本地名字近音前缀匹配随普通ASR观察进入模型，允许模型结合语义判断；接纳后的历史记录保留当时的匹配线索，兼容旧记录缺省，不授予身份或操作权限。第8版明确单独呼唤、问候和简短回答也可完整成立，移除已失效的 `allowShort` 参数及90秒接线。环境声可能被误转成孤立短词，与上句用户发言间隔较久只作语义线索，结合 `sinceAcceptedOwnerMs` 判断；当前名字、昵称和别称的近音单词优先核对呼唤关系，不设字数或时间硬门槛。回顾历史时保留 ASR 来源，并允许修订先前助手对原意的猜测；键盘追问在已有历史含本地 ASR 时也附带同份回顾规则及当前词表。

热词总库去重后最多512项，名字和昵称计入总量。[Apple 的 contextualStrings 文档](https://developer.apple.com/documentation/speech/analysiscontext/contextualstrings?changes=_1)要求系统上下文总计不超过100项，因此统一先取名字、昵称，再按额外词表顺序填充100项；主对话理解仍使用完整词库，系统回执仅表示实际提交子集。主人明确纠正重要且罕见的人名、区域地名或专用词后，Bunny在同轮可主动提交增改补丁，保存成功再回应；常见词、重复和过时内容应精简。主对话与任务上下文省略可推导的effective重复列表，仍按现有上下文预算返回超额省略信息，任务可经既有read工具读取完整词表，不额外安排纠错或后台维护模型。

句尾依据独立的 WebRTC VAD（固定 libfvad/WebRTC 内核，工作适配层使用 quality mode 0），只读同一 `toSend`，不修改 AEC、转换、声道、音量或送给 Analyzer 的样本。按每通道完整 10ms 帧观察：有声、非语音、未知分开；任一通道有声即阻止静音累计，残帧保留，错误、不支持格式、断档或旧代次均不当作无声。VAD 的模型、残帧和时间连续性属于物理音频流，不随 Analyzer 句段重建而冷启动；代次只用于观察归属和拒绝旧回调，真正音频断档或格式失效仍清理状态。端点策略独立按 Analyzer 代次重建，本代曾有活动或已有识别文字、当前证据新鲜且持续非语音达到 600ms，便开始收尾；已有真实声学活动时，迟到的文字修订不重新启动静音计时；只有文字而未观察到活动时仍要求文字稳定；无检测事件或文字暂时停更不能代替静音。排队 PCM 的 VAD 证据按实际进入的新 Analyzer 代次、与输入同序建立。

原生层核对实际输入范围、临时修订与确认前缀，保证真实完成回执。转写原字仍保留诊断，不按词形、语言或字数设黑名单。独立 VAD 记录同一结果音频范围的直接活动，不把算法 hangover 算作新的人声证据；至少连续60ms直接活动才提供 `speechSupported`，隔离瞬态、未知间隙和旧来源不能拼接。此证据不证明是主人或非回声；旧 you 误识别仍有130ms直接活动，时长阈值不能独立解决，系统人声门控是主修复。宿主在进入轮次及中断前核查声学支持；无支持候选仅保留原始诊断。

`SpeechEcho` 以实际播放 ID 和角色窗口回执登记播放起止；合成中、排队中和旧 ID 的迟到通知不构成已播放依据。播放记录绑定当时的上下文代次，只有当前上下文已实际开始的播放片段可进入 ASR 提示上下文，避免跨场景带出私密话语。ASR 回调携带采集时段，优先按该时段追溯回声，避免转写迟到时越过短暂尾窗；连续实际播放的队列句可合并核对，未播放或不相邻回复不拼接，缓存及近似匹配计算有界。这些匹配是 ASR 对话判断的上下文线索，不是丢弃转写的文本黑名单：主人也可能重复 Bunny 刚说过的话。非已知播放回声的有效 partial 或整句在交给轮次前同步中断当前朗读和未完成对话，已知播放匹配仍交给语义判断但不触发中断；AEC 开启本身不能证明有人插话。回声匹配并不完美，主人重复 Bunny 原话也可能被延迟识别为插话。声音看门狗按 WAV 实际格式估算时长，正常完成仍以对应 ID 的播放回执为准。

活动证据失效四秒或首段文字达到既有最长时限，取消本段，不提交半句；正常静默持续提供有效非语音观察，不会仅因一直无声报错。静音解除后重置活动证据与健康宽限，保留文字和原最长界。原生失败回执携带 `kind/code/reason/fatal/gen`，host 先退休失败输入并隔离迟到文字，再按来源分类恢复：普通识别、空段定稿及未确认输入失败静默丢弃，以1.2、2.4、4.8、最多8秒退避自动恢复，不弹气泡、不发声、不触发模型，也不关闭耳朵。失败不能产生 `final/utterance/audioFinal` 成功凭据。host 的输入确认和声学提交截止沿同一识别恢复路径；仅已被语义接纳且实际请求提交的操作失败保留“未执行”通知。采集、权限、语言资源等真实故障仍反馈；连续三次真实 VAD/code25 故障停止自动重试，由主人重新开启。两类失败计数分开，启动/就绪、仅原生定稿及语义接纳不清真实采集故障计数，须 host 实际发出回复或控制回执；后台自愈不能绕过等待主人状态。实际原生失败注入与主进程事件测试覆盖空段定稿失败静默、无成功凭据、重试及真实故障提示。

最终上报须同代次收尾请求、完整输入 finalizer 成功及结果流正常排空齐备，并锁内一次性认领。`resultsFinalizationTime` 是已收到结果的水位，不是唯一收尾回执：系统允许未变化的 volatile 文字在收尾时不补发 final，因此水位落后不能抢先判失败。两侧回执到齐后才确认最后一次范围修订，仍须核对全部文本位于本代实际投喂范围；撤回、失败、超时、异常结果流终止及旧代次不能提交。成功回执已齐备后，晚到的超时回调不能在认领前反向使它失败；仍缺回执时超时保护照常生效。已稳定文字的时间范围独立保护，同文重复与相邻边界的微小舍入不删除前句；真实冲突或无法精确保留已稳定前缀的局部替换不得猜测剪字后提交。普通日志仅保留有文字的完成及失败的固定非文本收尾元数据，便于区分旧水位和真实 API 失败。每次已交付音频的活动观察可异步触发收尾复核，避免只靠 150ms timer 错过短暂合格窗口；通知合并、代次隔离，并在关闭输入前再次核对最新活动。timer 保留健康和最长界兜底。独立 VAD 仍可能误判，文件回放与纯时钟测试不能替代实时验收。

有活动但没有转写文字的后继段，同样在新鲜持续 quiet 后请求真实收尾，不能因缺少文字而永远没有定稿事件。空段只有通过相同 finalizer/结果排空屏障，才发送绑定 Analyzer 代次与最后已交付活动序号的 `audioFinal`。host 仅在已有已过滤确认文本、没有新 partial、证明恰好覆盖首个未确认音频来源及当前 quiet 观察时解除等待；后代空段不能覆盖前代被身份或回声过滤拒绝的非空段。它不创建文字、改变主人认证或复活已取消轮次。新活动仍关门，旧代、旧序号、unknown、定稿失败均不能代替覆盖；纯静默没有活动时不反复创建空段。空段事件接入普通链与私有诊断链。

已定稿轮次在原有短安静窗口内等待后继音频覆盖时，可复用 checkpoint 请求该精确来源排空，避免被 native 普通句段较长的停顿阈值拖住。native 重新核验本代确实投喂、有活动历史且此刻 fresh quiet，仍走真实 finalizer/drain。连续同一安静窗口只请求一次；错过窗口后可在新的安静窗口重试，不刷新八秒确认或效果等待截止。active、unknown、过期安静、未投喂及错误来源均不得以此产生覆盖；原有提交门及序号核对保持统一。

原生活动元数据在普通和诊断链中统一传至 `VoiceTurns`，只含三态、quiet 时长、观察/发送 uptime、代次与递增序号。host 转换时钟并拒绝旧序号、跨代倒退和过期证据。普通聆听以新鲜 quiet 满 600ms 为声学收口条件；原生 finalizer 和结果流排空确认后立即发起语义解释，不从最终文字回调再等待一段时间。暂定文字立即展示，真实新识别文字同步中断未完成回应。已定稿轮次等待后继音频覆盖时仍使用精确来源和有界确认，只有文字而 VAD 未判有声的片段也可依安静条件收尾。声学故障、finalizer 及系统识别耗时会影响实际端到端延迟；纯静默不创建对话。

原生层对所有非空定稿文本给出一致收尾，主机不按字数或词数决定是否回应，短回答与长句同样交给 Bunny 判断；不能出现已上报半句而永远不发对应定稿的悬空状态。纯空白可直接退休。未定稿文字临近原确认截止时，主机可针对当前识别器与来源代次请求一次 checkpoint，预留原生有界收尾时间；它不刷新文字确认期限、不增加权限，也不替代真实静音或提交许可；真实定稿后才进入独立的一次性声学等待阶段。原生只排空已接收音频，后续 PCM 按序进入下一代；真实续说继续修订或取消旧意图，关耳、停止与旧代请求不能复活输入。独立完整的安静指令可走本地快速控制，包含后续问题或新目标的混合话语交原对话理解路径，不能因局部“别讲”等词吞掉后半请求。

接纳后的语义有效性与副作用提交许可分开：`isCurrent()` 核对轮次、取消及代次；`canCommit()` 和 `waitForCommit()` 核对实时声学提交门。新识别或新对话中断旧推理，未完成输入按来源和原有顺序纳入新一轮；旧回包不能展示、朗读或启动新效果。已发生或结果未知的外部效果不能被取消当作未发生，也不能盲目重放。ASR 候选仍以 `microphone-observation` 进入模型，附带同音或近音误识别提示、语义、两轮交流间隔及实际播放线索；未接纳候选不写成主人历史。判断不是对 Bunny 说话时返回空内容，不展示、不朗读、不交办；空决定与模型错误区分。时间和回声匹配均为线索，不能保证语义判断绝对正确。

有音频来源的定稿以 `recognizer/sourceGen` 区分句段。新来源即使文字相同也保留为新一段并重新计算封口；同来源重复只作幂等回执，不能清除后来音频的未确认屏障；已收尾来源的水位在轮次退休或重置后仍保留，迟到定稿不能复活为新交办。识别器停止或换代同时退休 current 与 retained 的待提交输入，忽略后继候选不会让保留输入逃过识别器生命周期。兼容旧识别器的无来源 final 契约；未调整 AEC、VAD、600ms 静音、60ms 直接活动或 finalizer/drain 基线。

外部会话在实际观察并登记同一会话的新消息后，取消尚未进入写入效果边界的旧判断，把未完成的原始消息按顺序合并；各批次保留各自来源回执与认证版本，不把旧批次的权限扩展到新批次。已经进入保护区或已提交的发送继续沿效果账本核对，不盲目重放。未被现有观察机制发现的消息无法提前触发取消。

普通非敏感对话在已获语义接纳且 `isCurrent()` 时可保存已确认会话、展示正文及朗读，不让无新文字的背景 active/unknown 丢弃已算好的答复；`rememberConversation()` 只记录本轮已确认原文，不授予 Task 或显式记忆修改许可。Task 接纳、显式记忆/自我修改及敏感输出仍在各自效果边界等待并重核提交门；首次实际 `waitForCommit()` 遇到声学关门后独立计八秒，不重新套用旧文字确认截止，也不被反复活动续期。前轮等待新候选语义解释时暂停该声学计时，语义等待复用该候选已有的主脑总截止；候选退休后恢复剩余声学预算，不能把模型等待误报为音频未确认。只有环境活动、没有操作等待时不启动提交超时。等待不占用全局 Task 接纳或写入队列。已进入持久写入的事实如实保留，未通过最终许可的任务不能启动或在重启后自动执行。最终回复或控制效果提交后退休本次输入，清除其等待器及计时器，不中止已经接纳的 Task 或朗读队列；后来的环境活动不对已结束输入再次报超时。门超时则取消旧结果，日志区分“输入尚未确认”和“前句已确认、后续证据仍不明确”；普通未确认候选静默丢弃，仅已被语义接纳且实际等待操作提交时提示未执行，可重说或输入文字。普通聆听沿识别失败的有上限退避策略恢复，迟到回调不复活旧意图。退出、手动关闭、场景/资料代次变化、锁屏及隔离诊断期间不由该回调重新采集。VAD 可误报，短诊断也可能先于提交等待期限结束；离线验证不能替代真实普通对话及实际回复验收。

聆听栏只使用 `VoiceTurns` 认可的实时文字；`asrLive/heard` 携带同一轮次序号及 partial/final/pending/reset/completed 生命周期，不再同时推送一份原始 partial。新轮次、重置、跳过、错误及完成清理临时文字和待填输入；旧轮次回执与旧消失计时器不能覆盖新轮次，相同文字也不作为轮次身份。实时识别时增量显示文字，不加“你说”前缀；定稿后仅“正在回应”显示用户刚才的内容，“正在转语音/正在说话”只显示状态，完成或略过恢复“在听”。离线 UI 回归不证明扬声器已实际出声。

前台模型启动即进入“正在回应”，持续到模型结束或当前TTS启动；首句播完但模型仍生成时恢复回应状态。聆听栏新文字同步取消旧滚动动画并复位文字位置，不等待宽度过渡才显示；音频上下文恢复的迟到失败按播放代次丢弃。`reply-stream.js` 只抽取已确定为 chat 的正文增量，排除 review/prediction、工具数据、skip/action和控制标签；每次出口重核取消与轮次归属，首个自然句进入既有TTS队列，最终正文不重复朗读。正文已播放而尾部协议失败时停止并保留未完成状态，不能记完整成功。敏感上下文沿整包保护边界。WorkBuddy 5.9.3 的本地 `http.fetch` 先完整读取响应再返回 `body_b64`，因此该连接仍受上游整包延迟限制；直接SSE模型连接可真正增量输出，不用打字机动画冒充流式。

普通日志保留接纳、提交门关闭/恢复、取消原因、模型开始/结束/取消及 Task 接纳等必要数值阶段；固定原因码区分文字修订、重置、识别器变化、输入确认超时、提交超时、有声、unknown 和过期，并带活动年龄/序号/来源代次及等待时长。`--speech-trace` 启用更详细的可选数值诊断，默认关闭，不改识别、分段、声道映射或门限。两者均只接收固定阶段、有限数值及布尔白名单，不记录正文、PCM、设备 UID 或凭据；只能辅助定位，不能独自解释缺字。原生字数按 Swift 字符、主进程按 UTF-16 长度计，非 BMP 字符时不能直接比较数值。

设置 → 听力 → 本机语音诊断提供独立的本地入口，默认关闭；处理后音频另行勾选。开始前暂停并丢弃普通识别器、重置普通轮次并封住自动重启。诊断识别器只绑定私有接收端，沿用同一过滤模块和私有 `VoiceTurns`，其原文、合并文本和请求仅写私有文件，不连接对话、历史、模型、Task 或朗读回调。输入确认或接纳后提交等待超时会记录 `host-turn-unconfirmed` 的不同原因，并以 `voice-unconfirmed` 结束私有采集，不在隔离测试中重启识别器。结束后普通聆听仍关闭，须主人重新开启；换设置、锁屏、来源变动及退出会停止诊断。当前入口仅支持 macOS 26 连续识别，且不请求新权限或下载语言资源。

host 与原生各有独立最长 20 秒截止。原生保存现有转换和 mute 之后实际 `toSend` 的 PCM；每 buffer/plane 有序号、帧偏移、原格式及文件偏移，direct/queued/replay 关联真实 yield 结果。`enqueued` 仅证明生产端队列接纳，不证明 Analyzer 已消费；成功完整 finalizer 的 API 契约可进一步支持该代输入已消费，不能外推到未收尾的尾代。私有事件还记录原生原始结果、range/定稿水位、合并文本、收尾原因及活动三态，以及 host 原始接收、过滤、合并和最终接收端。native uptime/wall 与 host wall/monotonic 锚点、识别器/代次/turn 用于对齐。host journal 自主管理 `seq/wallMs/monoNs`，原生活动序号另存 `activitySeq`，观察元数据不能覆盖本地序号或时钟。emit 时刻的 `diagnosticGen` 是当前代次快照，原生 result 的精确归属以 `raw-result.gen` 为准；新包的 partial/utterance 另带 `diagnosticSourceGen`，避免将 emit 后的当前代次误当文字来源。

文件只在应用用户目录的 `speech-diagnostics/speech-<UUID>/` 中创建：目录 0700、文件 0600，拒绝符号链接和覆盖。PCM 最多 32MiB、原生事件最多 2MiB、host 事件最多 2MiB；原生异步待写队列 1MiB，host 256KiB，最多保留 8 次诊断，满额拒绝新采集。音频回调不写磁盘，超限、写失败与超时留下可识别的不完整证据。正常 `buddy.log` 不记录诊断原文或 PCM。独立原生硬截止不等候 Analyzer 或磁盘锁；文件排空另有有界等待，退出、缺少结束事件或排空失败不能冒充完整捕获。

单次受控操作：先保持原麦克风、扬声器、位置、音量、AEC、声道和阈值；待对话/朗读结束并解锁记忆。在上述入口勾选保存音频，点击开始；仅当显示隔离采集且剩余至少 17 秒时，先静音 2 秒、播放一次约 9 秒已知短文、再静音 5 秒，不补词、不手改转写。若准备后时间不足，停止且不播放，保留启动耗时证据。结束后点击打开本次文件夹：先核对 `manifest.json` 中原因、`nativeExitCode`、journal 的 drained/failure，再看 `native-events.ndjson` 的 `diagnostic-end.reasonCode/overflows`，确认无超限或缺尾；按 seq/代次与 `host-events.ndjson` 对齐。PCM 是按 plane 保存的原格式字节，读取时必须使用 `audio-buffer` 的 format/planes 元数据，不能猜声道或直接当 WAV。外部录音只作源音背景，不能替代该处理后 PCM。核对后点击清理本次诊断，只删除该次私有文件及 Finder 目录元数据；需要恢复时点击重新开启聆听。重启后遗留的旧诊断可在上述目录按 UUID 手动核对清理。

来源不证明可靠度、身份或操作成功，不捏造全局正确率。`reviewEvidence/evidence.assess` 提供按需解释与补证，正常低风险判断直接使用已有信息。新增感知器沿用工具权限、取消、来源和预算，不另建任务轮询器。

## 8. 记忆与统一经验仓库

`MemoryService` 管理同一加密 Vault，`VaultDB` 通过 Swift 访问 SQLite；正文加密、检索 token 使用 HMAC。记忆记录带来源、场景、可见范围、版本及状态；自我理解使用自己的修订与锁定机制。钥匙串辅助程序保持签名身份和真实父进程核验。

任务保存由 Vault 写入层一次读取并核实来源的存在、活跃状态与可见范围。任务恢复通过当前任务索引分页读取正文，响应按最大记录体积限页。Operation 检查点经任务视图推送，减少对话历史和记忆面板的重复刷新。

Doze 按渠道和场景压缩。统一 `MemoryMaintenance` 负责 Dream/Deepdream 的预算、排队、取消与增量处理，轮流处理对话、任务结果和经验来源，避免某类积压永久饿死其它来源。显式资源导入可以只整理该来源，不强行处理私聊历史。

语义计划缓存先验证结构、消费边界和调用方领域约束，再接纳结果。Doze 的逐字引文校验在缓存写入之前执行；读取旧缓存也重验，无效则重新生成，通过后替换同一缓存，不推进原消息或摘要水位。引文缺源与不匹配分别使用固定错误码；不放宽引文规则、不记录正文。失败后可重新生成、成功后复用由离线测试覆盖，现场是否曾命中旧错误缓存未确认。

`ExperienceRepository` 使用 `bunny.experience/v1` 的 head、revision、alias、pack 和 tool 等记录，不增加第二个数据库。索引只找当前 head，正文按需读取；来源与实际有效性分别记录。`AgentLearning`、任务结果、主人传授及导入包接入习得仓库；随包先天指南使用独立只读命名空间，由相同上下文检索入口按需合入。旧验收记录只作为证据来源。

精确去重先由内容及条件指纹完成；相似、冲突、过时和失效由 Bunny 参考有限相关候选判断。提交前检查来源快照、当前 head 与 Vault 代次，迟到模型不能覆盖新修订。合并保留来源和工具引用；旧修订回收保留最近版本及仍被任务/证据引用的版本。工具快照当前保留，不宣称已具备完整垃圾回收器。

任务结果反馈只保存有界统计和必要证据，不每次使用都复制正文，也不按固定次数改变有效性。私聊和受保护的任务内容不提炼为通用经验；Task 检索最高生活，并排除由本 Task 自己派生的经验作为自证。

检索排除沿真实来源边传递到全部祖先，候选共享按场景读取的有界缓存；缺源、不可读、过期、未提交资源包、循环或超出预算的链不进入结果。既有任务证明和工具证明沿用原有效性校验，直接与深层来源按证明 ID 共用结果，最多检查 32 个证明，累计等待上限 4 秒；证明校验内部读取与来源图读取预算分别约束。返回的可用性区分完整、部分可用和不可用，已独立证明安全的候选可保留。旧来源边完整保留，Vault 写入仍执行最终来源与无环校验。临时 Vault 已验证多跳排除及拒写；这不证明某次现场 `invalid_source` 的具体来源边。

`AgentLearning.prepare` 在任务快照上形成独立经验补丁，不改运行中的任务或经验目录。初次接纳在私有候选上应用后保存；恢复或开关变更通过运行时的有序事务先保存、成功后只合入经验字段和新增来源。任务控制、目标、场景、资料代次或更新的准备请求变化时丢弃旧结果，保存失败保留原任务，既不删旧证据，也不回滚覆盖新的停止请求。

## 9. 可导入记忆经验包规范与吸收接口

当前推荐格式为 `bunny.memory-pack/v1`。它描述资料来源与资源完整性，不要求用户或作者把内容预先分类为记忆、经验、工具。ZIP 与文件夹是同一契约；普通文件夹或无清单 ZIP 也可导入，由 Bunny 分析内容。旧版 `bunny.experience-pack/v1` 的正文和工具声明保留兼容，但面板与 `experience.import` 的公开入口都先进入同一吸收流程，不将原条目直接当成可信经验。

### 9.1 目录与清单

```text
manifest.json             # 可选，建议分发资料包时提供
README.md                 # 建议说明来源、目标、范围、已知限制
notes/*                   # 任意目录名；事实、说明、经验可以混排
scripts/* 或 tools/*      # 可选配套代码，目录名不决定是否执行
resources/*               # 可选辅助资料
```

可直接导入的完整示例是 [`examples/memory-pack`](../examples/memory-pack/)。清单省略时，包身份取资料内容与相对路径的整体哈希；不依据本机绝对路径或 ZIP 外层文件夹命名去重。

清单字段：

| 字段 | 约束与含义 |
| --- | --- |
| `schema` | 固定 `bunny.memory-pack/v1`；已声明的版本必须受支持 |
| `id`, `version`, `title` | 可选稳定来源标识、来源版本、显示名称；不是安装权限或先天经验身份 |
| `author`, `description` | 可选来源说明；包内作者或示例人物不是本机主人 |
| `scope` | 可选 `work/life/private`；只能收紧当前导入场景，不能降低可见限制 |
| `resources` | 可选资源数组，每项 `{path, bytes, sha256}`；已声明项必须逐字节匹配。可省略整个列表，宿主仍计算所有文件哈希；额外普通文件仍作为资料分析 |
| `tools` | 可选工具接口提示数组，最多64项；声明不代表可信、已启用或允许执行。未声明代码可由 Bunny 根据完整静态内容识别工具 |

路径只使用包内相对路径，不能绝对路径、越界、反斜线、控制字符、链接或大小写/规范化重名。ZIP 必须是普通单卷 stored/deflated 格式，逐项校验 CRC、目录及实际解压大小，不直接解压到用户路径。上限：ZIP64MiB、普通单文件16MiB、总资源128MiB、512项；超限或结构无法安全解析时拒绝整包并说明原因。macOS 元数据被忽略。

当前自动读取 UTF-8 的 MD、TXT、JSON/JSONL、YAML、CSV/TSV、LOG、HTML、CSS、XML、TOML、INI、RST；代码按静态文本分析。二进制、PDF/Office、图片及嵌套压缩包当前不自动解析，列入未吸收报告，不假装已读。每包最多分析2MiB普通文本；正文按12000字符切块、每次最多4块/24000字符。需要完整审查的工具组最多24000字符，无法完整查看其依赖时不登记工具。

### 9.2 工具提示

每项工具接口支持 `id/title/entry/runtime/interfaceVersion/inputSchema/outputSchema/effect/capabilities/dependencies/resources`，语义延续旧经验工具库。`entry` 和 `resources` 都是包内真实资源；接口为有界 JSON Schema，`effect` 必须是 `read` 或 `write`。运行方式当前接受 `node/python3/python/sh/bash/zsh/pwsh`。代码与依赖被完整读取、静态审查接受且接口/资源校验通过后，才进入现有不可变工具快照库；未审查通过的工具不进入可用索引。

导入始终不执行代码、安装依赖、执行安装钩子或扩大任务能力。工具报告标明“静态审查，未运行验证”；后续实际使用仍由原任务授权、终端和结果核验机制负责。改进工具另建内容快照，不改写正在使用的代码。

### 9.3 吸收、合并与安全

`MemoryImportRepository` 在原加密 Vault 内保存批次、不可变来源块、游标和实际结果，不增加第二个数据库。`MemoryMaintenance` 的 Dream 队列负责预算、取消、调度和重试，用户导入是明确请求，不依赖自动提炼聊天的开关，也不强迫分析无关私聊历史。重启或恢复备份后重建待处理队列；不完整接收单独报告，重新选择同一资料可接续。

每批由 Bunny 读取资料、相关记忆与经验、只读先天参考，自主选择提取、合并或忽略。候选不足时可先要求一次短词检索再继续。记忆附原文证据，保存为带来源的资料说法，不伪造主人对话或确认个人事实；相关时进入对话参考上下文，明确区分资料作者与本机主人，不要求二次确认。相同记忆可复用。经验通过现有 head/revision/alias 仓库合并，保留条件、工具引用、来源和旧修订。已删除或失效内容不因重导同样内容而复活。先天区不接受导入、合并、覆盖或删除。

宿主在送模型前排除具体凭据及受保护内容，包内角色、身份与权限声明都是资料，不获得指令地位。LLM 根据最高原则判断并排除风险片段；宿主还检查输出的证据归属、目标范围、明显越权要求、敏感内容和工具真实资源。普通版本/条件差异由 Bunny 判断兼容关系，不简单当作安全冲突。能独立保留的安全内容继续吸收；拿不准的代码不登记，并说明原因。不能据此宣称静态分析能证明任意代码绝对安全。

模型读取在串行写入区之外，提交前重读原始数据库快照和当前代次；迟到结果不能覆盖已变化的资料。结果及游标在同一次 Vault 写入中提交；取消、网络失败和预算等待保留进度，不产生重复副作用。来源块通过来源图继承场景与可见范围，私聊资料不转为任务经验或通用工具。

### 9.4 用户入口与报告

面板只提供选择 ZIP/文件夹，不选择目标类别、不增加吸收审批。`pet:experience-import` 返回已接收的 `importId`，不冒充已完成吸收；`pet:memory-import-status` 返回当前场景可见的实际进度和持久报告，重新打开面板可继续查看。`experience.import_status` 仅允许任务查询属于自己的导入批次。

报告由实际提交的记录生成：新增记忆、经验、合并与复用数量、登记工具及其验证状态、忽略文件/片段及原因。凭据和风险指令原文不回显。输入结构错误、暂时模型不可用、不支持类型和安全风险分别说明；等待重试或预算不说成已完成。只读先天经验在独立页签展示，导入资料与它分离。

旧 `ExperienceRepository` 的内容登记与资源快照原语继续供内部整理及兼容使用；公开吸收入口统一经过上述来源分析。加密备份携带批次、进度、来源与工具资源，恢复后核对资源并恢复未完处理。

## 10. 外部应用、角色与持久资料

微信适配器负责可见窗口与对话定位、新消息游标、语音线索和证据；通用视觉 Action 负责实际操作、判断、等待与恢复。禁止微信 API、辅助功能控制树、内部数据库或协议，也不自动退出、重启或登录微信。窗口或登录异常保留现场并说明。

微信会话代管在打开、转写、另存和回复时携带当前渠道快照。宿主限制允许的界面操作，在键鼠发出前检查权限、窗口和视觉目标。右键菜单项绑定到本次操作打开的微信弹出窗口，附件只保存到独立接收目录并核对文件回执。来自认证渠道的交办绑定实际新消息，通用微信输入再次核对该授权。界面证据与行为由离线夹具覆盖，真实微信的菜单识别仍需独立验收。

WorkBuddy 使用已绑定会话监控、允许的应用适配与通用桌面操作。制作条件、原始请求及最终交付分别保存；`collectDeliveryEvidence` 提供实际文件与读取缺口，`verifyDelivery` 由 Bunny 决定完成、修订或需要主人。文件变化是证据失效，重新读取，不由文件类型推测直接否决业务结果。

Task 验收依据实际执行报告重新检索适用经验，保留场景、软件范围、先天经验开关与本任务排除项；检索有界且可取消，不触发经验安装或写入。宿主将同一 Task 的主人请求、持续授权上下文、范围约束及已核对来源交给验收；来源有效不等于新增副作用许可，经验也不能授予权限。验收前后核对经验版本、当前头、父来源和本轮会话身份，修订保存后再次核对，避免迟到结果继续验收或发送。新增上下文在模型边界使用现有敏感值保护，私有原文保持原样。提交结果未知时，任务摘要优先保留该事实，最近一次恢复的前置拒绝不覆盖原提交屏障。以上链路由离线夹具覆盖，网页公开可访问性及实机控制效果仍需对应现场证据。

新任务交办先识别当前是否位于 Buddy 应用，若是则切回通用任务页，再检查通用编辑器的草稿与工作位置，避免把应用提示文字或独立草稿误认为通用任务的阻塞。通用编辑器确有未发送内容时，在新建任务动作前保留草稿，返回 `E_WORKBUDDY_DRAFT_CONFLICT` 并显示可处理的任务状态，不反复重试或清空内容。应用切换、通用首页和工作位置均须经当前窗口复查。

工作空间控件按真实窗口内唯一编辑器及其左下方弹出控件的相对位置识别，适配缩窗及侧栏状态，不能使用窗口横向百分比推定。检查回传编辑器、弹出控件和候选数量；多候选、缺失、菜单未关闭或非通用页均不视为位置已核实。前后台共用同一核查依据；视觉输入路径保留 `E_WORKBUDDY_ROUTE_UNVERIFIED` 及结构诊断。制作模板只说明本轮工作与交付分工，不自动加入微信会话、收件人或聊天操作授权。

首次交办、主人续办与自动修订的最终正文统一由 `work-order.workMessage` 组合；阶段只追加续办语义，不各自拼接通讯软件规则。原始正文不按敏感词删除，交付渠道资料不自动转成执行方操作指令。本轮身份与已有会话绑定分别核对：`workSubmissionConfirmed` 排除沿用的旧轮次、待核实草稿、未观察到的新提交和旧消息回执。点击回执只表明输入动作发出；主人续办须等本轮新消息被观察后才确认 `work.submit`，等待期间展示“核对交办结果”。只读恢复可以用同一新消息回执完成核对，未知提交不重放，也不拿旧答复验收。

解释器把 WorkBuddy 作为默认执行渠道，并将相关路由经验交给 Bunny 判断；当前上下文或可靠先天/习得经验可以支持其他方法，不按软件名称关键词强制路由。路由阶段只提供默认渠道指南和与目标相关的习得依据；选定渠道后，经验装配及上下文选择均依据 `application` 和 `software:*` 标签筛选，跨软件经验需其软件范围均在当前执行上下文中，避免标签经验绕过场景隔离。网页作品的公开链接交付偏好与授权边界属于随包可修订经验，由 Bunny 写入工作目标与核查条件，不由代码按某个小游戏硬编码发布。

`interaction-policy.js` 按软件先天清单定义允许模式，Task 和 ToolRegistry 规范化已登记别名，每次 Operation 在实际执行前复核目标与模式。Task 表达语义目标并可跨软件；Action 可组合不同通道，不持有全任务单模式。先检索适用经验，失效后分析原因再调整；没有经验时自主选择合适的服务、终端/代码或结构化界面，其它允许方法不适用才视觉兜底。微信直接操作只授权视觉键鼠，关闭先天检索不解除该边界。明确软件启动器、应用包、协议和接口命令目标也按相同软件规则校验；不将所有 system 操作整任务禁用，也不把这一直接调度约束扩展到独立受托应用内部。

`software.service` 只接受宿主预注册的固定软件、固定方法及独立授权回调，有取消、超时和真实回执；默认未注册生产提供者时不会出现在工具目录，不开放任意 URL 或任意网络代理。`software.inspect/command/interface/control/recover` 保留独立安装发现、终端和结构化能力。WorkBuddy 前台/后台结构化交办独立核对新鲜目标、完整草稿和指针；这些能力无需视觉模型作为底层。明确未派发且方法不适用时才转视觉，未知输入与提交仍保留阶段屏障。

`VisualSession` 是所有软件共用的操作层视觉机制：`displayCapture` 仅从 CGDisplayStream 取得普通显示像素；旧窗口截图与窗口视觉采样入口明确停用，采集失败不得回退 AV、ScreenCaptureKit 或窗口接口；截图与视觉模型识别软件、身份锚点、主区域、监测区域及可见焦点，局部图像按像素裁剪。`displayInput` 仅接受新鲜显示/视觉区域证据及全局键鼠，原生入口拒应用、PID、窗口与 UI 参数；视觉采集超时只重建显示连接并重试原显示请求，不回落窗口采集、不重放输入。任务、会话、主动观察、screen.watch、追问与草稿恢复共用该机制；旧 `ocr` 字段只是兼容的 VLM 可见文字集合，实际来源标为 `display.vision`，不调用原生 OCR 或模板作必需语义路径。

采集、定位、观察、稳定采样、视觉判断和输入预检在异步返回后核对发起时的视觉 session；重置后的旧成功不能建立新身份，旧失败也不能清空新帧。最后派发点再次核对会话与帧；已发出的输入仍返回真实回执，但标记 `cancelledAfterDispatch`，不再修改新会话的焦点或输入依据。微信共享观察另有缓存代次：失效、重连、关闭或安全停发会分离旧 inflight；新观察可独立开始，旧结果不能回填缓存、提交采样基线或触发当前账户的安全判断。截图后端和视觉定位方法保持原有实现。

健康与身份核对可以只读观察可见但未激活的目标，不因此放行输入。拥有 GUI 的执行入口与 `screen.activate` 共用 `VisualSession.activate`：只点击当前视觉明确标出的安全激活区域，并用新画面重新确认；普通截图不触发激活。激活后观察失败保留原诊断与实际输入回执，安全提示可上送共享场景；已确认或结果未知的激活默认只读补证，不自动重复点击。任务可用 `screen.activate retry=true` 显式重选；固定桌面入口消费任务脑或主脑现有的新策略指导。两者均须输入回执后的新鲜同身份画面确认未激活和安全区域，同一Operation或指导只重选一次，不能越过需要主人处理的提示。控件拒绝沿现有 `candidateCount/guardChecks` 记录无正文的命中数与几何、帧归属检查，供下轮区分漏识别、区域不一致和歧义。

未取得安全激活区域时本次不发输入，并将该视觉判断标为需重新定位；下一次由既有有界恢复调度发起的尝试须取得新判断。不能因像素未变而永久复用导致失败的负面判断；重新定位保留会话身份、既有输入回执和登录／安全边界。此路径已离线验证，真实桌面效果需随实操单独核验。

定位模型的全部几何字段（包括 `texts`）统一使用第一张完整显示图的归一化坐标，文字框与身份、主区域、监测区域一样严格位于目标 `region` 内。宿主裁图时统一换算为目标图坐标；模型不同时承担整图与局部两套参照。几何校验失败按具体字段、预期关系与实际类型记录，并在同帧有界修正中指出坐标合同，不误记为 JSON 语法错误。

目标、主区域与身份锚点严格校验；辅助观察统一逐项筛选，记录脱敏字段原因及保留、丢弃数量，不裁剪或替换坏框。监测区域至少保留一个原始合法项，否则拒绝定位；可选粗文字坏行不进入guard，失效的焦点或激活框连同对应依据清空，只读观察可继续，真正需要对应输入前提时仍明确拒绝或补证。字面补证直接使用 `checkedJSON` 的抄录协议与原有30秒有界等待，不套用语义复核的摘要提示。

全屏粗识别漏掉关键标签或与控件区域不一致时，可通过通用 `VisualSession.readTextRegion` 对保留的同一 CG 像素帧按需裁图补证；不另取全屏、不提供期望标签诱导抄录，也不派发输入。宿主按实际整数裁图边界回投文字坐标，并绑定帧、身份、覆盖区域及完整性。桌面 guard 最多补证一次，使用原有的完整唯一性核查范围替换粗文字后重新执行精确标签、控件区域与同名检查；不能只识别已选小框而忽略范围内其它同名目标，迟到、错帧、不完整或部分覆盖的结果不能放行。

关键标签补证另提供已确认控件的 `focusRegion`：同一请求带完整唯一性范围图和焦点控件图，先独立读取焦点主标签，再只列范围内所有同文标签及坐标，不抄其它预览和时间。坐标始终相对第一张范围图，输出默认1024 tokens并复用既有受控恢复；完整结果须包含焦点内匹配，原guard继续逐字比对目标并检查全部同名。未指定焦点时仍可显式进行通用字面读取。

视觉会话与每软件目标分别保存随机身份令牌和有界帧；移动或显示几何变化重新视觉识别，旧输入证据不静默继承。身份须由前后实际画面确认，不靠身份小图 SHA 全等或未经校准的固定 confidence 门槛。局部监测按 VLM 选定区域比较像素和稳定性，细小标记不被整屏比例稀释，输入光标等无关动态不构成事件；输入前仅检查身份与实际动作相关锚点。无可见焦点依据时说明无法确认，不查询前台。发现安全/登录提示、遮挡或歧义即停止。取消前不派发，取消后的真实输入回执仍保留。观察失败不把已发输入变成未派发，提交只进行一次。

`experience.review` 使用本任务真实回执排除不适用方法，Dream 仍是统一学习入口。首次操作前准备的经验进入真实 planner payload；跨来源的完整段落先按本轮目标/失败上下文排序，再应用来源数与 token 预算，避免长首节占满及标题/单字残片。确认成功或明确失败才形成方法经验，输入回执或未知效果不能记成功；账号、聊天正文和坐标不成为通用经验。

`InnateExperienceRepository` 在加密 Vault 内使用独立 `innate:*` 命名空间与当前版本索引。安装时记录只读版本的包/条目内容摘要清单；习得经验的祖先链只有完整匹配本地安装来源才接受先天包，伪造 origin/type、篡改或缺失来源仍拒绝，未 committed 的导入包不被放宽。关闭先天检索不使已验证的习得经验历史来源失效。启动时依据校验过的随包指南直接安装，无需模型或先创建任务；升级先写入不可变版本，再切换当前索引，保留旧任务证据引用。旧版混存的随包条目迁出活动习得池；用户经验、导入包和私有资料不被替换。记忆面板只读展示先天区并提供参考开关；任务上下文及经验检索遵循开关，微信权限边界始终独立生效。外部资料先进入持久吸收队列，经 Dream 分析后写入习得/导入经验库；历史 `pending_review` 条目继续由兼容整理流程处理。

常驻关注和委派跟进复用一个 WorkBuddy 会话监控器。目录枚举和增量文件读取异步执行，单次扫描按批限制 I/O。候选答复需等待读到日志尾部且当前行完整，随后按既有静默规则判断交付。

角色与表现属于 UI。VRM/VRMA 保持现有资源库；数据形象包 `.wbavatar` 使用 `workbunny.avatar-pack` v1，清单、角色、动作、图、交互及资源整体校验与替换。包不执行脚本、着色器或网络代码；`declarative-3d-v1` 与 `soft-surface-v1` 声明实际宿主能力。具体字段以 [`avatar-pack-manifest.js`](../src/main/avatar-pack-manifest.js)、[`avatar-pack-reader.js`](../src/main/avatar-pack-reader.js) 及相关 Schema 为准。形象包与经验工具包的执行能力不同，不能混用。

角色加载完成后统一替换当前场景，并释放原有几何、纹理、材质和骨骼资源。VRMA 按需绑定到当前骨骼，保留动作原始数据复用。角色或窗口隐藏时暂停 WebGL 绘制，语音播放和动作状态继续运行。

内置芭尼在挂载前校验弹簧关节并应用已确认的头发和身体弹性设置；限制旋转时同步修正 Verlet 尾部状态，耳朵及个人导入模型不应用该配置。循环动作的跨边界脚掌接触仅在原始端点足够接近时共享锚点；锁脚引入原动作没有的急转时，整条腿保留原始轨道，避免局部回退形成新的接缝。七个内置形象的可编辑描述进入身体上下文，兔兔按实际配色动态附加主体颜色。

模型请求支持 WorkBuddy 及已配置的直接 API，使用同一对话协议、上下文预算、取消与来源规则；工具调用循环和真实模型传输分离。模型目录提供实际可用性与能力，后台免费调用的选择不自动扩大到付费模型。执行器使用哪种模型、校验使用哪种模型分别记录，避免将校验回退说成更换了正式执行模型。

桌面规划的模型预检将本次实际目录响应中的容量绑定到当前任务、执行代次和模型，供同一次规划预算使用，不依赖异步目录缓存，也不沿用旧任务保存的容量。预检成功记录实际模型容量与代次；规划的成功与预算拒绝都记录输入、文本与图片估算等数字诊断，不记录正文或图片；输入预算不足不会被归咎于主人话语过长。字符、UTF-8字节和token不是同一单位：当前没有匹配模型词表与聊天模板时，统一估算器分别处理中英文本、代码/符号、不透明串及独立图片块，不能称为精确token计数；每图16384是保守估算，Base64传输体积不按文字重复计费。协议/工具schema也计入输入，另预留误差与输出，真实超限仍保留原文并拒绝。输入、提交不确定时仍只核对原副作用。

两个模型入口共享响应解析和工具调用校验。直接 API 使用整个请求的绝对时限与响应大小上限，WorkBuddy 在本地代理完成身份握手后才发请求。桌面、Vault、ASR 和本地代理共享有字节上限的 JSONL 组帧器，完整行只合并一次。

`checkedJSON` 可归一化模型在唯一完整对象或数组前后的说明文字：按字符串、转义和嵌套边界定位，再通过严格 JSON 与原类型校验；多个候选、独立标量或字符串值、重复字段、截断和类型不符仍拒绝。附文中的普通数字与引号不自动构成另一个值，但整行只有 JSON 值时保守拒绝。附文不参与动作或授权，只记录格式偏差及丢弃字符数；校验失败的有界修正带回原拒绝答案，后续超时仍保留先前的脱敏协议诊断。

语音采集由原生 ASR 辅助程序负责，端侧持续识别与旧系统分段识别走同一轮次/取消机制；文字与语音均进入基础对话。TTS 会话管理合成、播放结束、打断与角色表现，支持系统、本地和远程引擎；播放失败不能用生成了文件冒充实际朗读。每句朗读使用独立代次与取消信号，合成超时、旧流回调和播放结束均不能影响下一句或改写当前引擎配置。 首个完整自然句单独入队，后文仍按原较长块合并并由既有队列预取；首句无需等后文合成完成，插话沿原取消与回声窗口处理，不另建播放状态。ASR 授权成功不等于采集已就绪，采集启动仍有25秒截止。主人声音筛选只提供本机声学近似，不参与主人身份认证。HTTP 语音配置是受限数据模板，示例在 [`examples/tts-profiles`](../examples/tts-profiles/)，不执行配置中的代码。

`bounded-wait` 对调用方提供取消和总截止，不用超时放行仍在变更数据的串行写区。对话的本地读取单项最多8秒，整轮按模型预算另加15秒准备时间；新语音取消旧轮后可释放旧 `busy`。明确本地停止、暂停和状态走既有 Task 权限入口，优先于角色与记忆准备；语音仍须提交确认，新执行或继续仍须真实交办来源。模型回复的总截止也覆盖忽略取消的本地回忆工具。经验文件证据在串行区外以15秒总时限准备，进入写区后重核来源和代次。迟到只读结果不能续发动作或提交经验；取消无法撤销已发出的写入，主线程同步阻塞或操作系统冻结不属于定时器隔离保证。

[`CompanionAutonomy`](../src/main/companion-autonomy.js) 仍负责自主生活的授权、安静时段、预算与活动选择，部分本地创作经 Secretary 执行。这与任务保活、Doze/Dream 和模型请求超时不同，也尚未全部迁为普通 AgentRuntime Task；后续统一需保留授权、资料范围与结果回执，不能仅凭总体框图宣布迁移完成。

正式资料默认在 `~/Library/Application Support/workbunny`，开发资料在 `.data/dev`。数据库迁移核对密文和完整性后原子切换指针；外置资料盘失联进入恢复，不自动创建空库。跨机器使用加密备份恢复，本机封装文件不能代替密码备份。

### 本机 MCP 控制（开发接口）

公开控制入口采用官方 `@modelcontextprotocol/sdk` 1.32.2 的 stdio Server，使用带 `initialize` 协商的 MCP `2025-11-25` profile；当前不实现 `2026-07-28` stateless profile。`tools/bunny-mcp.cjs` 处理协议与能力协商，`tools/bunnyctl.cjs` 使用同一官方 SDK Client 调用它。协议依据：[生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)、[工具与结构化结果](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。

真实主进程的 `local-control.js` 统一注册工具名、JSON Schema、参数检查和操作处理函数，桥接 `tools/list`、`tools/call`，结果使用 `structuredContent`、兼容文字块和 `isError`。当前开放 `scene_get`、`scene_set`、`boper_status`、`boper_enable`、`boper_disable`、`boper_refresh`、`boper_settings`、`boper_permissions`、`boper_authorize_screen`、`boper_test` 与 `settings_open`，不提供对话、历史、数据库、任意设置或任意代码读取/执行工具。新增能力必须显式注册，不能通过客户端自报方法扩权。`settings_open` 仅打开本应用面板并选择已有标签，返回自身窗口范围供受限像素核查，不执行任意脚本。

stdio 桥和 CLI 只使用项目 Node 22 与开发依赖，不加载输入 addon、不改变调试 fuse；实际操作仍由已运行的 Bunny 主进程执行。桥到主进程的内部 IPC 使用 `<userData>/control/bunny.sock`，目录 `0700`、socket `0600`；同一用户的本机调用按主人授权处理。请求、回执大小、连接数、并发和等待均有上限；超时返回结果不明，不自动重试或重放。仅内部传输使用私有 envelope，不将它称为 MCP。

设置的「键鼠」是独立标签，原「设定」更名「身份」，保留内部 persona 标识。键鼠页按未启用、安装/更新、等待驱动授权、故障、就绪提供下一步，操作即时生效；系统版本决定驱动批准位置，显示原厂驱动与发布者名称。屏幕识别权限单独列示，只在进入该页或手动重新检测时查询；`authorize_screen` 仅请求屏幕权限，不附带 AX 或注入权限查询。就绪、屏幕已允许且生活场景才开放合成接收窗口验收，诊断第一步先确认 CGDisplayStream 可用，之后才发送输入。

`scene_get` 仅读取 `config.memory.scene`，`scene_set` 与 UI 共用 `applySettings`，沿原有取消、场景失效和通知链路切换；BOPER 与 UI 共用 `controlBoper`。本地输入验收继续要求生活场景，只使用合成材料和自己的接收窗口。没有读取私聊内容的调试入口。

`speech_control` 也注册在同一 MCP 工具表，仅生活场景可用。`status` 只返回诊断及普通聆听的非内容状态，`listen` 通过与 UI 相同的 `setListening` 开关；`diagnostic_start/stop/clear` 复用 `SpeechDiagnostic` 的隔离、容量和清理约束，参数上限20秒。接口不返回转写、录音、目录或聊天数据；测试证据仅在本次明确合成采集范围内读取。诊断后不会自动恢复普通收音，开发者须按测试前状态明确恢复。

软件操作采用共同 Task/Action/Operation，不按微信另建任务系统。CLI/代码、AX 等结构化界面、服务和纯视觉是软件操作通道；BOPER 的 CGEvent/VirtualHID 是实际键鼠后端，不取代通道授权。WorkBuddy 可依当前能力、经验和权限组合多通道，微信仅视觉且必须 VirtualHID；各路径共用取消、效果记录、未知不重放及按 scope 停止。VirtualHID 不支持按 PID 后台输入时，在派发前拒绝，由既有恢复选择获准前台方法，不能暗中回退 CGEvent。

```sh
# 在项目目录使用 Node 22；也可显式指定 --user-data DIR 或 --socket PATH。
node tools/bunnyctl.cjs tools list
node tools/bunnyctl.cjs scene get
node tools/bunnyctl.cjs scene set life
node tools/bunnyctl.cjs boper status
node tools/bunnyctl.cjs boper enable
node tools/bunnyctl.cjs boper refresh
node tools/bunnyctl.cjs boper test
node tools/bunnyctl.cjs settings open --params '{"tab":"keymouse"}'

# 供 MCP 客户端配置的 stdio 服务入口。
node tools/bunny-mcp.cjs
```

## 11. 性能与升级边界

保持按需模块、当前 head 索引、有界候选、图像缓存和请求去重；不全库两两比较，不在每次对话附完整任务状态，不重复为确定性 Operation 调模型。必要核查和合理异步等待由 Bunny 根据真实环境安排。

构建使用资源白名单、文件哈希和稳定本机签名；安装先验证暂存包，失败可回滚，成功清理旧应用备份。用户资料、个人模型及密钥不进入源码或安装包。旧安装产物和实验记录使用外部备份，不在仓库中长期堆积。

任务系统本轮审查覆盖创建与默认路由、五项准入、并发 Action、来源与权限、未知效果恢复、接续、到期、停止及外部资源、结果汇报和用户反馈。发现并修复的共性缺陷包括：外部停止失败抹掉本地停止意图、恢复重新接手、旧可写对象穿透终态、批量停止串行等待、晚到权限与报告回调、控制错误提示被刷新覆盖、原生空 RunLoop 等待提前返回，以及已结束资源仍持有活闭包。离线验证涵盖真实 IPC 处理函数、隐藏渲染窗口、独立本机终端进程与进程身份拒绝；不操作当前桌面、WorkBuddy 或微信。真实软件卡死、未保存窗口识别、正常/强制退出与重开仍需独立现场验收，不能以协议夹具通过宣称任意软件恢复可靠。

当前仍需持续验证：其它 Mac/旧系统兼容、长期经验质量、开放任务迁移能力和外部平台的真实授权环境。真实微信、平台保存及接收方结果不能由离线测试替代；本轮问卷的官方预览登录验收尚未完成。架构支持自主学习与恢复，不代表任意任务均能完成或程序可自行无限改写。

### 任务列表保留与输入命中

`AgentRuntime.archiveList/restoreList` 只在加密 Task 记录中写入或移除 `state.listArchive`。清空时快照旧任务并先同步封住执行，新任务可独立准入；保存以24条为一批，保留来源图、结果、清理日志和文件，取消未交付的旧报告。恢复只恢复列表可见性，不恢复执行或发送。它不调用资料删除或推进记忆代次；写入失败保留可见状态并报告缺口。

透明宠物窗的输入区域由渲染器上报实际可见控件矩形；主进程 `PetWindowInput` 用当前原生窗口边界及屏幕鼠标坐标重新命中，并在展开、移动、缩放及控件移除后更新穿透。渲染器 hover 只辅助角色命中；任务控件可在 GUI 租约期间操作。隐藏窗口 compositor 验证与真实系统鼠标验收分别记录。
