# 0.10.0：Character、消息块、语义水位与请求预算

2026-10-27。承接0.9.0记忆生命周期，落实随后三轮讨论。本文件先记录本轮设计与实施计划，实际验证和未完成边界在交付记录中说明。

## 代码诊断与方案

0.9.0的消息入口和提炼器主要接受user/assistant；Dream按100条用户消息触发；Doze保护完整轮次但不允许模型选择连续前缀。最近交流由8轮与字符预算共同裁剪，整体请求之后还会增加角色设定、工具及任务状态。单纯改数字和role会造成来源混淆、非对话消息漏处理和实际请求超限。

继续使用本地加密库、不可变派生资料和来源DAG，不引入新的Agent框架。职责分为：原始消息身份→可重建消息块→独立的Doze/Dream语义提交→当前场景检索→完整模型请求预算。

## 不变量

1. Character是身份，API role是适配。主人、Bunny、WorkBuddy及其他来源有稳定characterId、channel、conversationId、taskId、eventType。只有Bunny自己的话映射assistant；其他来源按合法普通输入封装，不因文字自称system就升级权限。旧记录只在读取时兼容默认身份，不能重写旧来源指纹。
2. 接受的原文完整保存；超出明确支持的单条上限应拒绝并提示分段，不能静默截断。流式片段、ASR中间结果、心跳不作为独立历史消息。来源内容不能成为授权。
3. Dream累计50条未处理原始消息触发，包含所有Character，压缩块与派生摘要不重复计数。全库统计只触发调度，输入和水位仍按六个数据分区独立；Doze保留三个可见范围的独立摘要。
4. 连续同Character超过3条才成为块候选，同时必须同任务、会话、渠道和精确隐私分区。关键错误、取消、等待确认与终态保留；每块有界分段，原文仍可回查。跨场景不合并。
5. 消息块是索引，不是事实。Doze/Dream复用块；具体记忆的证据仍指向原始消息。外部观察不能升级成用户事实；用户主动记忆和自动来源标签继续有效。
6. 语义水位由模型提出最后已处理消息ID，程序验证连续前缀、完整轮次、引用与范围，产物和水位成功提交后才推进。未处理尾部原样留存；所有读取输入也保留来源依赖，不能只给产物挂上被处理的前缀而遗漏模型看到的后文。
7. 允许读入50条只处理42条。重复读取同一未变化尾部要有缓存/退避；达到等待时限、日常清尾或显式整理时允许生成带“未完事项”的阶段性记录，不能假装任务已经结束。
8. 最近20条用户/Bunny交流为原文目标，保护完整问答；外部渠道单独有界，不挤掉人与Bunny的交流。巨大历史用明确标识的块/摘录，当前请求不能悄悄删减。
9. 每次实际调用前，连同system、角色设定、历史、检索、工具定义、搜索结果和输出预留统一核算。使用服务商提供的上下文/输入元数据；缺少时用保守预算。文本采用保守UTF-8计量并留余量，不宣称是所有模型的精确tokenizer；视觉按独立保守成本处理。超限先缩减历史/外部资料，仍不能容纳当前请求时明确失败，原文保持不变。

## 形成与调度

消息入口和Bunny回答后都可排入块整理，排队合并、前台优先、共享后台免费模型预算。不依赖Bunny先回答才处理洪峰。完全重复先本地归并；语义块由后台模型生成并核验引文，缺少缓存时用有来源、明确不完整的本地摘录，避免为了预压缩阻塞首次回答。

Doze/Dream使用同一块准备器，但保留不同产物与水位。对话摘要导航、长期记忆、观察与任务经验分别标明证据类型。大块分批有界，缓存身份包含输入指纹，来源变化或删除使派生结果失效；备份恢复不能重新引入已遗忘原文。

整体预算在传输层再次检查，覆盖搜索第二轮、工具返回和格式修复附加提示。压缩与提炼适配器也受同一请求预算保护。人格/操作规则与当前请求优先；不通过删除规则来凑预算。

## 开发与验收顺序

1. Character契约、完整消息写入和WorkBuddy来源接入，兼容旧记录。
2. 消息块共享索引与后台调度，核验同角色不同任务/隐私范围、重复洪峰、关键事件与来源删除。
3. Dream全角色50条计数、观察与事实分级、连续前缀语义水位和尾部续接。
4. Doze语义边界、近期20条交流与外部限额，复用不可变摘要图，避免旧指针循环依赖。
5. 模型能力元数据、整体请求预算与超限恢复，检查搜索/修复路径，保持结构化数据不朗读。
6. 临时加密库与隐藏Electron全链路验证；少量真实WorkBuddy探针不写入正式聊天。成熟后稳定签名安装、核对原始资料与配置保留，再白名单提交推送。

## 实施结果与责任边界

| 责任 | 实现 |
| --- | --- |
| 消息准入与身份 | `message-identity.js`；新消息明确Character、渠道、任务与发生时间，旧消息按原角色兼容；主人身份同时用于记忆、经验与任务恢复授权 |
| 连续块与复用 | `message-blocks.js`；同分区、同会话与任务，超过3条形成块；每32条以内分段，精确重复本地处理；语义缓存核验来源指纹，错位窗口可复用覆盖区间 |
| 语义提交 | `semantic-plan.js`、`semantic-boundary.js`；Doze/Dream分别缓存分析结果，验证合法块端点、连续前缀和完整问答，读取后文也纳入来源依赖 |
| Doze | `context-compression.js`；三场景独立不可变摘要图，近期交流保留原文；洪峰可先整理外部通道，独立水位、先产物后指针 |
| Dream/Deepdream | `memory-maintenance.js`；六个精确分区各自提炼，50条全角色待处理消息触发；外部来源只形成带真实Character的待核对观察，不能确认为用户事实；Deepdream继续做受证据约束的归并、关系与经验整理 |
| 前台上下文 | `memory-service.js`、`recent-rounds.js`；默认最近20条主人/Bunny交流、完整问答优先；外部最多8个单元；历史原文仍可检索，预读80条不等于屏蔽这80条的历史检索 |
| 最终预算 | `context-budget.js`在普通LLM与WorkBuddy传输层统一检查；覆盖联网后续轮、工具定义/结果及格式修复，不仅检查历史列表 |
| WorkBuddy接入 | `monitor.js`、`index.js`；只接入启动后新出现的实际文本，不回灌历史与思考；快照固定任务身份，按持久任务继承隐私范围，不能由文本自称授权 |

入口和回答后自动合并排队即可提前整理块，不给每轮对话增加“是否压缩”的前置模型判断，也不依赖模型额外输出提示字段。前台无可用语义缓存时使用明确标为不完整的原文摘录索引，模型整理留在后台免费通道，共享现有调用预算。

语义尾部未变化时复用结果，不重复调度；等待10分钟后、04:00清尾、手动整理或Deepdream补提炼时允许提交阶段性未完事项。非法水位、引文不实、来源变更、模型失败或预算不足均不推进水位。删除或纠正来源会清理派生记录，并按受影响分区回退Dream水位，重新处理仍存在的原文；Doze从可验证的不可变摘要图恢复。

## 参数与实际限制

- 当前消息单条准入上限128KiB UTF-8；超限明确拒绝，不保存残文。已接受的原文不再按旧12000字符截断。密码/密钥仍走独立保密路径，不能进入普通记忆和云模型整理。
- 批次最多50条原始消息，具体受字符预算、完整问答和语义前缀进一步约束；Doze/Dream独立水位。20条交流是目标，不是任何长度下均硬塞20条。
- 预算使用模型能力元数据；缺省上下文32768，扣除输出预留并留15%余量与额外缓冲，运行输入估计上限64000。UTF-8计量偏保守，视觉采用独立估值，不宣称是精确tokenizer。
- 超限先减外部/检索等历史，再对过长旧消息生成明确标识的部分索引，按完整历史轮次舍弃。人格/操作规则、本轮请求及其工具往返受保护。服务商仍报告上下文超限时，在同一截止时间内仅重试一次半预算；本轮自身过大则提示分段，原文仍保全，不实现未经说明的任意长文自动分解。
- 非主人来源的观察保留真实来源、时间与任务条件。任务不同阶段的进度差异不会直接变成“用户矛盾”；与用户事实不混合归并。语义相似不能代替证据。
