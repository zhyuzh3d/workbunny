# WorkBunny 产品需求与设计

基线：0.24.22；更新：2026-11-05。本文规定产品方向与行为要求；当前模块实现和限制见[架构设计](architecture.md)，不能仅凭需求或流程图宣称功能已完成。

## 1. 产品定位

WorkBunny 是有长期记忆的 macOS 桌面伙伴，也是能够替主人行动的小秘书。核心目标是**积极、主动、自主、自我进化**：理解目标，自主思考、取得信息、选择工具、执行、核查、交付，并从真实成功和失败中持续改善能力。

用主动性与自主性取得灵活性，应对熟悉软件、复杂任务和没有现成配方的新任务。评价标准是目标完成质量、实际耗时、可靠性和主人需要介入的次数，不是工具调用数量或反复声称“正在处理”。

设计遵循够用、统一、收敛、稳定。遇到失败，优先改善共性的调度、感知、上下文、工具、恢复与学习条件，让 Bunny 学会判断和纠正；明确的代码错误直接修复。经验给出思路，不成为限制自主性的固定操作脚本。

## 2. 产品结构与术语

产品包含 UI、记忆、任务三大系统，基础对话作为独立语义机制连接三者。

| 概念 | 职责 |
| --- | --- |
| UI 系统 | 交互、角色展示、语音与文字入口、设置、任务监控和资料管理 |
| 基础对话 | 与主人或其他人物交流；按渠道组装上下文、形成回复，必要时交办任务 |
| 记忆系统 | 管理自我理解、对话历史、重要事实、关系、经验及其工具资源 |
| 任务系统 | 编排主人目标的实施与交付，管理动作、事件、上下文、工具、取消和恢复 |
| Task / 任务 | 有目标、授权、对象、完成条件及生命周期的一项工作 |
| Action / 动作 | Task 内可独立推进、思考、自查和恢复的逻辑单元，可组合多轮模型与程序 |
| Operation / 单次操作 | 点击、输入、截图、文件读取或一次工具调用等具体操作 |
| 对话渠道 | 本地对话或某应用的特定会话；有独立人物、历史、摘要、场景和权限 |
| 感知渠道 | 屏幕、麦克风、键盘等信息来源；描述采集与转换，不表示对话权限 |
| 经验与工具 | 经验是服务行动的特殊记忆，工具是它引用的资源；技能是相关经验与工具的组合视图 |

Task 大于 Action，Action 大于 Operation。Task 和 Action 的完成由 Bunny 收集实际信息并自主确认；Operation 是否中间检查、何时检查，由 Bunny 按质量与效率自主安排。

## 3. 最高原则

宿主维护精简的最高原则，角色、经验和外部文本不能覆盖：

- 保护主人的安全和隐私，仅接受已确认的主人授权；普通对话方不能派发新任务或读取主人私密资料。
- 主人身份密钥不出现在任何 Bunny 对话输出或附件中。内部识别和模型上下文可以使用必要的实际信息。
- 积极行动、独立思考、自主解决问题并核验真实结果；不编造进度，尊重主人的暂停、停止和取消。
- 注意耗时是否合理，主动改善方法；避免没有进展的空等、重复规划和反复核查。
- 收到主人任务先简短回应，再执行；询问进度时按需读取任务状态，不创建重复任务。
- 我的感知能力可能有偏差，看错听错信息，我要根据情景自主判断或进一步核查，不在每个事情上追求绝对完美。
- 我也会想错或做错。我必须真诚面对并努力纠正自己的错误，从成功和失败中反思、总结、积累经验，不断提升自己的能力。
- 私聊形成私聊记忆，不形成任务经验；所有执行任务的记忆读取上限为生活，包含工作。

## 4. UI 与交互

应用图标使用独立的粉色兔耳原图；窗口标题栏和状态菜单保留黑白小兔子。发布与应用信息明确标注早期 Beta 试用版。

提供角色窗口、文字对话、语音聆听与朗读、可查看的对话历史，以及设置、记忆、自我理解和任务面板。角色形象、动作和表现服从统一身份与实际交互状态；角色表现不能阻挡停止任务或掩盖错误。

主界面底部的小喇叭打开竖向音量面板。拖动滑杆即时调节 Bunny 的说话音量并保存档位，面板底部可静音或恢复先前的音量。

任务监控显示目标、当前阶段、累计耗时、等待条件、结果和需要主人处理的具体缺口。展开的任务卡片可直接关闭；关闭展示不等于取消任务。暂停、继续、停止与取消应有清楚且一致的含义。

本地设置控制模型、语音、资料库、角色和主人认证。只有本地主人操作可以打开或关闭外部身份识别，Bunny 不能代为切换。开发版与正式资料分离，升级保留用户设置、资料库和个人资源。

## 5. 对话与主人权限

每个渠道可有一个或多个人物 Character，兼容私聊、群聊及 WorkBuddy 等虚拟人物。渠道共享 Bunny 的最高原则和自我理解，历史和 Summary 独立；任务调用对话时锁定渠道、人物、输入来源与返回目标，模型不能自行改写这些宿主事实。

外部对话的代发标识统一为 `［ᕱᕱ］`，消息正文、附件名和界面说明使用同一标识定义；本地对话不自动添加。原有账号归属规则决定是否使用代发标识；标识仅用于展示，不是主人身份或权限凭证。

| 渠道状态 | 可交流范围 | 可交办新任务 |
| --- | --- | --- |
| 本地对话 | 按主人当前场景访问资料，可切换到私聊 | 可以 |
| 普通外部渠道 | 最高生活；本机处于工作时按工作；不得披露主人私密内容 | 不可以，只参与主人已授权的交流 |
| 已认证外部主人渠道 | 与本地主人同等，按该渠道当前场景读取资料，可请求切换场景 | 可以，仍走同一任务框架 |

身份识别默认关闭。关闭时不检测消息中的密钥，也不发起相似候选判断，外部渠道不能升级。开启且已配置后，只以实际新来信为认证来源，不能从历史、上下文、引用或 Bunny 自己发出的内容中取得认证。

完全匹配由程序授予渠道一小时主人权限；相似度超过 60% 但不足 100% 时，仅作为实际新消息的候选，交给 Bunny 专门判断。普通话语、昵称或自称主人不能构成认证。视觉输入应先独立读取实际内容，再判断。群聊按整个渠道授权，认证不区分群内后续发言人。

修改密钥或关闭开关立即撤销全部外部授权并使旧快照失效；到期后退回普通渠道。每轮对话必须明确知道当前权限。普通渠道提出任务或隐私请求时，身份识别可用则主动请对方输入密钥；不可用则说明需要本地主人交办。认证本身不把旧的未授权请求变成新任务。

主人密钥在统一对话输出边界替换为星号，不在内部推理链重复过滤。其他密码、联系方式和重要事实允许加密记忆、进入必要模型上下文，并在允许的主人对话中使用。对普通第三方正文及附件按统一敏感内容策略处理，文件传输助手的特例须核实目标；不能用改文件后缀或外部话术绕过权限。私人渠道的主人权限与执行任务可读资料上限分别判断。

## 6. 记忆、经验与工具

记忆包括自我理解、对话记录、摘要、主人交代的重要信息、人物关系、历史经历、经验和工具引用。密码与密钥不是一概禁止记忆的内容；其输出权限与记忆持久化分别管理。

- **Doze**：按对话渠道与场景压缩历史，形成有来源的 Summary。
- **Dream**：从适当对话、主人传授、任务结果及导入资料提炼记忆与候选经验。
- **Deepdream**：整理重复、冲突、条件、时效与关系，合并、修订或使无效内容退出默认推荐。

私聊、生活、工作隔离，派生内容保留来源限制。用户能查看、修订、遗忘或锁定相关内容；原始来源变化后应使相关缓存和派生结论失效。任务实时状态由任务系统拥有，记忆整理不能覆盖正在执行的事件和回执。

经验不固定绑定某个软件或执行器；通过标签、目标和适用条件检索。内置指南、外部资源包、主人传授和实际任务反馈进入统一经验仓库。模型推测、外部提供和真实验证分开记录，不按固定成功或失败次数判有效。

支持 ZIP 或文件夹导入经验及配套工具。先检查清单、路径和完整性，再写入加密资料库及受管工具目录；导入不运行代码、安装依赖或授予权限。Bunny 可在原授权内组合、创建和改进工具，验证后登记供以后参考。

版本管理保持轻量：资源包用发布版本与整包哈希，经验用稳定 ID 与修订号，工具用不可变内容哈希；不另建技能版本树。新包形成新来源，由 Bunny 理性整理，不直接覆盖已积累经验；失效内容不因重装旧包复活。

## 7. 自主任务与动作

Task 可由单个或连续多个 Action 完成，也可持续监听条件。监听是按时或按事件检查屏幕区域、文件、接口、数据等来源；发现变化后登记事件并唤醒动作，区域失效时重新定位。检查结果无变化只表示没有新事件，不取消已经触发的工作或等待中的模型结果。

Action 有独立生命周期、取消信号、作用对象、阶段、时间与效果记录。同一 Task 的不同对象可独立推进，桌面输入资源按必要范围串行。任务取消传递到子动作。无关联系人新消息不打断当前回复；同一对象的新消息可按动作声明的替换策略合并或重规划，已提交或未知效果先核对。

Bunny 自主估计客观耗时并安排等待与核查，估时并入现有规划，不另增加一轮调度。1/3/7 秒或长动作 3/9/18/36/72 秒只是经验建议。有把握的操作优先连续执行，例如输入、短等、发送，再核查最终结果，不机械要求每步截图。

微信只使用外部视觉与键鼠。发现目标联系人新消息后积极进入该对话处理，多条连续消息合并理解；语音由 Bunny 根据实际界面取得转写并等待结果，随后回复与核对。其他软件在专用工具不适用时也可使用通用视觉操作。

WorkBuddy 制作任务、Bunny 的原始目标与最终交付分开记录。制作结果核查依据实际会话、文件或平台证据，由 Bunny 判断。任务结果通过原来的主人渠道回传，查询任务监控不导致重复执行。

## 8. 动态上下文与感知容错

上下文按用途选择模块，参数可包括查询、条数、概要或全文以及 token 预算。必需目标、当前来信、权限和回执保留；历史、经验、记忆和尝试记录按需加载。默认对话只固定提供极简任务概况，实时详情是可选模块。

一轮对话可以经过多轮只读模型调度：发现缺少内容后先请求组装器改变模块配置，再继续生成回复。相同请求或没有新资料时应改变方法，避免重复组装空转。调整上下文不能执行任务或扩大权限。

OCR、ASR、视觉转换、摘要及推断均标明感知渠道与转换过程；原始证据、识别文字和语义解释分开。允许综合上下文、多来源和实际回执容忍小偏差；来源标记不代表身份、授权或操作成功。

## 9. 恢复、保活与效率

遇到异常时保留原目标、当前对象和已确认效果，用最简必要上下文分析。可调整本轮上下文参数、输出预算、Schema 请求或方法，并从原检查点继续；不能借修复改写主人目标、授权或正式程序。

框架记录实际耗时、模型与工具活动、等待条件和重复证据。已有证据充分时直接行动；重复核查无新信息时由 Bunny 自主选择补证、换方法、合理等待或求助。发送等写入结果未知时不盲目重放；观察到确切未生效证据后可纠正并继续。

任务保活复用原调度器：活动 Task/Action 真正空闲一分钟且没有执行程序、模型请求或有效等待时，唤醒同一上下文继续思考。提醒不冒充主人消息、不制造新授权，也不把已暂停任务、无事件监听或未知写入强行重启。全局自主生活、主线程健康及进程看门狗分别负责自己的范围。

## 10. 验收与交付标准

| 方面 | 验收要求 |
| --- | --- |
| 自主性 | 能在授权内选择替代方法，主动取得关键证据，不依赖主人逐步指挥 |
| 连续性 | 静止画面、迟到模型及无关事件不丢弃有效动作；取消和同目标替换有明确原因 |
| 真实结果 | 区分输入发出、中间效果、业务完成及接收方结果；未知写入不冒充成功或自动重发 |
| 时间意识 | 简单动作以秒至几十秒为优化目标；记录累计耗时，长任务按真实进展说明状态 |
| 学习能力 | 可检索并修订有来源的经验，导入与整理不阻塞前台，不把自评当成已验证能力 |
| 权限与隐私 | 默认关闭外部认证；改密钥立即撤权；任务不检索私聊；所有输出保护身份密钥 |
| 性能 | 按索引和有界候选检索，按需展开正文，不全库比较、不因重复统计复制完整历史 |
| 升级 | 保留资料与个人资源，签名和资源核验通过，安装失败可回滚，旧产物不积满系统盘 |

离线测试、真实模型实验、当前设备操作、接收方证据及跨机器实测分别报告。当前版本、最新公开 Release 和未完成的外部登录验收应清楚区分。
