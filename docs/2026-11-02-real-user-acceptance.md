# Bunny 真实用户场景验收

本轮从普通聊天、主人微信和设置窗口进入；实验脚本只负责扮演用户、等待和记录，不绕过产品编排去代替 Bunny 完成工作。模拟规则测试和真实软件测试分别记录。

| 场景 | 用户实际说法或处境 | 验收重点 |
| --- | --- | --- |
| 多轮交办 | 先讨论文件内容、项目背景，再说“按刚才方案办，结果微信告诉我” | 不要求重述；补全上下文；真实工作与文件；结果只走文件传输助手 |
| 连续修改 | “再补上这一点” | 原会话、原工作绑定；结果修订递增；旧成果仍有来源 |
| 转交结果 | “把刚才成果转给 Alice” | 不重做；发送真实文本和附件；单一渠道 |
| 主人离开电脑 | 明确将实验 Alice 绑定主人入口后，从 USB 手机发来工作交办 | 识别新来信、WorkBuddy 实做、回到微信汇报；不依赖 Codex 代发回复 |
| 上下文改变 | 项目期限从周五变成周一，再追问期限 | 使用新信息，不混用旧背景；每轮只回复一次 |
| 杂讯与争用 | 广告来信、桌面正在忙、输入框已有草稿 | 广告忽略；消息不丢；不覆盖草稿；电脑空闲后继续 |
| 新方法失效 | 软件布局或程序路径改变 | 先观察、定位、改用另一方法；保留真实失败和恢复证据，提取候选经验 |
| 缺少权限 | 终端或系统配置开关关闭 | 打开对应设置；逐项引导；允许后原任务继续，不让主人重新交办 |
| 任务完成 | WorkBuddy 给出实际结论 | 极简播报实际结果；详情能看正文、文件与交付状态；不循环说“未验收” |
| 长时间代管 | 两软件共用调度、区域观察，主人偶尔操作电脑 | 无重复输入、无错误对象；静态画面跳过识别；记录模型、CPU、内存及延迟 |

记录：版本、任务和会话绑定、入口、用户操作次数、非必要确认次数、真实产物、发送回执、失败与恢复、开始/结束时间。不能把“输入成功”当作“用户任务完成”，也不能把本机路径当作收件人已获得文件。

2026-11-02 开发阶段已通过：真实空间/无空间路由；原会话连续修改；真实附件交付；Alice 手机新消息、上下文追问、广告忽略、忙碌排队；实际终端写入/读回与用户配置恢复。普通聊天入口的完整安装验收及 2 小时、8 小时观察仍单独执行。
