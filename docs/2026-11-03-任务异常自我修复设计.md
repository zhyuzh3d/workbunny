# 任务异常自我修复

目标：任务在遇到可恢复异常时，保留原目标、队列、模型决策和执行回执，分析后在同一任务中继续，不创建新的替代任务。普通对话也复用同一组诊断类别和受限调整。

在后续[统一任务编排重构计划](2026-11-03-统一任务编排重构计划.md)中，修复仍由任务协调器管理，并从业务动作已保存的检查点恢复；本文的最小诊断、受限调整、取消传播和未知写入核对继续适用。将修复接到完整业务动作生命周期是规划，不代表所有技能现已支持该层恢复；普通前台对话仍可复用诊断，不强行纳入任务系统。

本文以下固定诊断动作和次数描述当前实现，不是自主能力的最终目标。后续按[产品目标与智能体设计原则](产品目标与智能体设计原则.md)扩展动作级恢复：Bunny 可根据必要观察和失败证据自主分析、尝试其他已授权方法、核验结果，并把有效经验保存为有来源的候选。预算用于防止空转，不以达到固定次数代替问题诊断；未知写入仍应主动只读核对，不能直接重放。

## 流程

1. 原有局部机制先处理短暂网络、JSON 格式和模型输出限制。仍失败时，任务运行器保存异常状态和修复次数；已有写入处于结果不明状态时直接保留原有只读核对流程，不启动自动重放。
2. 对可恢复错误提交一次诊断：仅包含错误类别、代码、技能名、次数和必要的 schema 结构审计计数，不发送交办正文、消息、截图、凭据或历史。诊断只能从固定动作中选择。诊断不可用或超时后，已知的上下文、schema 和输出额度错误使用确定性本地策略；未知原因等待原任务正常重试。
3. 调整只应用于本任务的后续模型请求：分级裁剪可选历史、补充结构化输出修正提示或增加有上限的输出预算。当前来信、任务目标、授权、对象、工具、已确认回执和原始存储不会被裁剪或改写。上下文无法安全缩小时保留原始内容并报告失败。
4. 原任务以原事件和原操作标识继续。任务继续后记录恢复状态，修复参数最多沿用十分钟，随后恢复默认；任务目标被修改或重新接纳为另一技能时清除旧修复配置。持久化的修复进度可跨重启恢复。

## Schema 处理

对输入 schema 做结构检查；模型输出或工具参数不符合 schema 时，使用同一 schema 和本地验证器重新生成，不能放宽权限或绕过校验。运行时不会让 LLM 改写程序代码或将未经验证的 schema 直接替换为正式契约；若契约本身有缺陷，仍需经过开发、测试后更新。

## 收敛与边界

同一异常最多分析两次，每任务一小时内最多四次；诊断最多等待 12 秒。暂停、停止、权限变化、微信身份变化以及发送结果不明沿用原机制，不因为修复而继续操作。重试前重新检查任务授权，已确认的写入使用原有幂等回执，不会再次执行。诊断不创建新任务或独立对外发送。

本机制主要覆盖统一任务运行器中的会话、画面观察、任务解释及组合操作，以及前台普通对话请求。外部网络、登录或模型服务本身故障无法保证由本机修复；达到预算或缺少必要证据时保留任务状态，交由既有重试或人工核对机制处理。
