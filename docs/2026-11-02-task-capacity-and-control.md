# 任务额度与统一控制（0.19.0）

本文记录 0.19.0 的产品规则与验收口径。后续任务内部的条件、动作、并发与迁移方向见[统一任务编排重构计划](2026-11-03-统一任务编排重构计划.md)；重构保留本文件的业务任务名额和待启动规则。

目标：所有 Bunny 软件技能沿用同一个任务记录、运行时与控制入口；主人能看到任务在做什么，并直接停止。原有 WorkBuddy 状态同时显示，但不把一个委派拆成两个任务。

## 产品规则

- 最多同时启动 5 项业务任务。准备执行、执行、等待事件/结果、等待授权、需要处理和正在停止均占一个名额；暂停、待启动和已结束不占。一次任务涉及多个软件仍只占一项。
- 理解主人指令的短暂内部记录不占业务名额，满额时仍能理解“停止 Alice 监听”等控制指令。主人自己在 WorkBuddy 创建的独立任务显示在状态条，但不占 Bunny 业务任务名额。
- 满额时新交办照常保存为“待启动”，明确提示打开“工作与日常”停止旧任务，然后点击新任务的“启动”。释放名额、重启应用、修改目标都不会自动启动待启动任务；时限从实际启动计算。
- 工作与日常显示运行数量/5、待启动数量和各任务状态；支持启动、暂停、继续、停止。口头或文字控制与按钮使用同一运行时。
- 主界面多任务上下轮播，悬停停止轮播，滚轮选择。进行中的任务显示 ×；点击发出实际停止，等待确认，不把任务直接隐藏。只有完成任务显示 ✓，点击只收起状态提示，成果和历史保留。停止和失败不伪装成成功。

## 实现

1. AgentRuntime 使用同一个串行名额提交段处理创建、内部交办转正式任务、继续。模型理解/观察不放进这个提交段。并发创建也不能突破 5 项。
2. `queued` 保存在现有加密任务账本，不另建队列。`stopping` 先阻断后续工具输入，再等待技能执行器停止；失败保留“需要处理”，不宣称已停止。
3. 软件执行共用 GUI 租约。微信仍然只用外部显示画面和通用键鼠。WorkBuddy 停止先核对已绑定工作轮次，再核对可见会话标记（独立手工任务核对标题及原文），点击真正的停止控件，观察控件消失后确认。禁止退出应用或杀软件进程代替停止。
4. 监听修改只链接本次主人原始指令来源，不链接任务自己的下游汇报；修改先持久化副本，成功后替换运行状态，避免循环来源错误污染正在运行的任务。
5. WorkBuddy 实际日志中的 `Interrupted by user` 归为已停止，历史重放也采用此语义，不播报完成。

## 截图与性能

微信默认每 5 秒比较，活跃时 3 秒。定位有效时主后端 CGDisplayStream 按已定位区域采集；首次或定位失效才回到全屏定位。备用 AVCaptureScreenInput 后端仍可能整屏采集后裁切，不能把所有路径都称为原生局部截图。

同一微信场景共享观察器和并发采样；不变画面跳过 OCR 和模型。观察既包含会话列表，也包含当前聊天区域，避免已打开 Alice 时没有红点而漏信。通用软件的不同画面仍会增加采样和识别开销；5 项是产品上限，不代表 5 次视觉模型识别可以没有成本。输入操作通过同一个 GUI 租约串行，不互相抢键鼠。

## 验证口径

- 回归覆盖并发 8 项只启动 5 项、待启动恢复、释放名额不自动补位、手动启动、满额仍可理解控制、停止未确认不释放名额、加密存储来源无环、主界面 ×/✓ 与轮播。
- 真实 WorkBuddy 隔离等待任务已观察到停止按钮从存在变为消失；安装后还需验证状态条完整控制链。
- 不把界面夹具称为真实微信监听验收；2 小时及 8 小时长期稳定性仍须另行验收。
