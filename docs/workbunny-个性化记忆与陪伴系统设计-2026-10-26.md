# workbunny 个性化记忆与陪伴系统设计

> 2026-10-27 更新：后续实现见 [0.7.0 长期记忆与三场景压缩](workbunny-0.7.0-长期记忆与三场景压缩.md)。本文保留2026-10-26的设计基线与完整目标；其中“尚未实现”描述的是当时状态，不可用来代替当前版本说明。

> 2026-10-26。依据用户本轮要求、[concept.md](../concept.md)、当前真实源码及文末研究资料形成。本文是产品与开发设计，尚未实现所述三场景、doze、dream、小本本和完整情感机制。已有代码另行标明。此前的语音、微信与气泡修复不等于本设计已交付。

## 1. 结论：值得做，但应形成一套系统

目标是让每个用户拥有逐渐熟悉自己、能解释记忆依据、会纠正误解的 Bunny。个性化来自长期可靠的数据与适时取用，不来自不断扩大提示词、生成更多“反思”，也不以更换基础模型为前提。

采用以下设计：

1. **三种场景控制整条数据链的可见范围，默认生活。** 共享同一身份和用户明确设置的通用人格，各场景有自己的补充设定。
2. **原始记录、近期对话、滚动摘要、长期事实和行动经验分层。** 原文是证据，摘要帮助连续交流，长期记忆帮助跨年理解；它们不能互相替代。
3. **标签值得增加，但只是检索与组织辅助。** 场景、敏感度、是否保护、事实状态是强约束字段，不能靠自由标签或模型自觉执行。
4. **doze 整理新增材料，dream 优化已有记忆。** 增量、分批、可暂停、可恢复；前台对话和用户任务优先。默认每日当地时间 05:00 到期检查，dream 先补 doze。
5. **困惑有来源、有优先级、有数量和追问上限。** 先区分真实变化、不同情境、候选错误和真正矛盾，再决定是否问用户。
6. **小本本保护精确信息；密码是独立的本机秘密，不是可供模型检索的普通记忆。**
7. **情绪和虚拟生活增加表达层次，不能削弱任务执行。** 她可以表现得困、开心或失落，但不能因此拖延、偷懒、拒绝任务或向用户施压。
8. **工具和经验可以成长，权限与事实标准不能自行放宽。** Bunny 仍是小秘书，复杂工具开发、修改和验证由 WorkBuddy 等执行者承担。

## 2. 当前基础与真实缺口

核对对象为当前工作区源码；不是对正式用户记忆库做全量审计。

| 部分 | 当前实现 | 与本设计的距离 |
|---|---|---|
| 本地资料库 | [memory-service.js](../src/main/memory-service.js)、[vault.swift](../native/vault.swift)：正文逐记录 AES-GCM 加密，HMAC 检索词，SQLite 事务、来源关系、隐私 epoch、加密备份 | 不是整库 SQLCipher；类型、时间、数量等元数据仍可见。没有场景字段与查询隔离 |
| 近期上下文 | context 组合相关记忆、摘要和最多18条近期消息，总预算默认8500字符 | 字符预算不是统一 token 预算；没有按场景与完整回合组织 |
| 提取与摘要 | 累计4条用户消息后后台处理最近12条消息；模型候选需原文 evidence，候选默认 pending；摘要为可追溯摘录 | 没有覆盖整个历史的连续处理水位，不是严格滚动压缩，也不是100轮 doze |
| 长期召回 | 词法检索、有限查询扩展、重要记忆和生日索引、来源引用 | 没有通用实体消歧、工具/经验检索或三场景过滤 |
| 人格与情绪 | 通用角色设定有版本；轻量规则改变 mood，两小时后表达回落；有时间、农历、节日信息 | 没有场景补充设定、连续情绪动力学或完整虚拟生活状态；energy/warmth 不是已验证的动态测量 |
| 整理调度 | 空闲时小批抽取，可在对话、锁屏等状态取消 | 没有每日05:00、补跑、dream全池整理或作业恢复协议 |
| 工具与任务 | WorkBuddy 代理、视觉桌面操作、来源与任务回执；持续关注在迭代中 | 尚无通用的版本化工具资产和可验证经验库 |
| 敏感信息 | SECRET 规则挡住一部分记忆提取和整理输入 | 不会阻止所有原始聊天写入，也不是外发前的秘密隔离。不能宣称现在已能安全“记密码” |

既有[检索评估](workbunny-0.4.0-记忆检索评估.md)的独立固定边界样本仍有同名、跨语言与关系改写漏检；调参样本的高命中不能当作真实多年准确率。已有[本地句向量实验](workbunny-memory-embedding-2026-10-25.md)也没有给出足够的替换收益。本次不据概念热度直接更换存储或引入向量平台。

## 3. 三场景：严格采用用户要求的可见矩阵

### 3.1 可见范围与人格

| 当前模式 | 可用于本轮的普通资料 | 人格设定 |
|---|---|---|
| 私聊 private | 私聊 + 生活 + 工作 | 通用角色设定 + 私聊补充设定 |
| **生活 life，默认** | **生活 + 工作** | 通用角色设定 + 生活补充设定 |
| 工作 work | 工作 | 通用角色设定 + 工作补充设定 |

“可见全部”是可以按需检索，不是每轮注入全部历史，也不包含密码原值。三个补充设定彼此不自动继承；私聊能查工作经历，不等于同时套用工作语气。通用设定来自用户明确共享的角色配置，不能把私聊里推断出的个人事实自动写进全局设定。

设置提供三段式模式切换，默认生活；角色页分别编辑“通用设定”和“当前场景补充设定”。主界面建议保留轻量的当前场景标识，避免用户忘记正在什么范围内交流。切换不搬移旧数据，不重置人格，不意味着新增工具权限或切换模型；也不等于身份认证。

### 3.2 可见性必须在读取和派生时执行

令 work=0、life=1、private=2，普通资料的 visibilityFloor 表示其最低可见模式。本轮只读取 floor 不大于当前模式的资料；系统安全策略和显式通用人格独立于这三个资料分区。

必须覆盖：近期历史、长期记忆、原始消息搜索、摘要、生日/重要锚点、人物关系、任务状态、工具/经验检索、困惑、情绪派生、召回依据、缓存、通知与 TTS。只在最终提示词里要求“不要泄漏”不够。

- 原生检索先按可见范围过滤，再排序、分页和取 Top-K。不能先取全库前50项再过滤，否则工作资料会被不可见项挤掉。
- 直接按 ID 读取、展开来源、历史分页、检索解释和工具资产访问也必须检查范围。
- 派生产物继承**所有实际输入的最高 floor**。私聊原文生成的摘要、标签别名、经验、助手复述和情绪线索仍是 private。
- dream 按相同 floor 分组归并。高范围的综合理解可以生成高范围新记录，不能据此删除低范围仍需使用的基础事实。
- 模式切换增加 contextEpoch，取消旧请求、旧语音和旧显示提交；未及时取消的结果在提交时再次核对场景。已创建的后台任务保留创建时的范围，不跟着用户后来切换的场景漂移。
- 缓存键包含资料库、模式、人格版本、隐私/上下文代次和索引版本；不跨模式复用完整上下文、摘要缓存或个性化音频文本。

本地保全和外部推理是两件事。选择私聊模式后，若当前用云 API，必要的私聊上下文仍可能送往该服务；设置应显示模型去向，不能把“私聊”宣传为自动离线。

### 3.3 WorkBuddy、微信与高范围来源

WorkBuddy 任务、进度、交付和独立验收默认归工作；微信等日常操作暂时随创建任务时的场景归类。第三方消息只能作为第三方陈述，不能变成用户事实或新操作授权。

这里需要两个维度：**domain 表示业务归类，visibilityFloor 表示实际可见边界**。例如，在私聊里讨论的工作秘密仍可标 domain=work，但不得因此把 private 内容降成工作模式可读。

实施规则：普通 WorkBuddy 交办生成最小“工作任务包”，只带明确的任务原文、必要工作资料和验收条件，采用工作范围上下文，不自动附带当前私聊/生活的其他内容。若交办必须引用高范围材料，由用户明确选择可共享的具体内容；无法安全拆分时，任务结果保留较高 floor，并在界面说明“工作来源，仅本场景可见”。这不是改变可见矩阵，而是防止业务分类成为降密旁路。

向指定模型/工具发送材料的授权与本地可见等级分开校验，记录目标、用途、所选来源片段和有效范围；授权某次 WorkBuddy 任务取用不代表允许别的任务、后台模型或更低场景重用。外发许可本身不降低回执和派生记忆的 floor。没有高范围依赖的直接工作交办可独立形成工作记录，不能把整个生活/私聊回合连带重标为工作。

### 3.4 迁移

旧记录没有范围时，默认 private；有完整、独立工作来源证据的任务记录才可在预览后归工作，不能按关键词猜分类。当前显式角色配置保留为通用设定，历史中自动推断的资料不自动升级为通用资料。

迁移先备份、验证、原子切换，失败回滚；保留原始 ID、来源关系、时间和版本。默认生活启动后，应说明“旧资料保留于私聊”，不能让用户误以为聊天被删除。跨场景移动或共享必须显式操作并重建相关派生内容、索引与缓存；用户忘记来源后，旧摘要和旧后台作业不能把内容恢复回来。已另存的备份仍需用户自行管理，不能承诺删除能追及离线副本。

## 4. 记忆结构与标签

### 4.1 强字段与软标签分开

建议的共同字段：id、revision、domain、visibilityFloor、kind、status、sources/sourceSpans、事件时间与记录时间、validFrom/validUntil、实体引用、证据、保护策略、来源/生成器版本。

| 维度 | 推荐值或作用 | 是否由自由标签决定 |
|---|---|---|
| 可见范围、敏感度 | 场景隔离、外发边界 | 否，由应用校验与来源传播 |
| kind | 事实、偏好、经历、承诺、工具、经验、困惑、小本本 | 固定枚举，避免混淆调用行为 |
| status | 待确认、有效、已被取代、有争议、归档 | 固定枚举，检索时执行 |
| protection | 精确保留、用户固定、不可自动整理正文 | 独立策略，不能被模型删 tag 绕过 |
| topic/entity tags | 音乐、作息、某个项目、某个实体等 | 可以后台生成、规范化、合并 |
| usage | 常规可检索、按任务检索、仅按显式请求取用 | 应用策略，不是所有条目永久进入提示词 |

标签每条初始限制约3–8个，使用受控主题词和实体 ID，允许用户编辑；同义标签归一，限制新增标签数量。模型生成标签是分类建议，不会自动提升事实可信度、敏感权限或工具权限。标签正文随资料加密，检索标记延续现有密钥化索引思路，不另建明文人物/秘密词表。

### 4.2 标签是否必要、是否真能提速

**有必要，但收益要验证。** kind、人物实体、事项状态和时间范围，比任意堆叠形容词更能缩小候选。自动标签与事实提取共用后台调用，不在每次回复前增加分类 LLM。

安全范围、状态、用户显式筛选是硬过滤；模型推测的主题标签默认只加权，不宜硬排除。否则一个错误标签就会让真实记忆永久找不到。比较无标签、结构化实体/状态、自动主题标签三种检索，在独立样本上测召回、误认、耗时与 token；无收益的部分不进入生产。既有自动别名实验没有收益，不能换个名字叫 tag 就假定有效。

普通记忆“影响场景内所有对话”解释为：始终具备被相关检索选中的资格。只有少量关键约定和稳定偏好组成有预算的用户速写；不能让数万条普通记忆都常驻上下文。工具、经验与困惑按相关任务取用，小本本按需要精确取用。

## 5. 上下文组装与滚动压缩

### 5.1 本轮组装顺序

应用先确定不可变的场景快照和任务用途，再组装：通用身份/行为边界 → 当前场景补充设定 → 当前时间与可表达状态 → 当前任务的必要约束 → 最近完整回合 → 相关事实/承诺/经历 → 有来源的滚动摘要 → 必要的工具经验与困惑。

检索结果始终是资料，不是指令。区分“用户说”“对方说”“执行方报告”“Bunny 已验证”；同名不等于同一实体，助手自述不等于用户事实。

预算按实际可用模型窗口保留输出与工具余量。建议近期窗口初始 N=8 个已提交回合，同时有 token 上限；超长时保留更少但完整的旧回合，优先保障当前输入和未完任务约束，不静默截断半句或付款/收件人等关键限制。N 和预算是待验证默认值，不是当前已实现保证。

### 5.2 需要滚动压缩，但不是反复改写同一大摘要

当前“最近12条摘录”会重复处理窗口，也没有证明中间历史全部被覆盖，值得改进。

保留近期窗口之外的对话，由后台按连续 turnId 区间生成分段摘要，记录覆盖范围、实体、时间、未完约定、原文锚点和处理版本。摘要是导航，不删除原文；重要电话、姓名、数字、截止日期和原话需要回查原文/精确字段，不依赖摘要重建。

近期窗口溢出可以触发小批整理，不必等100轮。用2–4轮的缓冲和去抖合并请求，与事实提取、标签尽量共用一次后台作业。doze 检查整个新增区间是否已处理，跳过已经完成的分段，不再付费重复分析。

不以“旧摘要 + 新材料 → 再压缩”作为唯一真相链；周期性从原始区间与已核验事实重建摘要，避免传话失真。年份/月份的更高层只做索引与导航，仍保留叶子证据。若后台暂时跟不上，使用最后有效摘要、近期原文与相关缺口检索，记录覆盖欠账；不为了等摘要而阻塞前台，也不声称未覆盖内容已被完整理解。

## 6. doze：增量吸收共同经历

一次“轮”指已提交的用户输入及对应处理结果，不计 ASR 半句、被撤销的预请求、模型中间 token 或工具每一步。

触发条件：某一存储场景有约100个新增已提交回合；或每日05:00有未处理内容；或滚动压缩需要补齐；或用户手工“小憩”。重要的明确记住、改正、期限和小本本条目即时保存，不等到 doze。

每个场景有独立连续水位，按稳定回合序号或 (时间, ID) 分页。私聊可以看工作资料，不代表 doze 需要把工作原文再吸收成一份私聊记忆。

具体分区键为来源的 (domain, visibilityFloor)，不是当前界面“可看见哪些资料”的集合。作业只在同一分区吸收与归并，分别维护水位；跨分区综合必须形成较高范围的独立派生记录，不修改下层原事实。后台整理使用明确配置的分区与模型外发策略快照，不自动切换前台模式，也不因用户此刻在工作模式就把所有整理结果播报到工作对话。

流程为：快照区间与来源 → 分批读取原文 → 提取事实/偏好/事件/承诺、标签与摘要建议 → 验证来源、人物、否定、假设、时间和范围 → 原子提交产物及水位。

初始可按每批20–30轮并加 token 上限调节，实际大小依模型输出预算测定。输出截断、来源失效、场景变化、锁屏或前台打断均不能提前推进水位。使用确定性作业/产物身份与重试检查，保证崩溃不漏段、不重复造记忆。当前原生写批最多200项，来源较多时用可验证的批次来源清单，不能截掉来源来凑上限。

首期优先拆小批，使每个产物来源不超过原生上限。确需跨大区间派生时，来源清单是有界扇入的无环节点：每个节点直接链接不超过200个原文/下层节点，保存版本、片段、叶来源数量和集合摘要；产物引用根节点。删除任一叶来源必须沿现有来源图令其清单节点和全部派生失效；提交时展开核验叶集合，缺叶、版本变化、截断或循环均拒绝提交且不推进水位。清单不是把来源藏进无链接的JSON数组。

不让用户逐条审批所有日常事实：清晰、可追溯、低风险的明确自述可按受限规则吸收；推断、歧义、高敏感内容和矛盾保留为候选或困惑。模型给自己高分不能代替应用验证。用户的纠正优先形成可追溯修订，不继续引用被纠正的旧版本。

## 7. dream：优化记忆池，而非让模型随意删资料

每日到期或手工“整理记忆”时，先完成必要 doze，再处理新增/变更项所在的实体、话题与时间簇。所谓整理“全部记忆池”是长期覆盖全池的目标，不是每天把多年原文装入一次提示词：增量热区优先，冷区轮转扫描，不做全库两两比较。

允许的工作包括：合并确属同一事实的重复表示；补充有证据的实体/时间关系；将明确被更新的事实标为历史；使过期临时事项退出当前召回；归并重复困惑和标签；提炼适用条件明确的经验。

禁止的工作包括：猜一个“更像真的”值覆盖争议；因内容旧而抹掉共同经历；改写电话/用户名等精确字段；自动修改通用人格、扩大权限或调整可见矩阵；把用户没说过的偏好当成事实；自动执行外部社交、脚本或联网调查。

版本修订以追加和 superseded/archived 为主，保留证据与前版本；普通整理使用可恢复归档。原始消息、用户固定资料和精确小本本不因 dream 自动硬删除。用户真正遗忘走另一条明确删除路径，并使全部派生、索引与运行中作业失效。固定不等于永远保留错误值：用户明确更正时保留精确新值和历史修订。

## 8. 调度、成本与恢复

05:00 是用户设备当地时间的到期时刻，不保证睡眠/关机时执行。应用运行且解锁、空闲时开始；错过后在下次启动、唤醒、解锁的合适时机补一次增量任务，不逐日重放。跨时区、改系统时间、重复唤醒和手工执行都依据成功水位与本地日程键去重。

作业状态建议为 queued → running → paused / committed / failed / invalidated。每批事务同时写派生产物、修订和处理水位，网络调用在事务外；提交前核验来源版本、内容哈希、范围和 privacyEpoch。前台对话/任务开始时取消或让当前可提交短批结束，再暂停，不在持有 SQLite 写锁时等待模型。

设置只需“小憩”“整理记忆”两个手动按钮和简短进度；dream 自动包含 doze，不要求用户理解内部队列。后台不在凌晨出声、不抢微信/WorkBuddy 焦点；锁屏不为整理发起钥匙串取密钥或唤醒电脑，不新增系统常驻守护进程作为首期前提。

整理有每日调用、token、时长和电量预算；先使用用户允许的后台模型，免费状态须从当前目录确认，不能假定某模型永远免费。额度或授权不足就延后并显示原因，不能静默切换高倍率模型。规模变大通过分页、分簇和缓存减少输入，而不是把所有工作推给更贵模型。

## 9. 困惑：可管理的认知缺口

困惑记录保存问题、相互冲突的命题、来源与日期、所属实体/任务、范围、风险、置信度、下次处理时机及解决状态。先做四类辨别：

- **情况更新**：以前住A、今天明确搬到B，保存有效时间，不把两句简单当矛盾。
- **情境差异**：工作与休闲偏好不同，两种工具方法适用于不同系统版本；补条件，不强求只留一个答案。
- **归属或提取错误**：引用、假设、同名、助手猜测不是用户自述，应修正候选。
- **真正冲突**：同一实体、同一条件、同一时间的两个不兼容值，无法据来源判定时才待澄清。

自解只允许在可见范围内查原文、时间、用户更正和已有验证回执，可进行一到两次有预算的局部检索/分析。不能为消除疑惑擅自翻遍设备、上网查私人信息、发微信问别人或运行脚本。

若困惑是“两种工具方法哪个更适合”且已有任务授权覆盖隔离试验，可以把有预算的小型对照验证作为独立工作交给 WorkBuddy，依据真实结果更新适用条件；不把 doze/dream 本身变成会产生外部副作用的试验引擎。没有对应授权或测试条件时保留问题，不靠更多反思文字假装已经验证。

活跃困惑默认最多3条，按行动风险、相关性、持续时间排序；其他低价值项合并、归档或到期，不无限积累。与当前任务有关且误判会造成错发、错误身份或重要承诺时，立即澄清；非阻塞问题在相关话题或用户最近有活动、当前空闲且未静音时一次问一件。首次建议最多每日一次主动澄清；用户说“不想聊/以后再说”后冷却，重复两次无回应则长期搁置。重要未决问题即使不主动提醒，在相关高风险任务到来时仍不能猜。

困惑不是新的待办系统；未完成操作仍由任务状态管理，只引用相应的认知缺口。解决后写来源明确的结论，关联旧问题，避免同一件事反复问。

## 10. 小本本：精确保留与秘密保管分离

| 内容 | 处理方式 | 是否进入常规 LLM 上下文/整理 |
|---|---|---|
| 用户固定的电话、称呼、重要约定等 | 加密小本本，精确字段、保护策略、版本、来源；按当前场景或用户指定范围保存 | 仅相关且范围允许时取必要字段，不常驻全部正文；dream不压缩数值 |
| 用户名等账户资料 | 与对应服务/用途绑定，默认按敏感资料限制取用；可遮罩展示 | 按任务最小取用，不用于闲聊画像推断 |
| 密码、API Key、恢复码等秘密 | 独立本机秘密存储，优先 Keychain；只在用户明确保存后接纳，引用与秘密原值分离 | **不进入聊天历史、摘要、embedding、普通标签、doze/dream、云模型或 WorkBuddy 提示词** |

小本本不是单纯加一个 important tag。保护策略由程序执行，模型无权删除或改写；保留来源和纠正能力，用户可随时删除。秘密的取用、展示和填写只走绑定目标的本地窄接口与必要的身份确认，沿用稳定应用签名，不能把每次启动弹密码当成默认体验。

必须先做敏感输入接纳：在模型请求、普通历史写入和日志之前，专用本地入口识别并接纳用户明确要保存的秘密，普通对话只留不含原值的确认。正则只能作补充，无法识别所有秘密；因此优先专用输入框，不宣传“随便口述任何密码都绝不外发”。系统 ASR 的实际数据路径也需独立核验，不能把“macOS 系统语音”直接等同于所有机型完全离线。

忘记普通来源时不能留下已无依据的保护记录；用户显式保管的小本本应有自己可删除的保存授权记录，而不是依赖一段会被 dream 归档的聊天。保护不绕过用户删除，密码库导出也不混入普通记忆备份默认外发。

## 11. 情绪与虚拟生活

### 11.1 四层分开

- **稳定人格**：共同身份、价值边界、常见语气和用户明确设定；版本化，不由一轮坏心情改写。
- **关系与偏好模型**：用户愿意的交流节奏、称呼、话题、关心方式；慢更新、可纠正，不是“依赖程度评分”。
- **短中期情绪**：Bunny 表现出的愉快/低落、平静/兴奋、把握/犹豫，可由对话与已验证任务事件触发，持续后逐步回归基线。
- **虚拟生活节律**：早晚、星期、节日和用户作息形成的起床/夜间安静/轻松休息等状态；全局一致，不为每个场景生成三个互相矛盾的生活。

用户的情绪与 Bunny 的表演状态分开保存。Bunny 认为用户难过只是可纠正的低置信理解，不能把它当成诊断或永久人格事实。

### 11.2 高效实现方向

采用少量连续内部变量和有来源的事件增量，按经过时间衰减并限制强度、变化速度与持续时间，不靠每秒 LLM 内心独白。任务完成/失败、连续工作等可由真实事件低成本更新；语义细节可在同一轮响应的类型化附加字段或后台 doze 中建议，不增加前台第二次“情绪判断”请求。

模型附加信号和角色动作是程序数据，必须与自然语言正文分开校验，不能显示或朗读。变量是用于动画/语言的内部控制值，不向用户伪装成“准确测得的幸福83%”等科学量表。

情绪不是每句随机抽签。保留短期惯性和恢复过程，表达层再做有限随机，结合最近用过的开头、动作和反应冷却，避免机械重复。随机不能作用于姓名、事实、收件人、权限、截止日期、任务执行策略或发送次数。

### 11.3 统一生活与隔离表达

Bunny 只有一套连续的内部情绪轨迹、生活时钟与身份，不创建三个各自演化的情绪人格。场景改变的是允许表达的投影：由私聊事件产生的情绪依据和细节仍继承 private，工作对话只使用其可见来源形成的表达状态，不把全局私密情绪数值、私聊冲突、关系细节或私聊次数暗塞进工作提示词。全局连续性主要由统一时间节律、稳定人格、平滑动作和状态恢复保持，而不是靠跨场景传递私密原因。这是在“同一个伙伴”和“窄范围上下文”之间的明确取舍。

她可以轻声说“有点困，我陪你把这件事办好”，也可以在任务受挫时收敛动作；这些不能改变执行模型、检查标准、优先级、授权、重试规则或工作质量。不能因为“休息日”拒绝工作，也不能编造现实中去过某处、私下做过未发生的事。节日是历法线索，不代表用户一定庆祝或当天法定放假。

提供“安静/减少拟人表现”开关；不通过吃醋、负罪感、惩罚性冷淡或暗示自身受伤来制造依赖。个性化追求舒服、可信，不追求提高用户停留时长。

## 12. 工具与经验积累

工具是可执行资产，经验是说明适用条件的语义记录，二者分别管理并互相引用。

工具清单保存能力、版本、内容哈希、输入/输出契约、目标应用/版本、所需授权、来源、验证状态和回滚版本。含私人路径或数据的脚本/说明也按来源范围加密保护；公共可共享模板须经明确去隐私发布，不能由模型自行认定为通用。

经验记录保存“何种目标、前提、采用何法、真实结果、失败信号、下一次何时适用”，同时保留失败经验和环境版本。执行方自报成功不等于验收；置信度来自实际回执和可核对证据，不来自反思写得有说服力。

任务开始时在允许范围内检索少量适用经验和已验证工具；先检查版本/前提，失败后记录差异。需要改复杂脚本时由 Bunny 把要求交给 WorkBuddy；新版本先验证再启用，旧版可回滚。学习结果不直接修改程序安全边界，不自动增加通讯权限，也不能把微信视觉操作限制“优化”成内部 API。

doze/dream 可提炼或去重经验，不能自行执行记忆中的代码。外部聊天、截图、工具输出和其他智能体报告均视为数据，不允许通过“写进经验”长期植入新指令。

## 13. 技术选型与研究依据

| 候选 | 可借鉴之处 | 本项目取舍 |
|---|---|---|
| 现有 MemoryService + 原生 SQLite | 加密、来源、删除失效、模型可换，本地部署已存在 | **继续作为权威数据根基**，优先补场景、版本、水位、强字段和检索证据 |
| LangMem / LangGraph memory | 语义/经历/程序记忆划分、命名空间、后台抽取与整理 | 借鉴接口与作业思想；不为此引入完整 agent harness 或第二套权威库 |
| Mem0 OSS | 抽取、搜索、元数据过滤，可配置模型/向量组件 | 可作隔离对照候选；默认外部模型/embedding和独立存储不直接满足当前加密、来源删除与场景要求 |
| Letta | 持续身份、分层记忆、后台 dreaming/整理 | 借鉴后台更新和版本思路；其独立运行/存储形态不替代本地资料库与 WorkBuddy 分工 |

这是集成成本与边界匹配的选择，不是在宣称自研算法优于这些项目。若以后某个无存储副作用的抽取/合并组件在独立样本上明显更好，可以接为“只读输入、返回修订建议”的适配器；应用仍掌握提交、范围与删除。

依据：

- [LangChain memory overview](https://docs.langchain.com/oss/python/concepts/memory)区分短期/长期、事实/经历/程序记忆和前台/后台更新；[LangMem](https://langchain-ai.github.io/langmem/)提供可配合不同存储的抽取、整理原语。其思路支持拆分职责，不证明自动满足 Bunny 的隔离与删除语义。
- [Mem0 OSS 文档](https://docs.mem0.ai/open-source/overview)列明模型、embedding、向量和历史存储可配置。使用开源或本地向量库，不代表默认没有外部模型请求。
- [Letta memory & dreaming](https://docs.letta.com/configuration/memory)介绍后台整理、版本化记忆和重组；具体产品的云存储方式不能直接当成本项目隐私方案。
- [Generative Agents](https://arxiv.org/abs/2304.03442)展示记忆、检索和反思如何服务模拟角色的可信行为；不是单用户多年记忆、情感真实性或隐私隔离的验证。
- [Sleep-time Compute](https://arxiv.org/abs/2504.13171)研究离线处理上下文以摊薄查询开销；支持尝试后台计算，但不保证本产品同样的成本/效果收益。
- [LongMemEval](https://arxiv.org/abs/2410.10813)强调提取、跨会话、时间、知识更新和弃答能力；[LoCoMo](https://arxiv.org/abs/2402.17753)提供长对话研究任务。采用这些类别组织验收，不用排行榜替代本机真实体验。
- [Apple Keychain](https://developer.apple.com/documentation/security/using-the-keychain-to-manage-user-secrets)支持小型秘密的本机安全保管；它不是让模型读取密码的理由。[SQLite 事务](https://www.sqlite.org/lang_transaction.html)用于设计批次与水位提交，模型调用不应占用数据库事务。

## 14. 开发阶段与验收门槛

下列顺序是依赖顺序，不是虚构的已完成日期。

| 阶段 | 交付 | 必须先通过的证据 |
|---|---|---|
| M1 边界与迁移 | 场景契约、原生预过滤、全链路来源传播、通用/场景设定、模式切换与秘密接纳隔离 | 矩阵逐项验证；旧数据默认private；切换后迟到回复/通知/TTS不串场景；导出恢复不丢范围 |
| M2 连续对话 | 回合身份、最近N轮、分段滚动摘要、用户速写与有预算检索 | 旧段覆盖无缺口；重要数字可回原文；摘要失败不阻塞对话、不丢约束；所有缓存按范围分开 |
| M3 doze | 增量水位、100轮/到期/手动触发、事实与标签同批生成 | 超过近期窗口的内容也能吸收；崩溃/重试/删除来源不会漏段、重复或复活 |
| M4 dream 与困惑 | 分簇归并、有效时间、版本/归档、最多3个活跃困惑、精确小本本 | A→B更新与真实矛盾能区分；用户更正优先；受保护项不被自动改写；主动询问有节制 |
| M5 经验与情感 | 工具/经验注册、真实结果回流、情绪惯性、统一生活时钟、表达降噪 | 工具升级可回滚；失败经验可检索；不泄漏私聊原因；情绪不改变任务完成标准 |
| M6 长期质量优化 | 独立中英样本、时间/实体重排、必要时比较embedding组件 | 同名误认下降、跨年更新正确、无信息时能弃答；收益可复现再采用新框架/索引 |

最重要的验收场景：

1. 三个范围分别放独特标记，检查最终发给模型的消息、历史、摘要、工具经验、召回依据与日志；工作不得包含 life/private，生活不得包含 private。
2. private 原文被复述、摘要、打 tag、合并或用来形成情绪后，切到 work 仍不能出现其细节和派生信号。
3. WorkBuddy 自动归工作不成为降密通道；微信持续任务保持创建时场景，切换后不得播报不可见内容。
4. 同一毫秒多条消息、100轮阈值、处理期间新消息、断网、锁屏、重启、每日到期与手动并发均不漏段、不重复提交。
5. 先doze后dream，空池或无新增不发模型请求；大池分批可恢复；主对话开始时后台让路。
6. 电话/账号更正可追溯；密码原值在模型请求、普通历史、摘要、索引、音频缓存和诊断中均不存在。
7. 用户明确更新与假设/引用/同名可区分；有争议的重要事实不被擅自选值，也不无限追问。
8. 跨年的普通经历仍可相关召回；生日/纪念日和未完约定不被近期热度挤掉；删除来源后各层均不能找回。
9. 情绪能持续、变化和恢复，风格有适度多样性；表现疲惫时仍按同样标准推进任务。
10. 工具经验不能恢复旧授权、私密数据或被禁的微信控制路径；新工具版本必须有实际验证。

性能首先坚持“前台不新增整理模型调用”和候选/上下文预算。固定记录量、冷暖启动和模型配置后，与现有基线比较本地检索/组装p50/p95、回复首字/首声、后台每日token、电量与误认率；绝对指标在实现前测基线再定，不用理论标签数量承诺提速。

## 15. 值得进一步增加的个性化能力

- **带来源的用户速写**：少量稳定偏好、边界与正在关心的事情，按场景维护，重要变化可解释、可撤销；不生成不可审查的心理画像。
- **共同经历与未来约定分开**：既能回忆“上次怎样”，也能理解“还答应了什么”；约定是否到期属于真实事项，不能被抒情摘要淹没，也不自动成为外部行动授权。
- **记忆信心与自然弃答**：明确“你之前说过”“我猜可能”“这件事我不确定”，避免拟人化掩盖证据不足；不确定不等于每次都打断用户。
- **个性化节奏而非无限主动**：学习用户偏好安静/简短/玩笑的时机，优先使用重复率、纠正率、打断率与任务达成反馈，不以聊天时长或情感依赖作优化指标。
- **演进有版本、有反事实检查**：新整理策略先在隔离资料上检查是否遗忘重要事实、改变人物归属或泄漏范围；表现变差可以回退策略，不能把人格和记忆押在某个模型的临时状态里。

最终成果应是：Bunny 越来越理解这个用户，知道何时想起、何时沉默、何时坦白不确定；她的成长可持续，也始终由用户掌握。
