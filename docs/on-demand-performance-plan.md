# Bunny 按需表演开发计划

日期：2026-11-12
状态：2026-11-13 已获授权并实现；开发版文字调度、实际动画及文字打断已验收，详细结果见 [验收记录](on-demand-performance-validation.md)。真实麦克风插话仍需实机语音复核。

实现采用统一调度入口，兼容芭尼等VRMA形象和兔兔的剧场动作。表演实际状态连同当时的形象名称进入后续对话上下文，并沿现有身体状态持久化。

保留现有普通对话动作、事件动作和空闲随机动作。对话 LLM 判断这些表达不够用时，自行写一两句表演要求，额外调用一次 LLM，从当前形象的完整精简目录中选动作，并自行决定是否说话。新输入沿既有打断入口取消整次表演，迟到结果不再执行或播报。

## 1 行为与范围

- 大多数对话保持原路径，不增加模型调用。额外表演由对话 LLM 按语义决定，不用关键词、固定命令或程序随机触发。
- 主回复可以有文字，也可以为空；空回复带有效表演请求仍表示正在回应。单独的空回复和 `skip` 保持原有静默语义。
- 表演调用只接收固定提示词、编号动作目录和对话 LLM 自配的简短要求。不自动追加自我叙事、记忆、Summary 或完整聊天历史。称呼、语气、相关情景及想留到表演时说的话，由对话 LLM 按需要写进要求。
- 表演正文仍按现有设计增量显示气泡、首个自然句进入统一 TTS；不新增等待动作开始或结束才播放的台词队列。
- 首期一次选择一个动作或库中已有的完整组合动作；不增加临时编舞、多动作规划、速度控制、桌面行走或新的长期任务系统。
- 复用当前对话模型和传输配置，不新增模型设置页。表演用途不执行软件、修改记忆或递归发起下一次表演调用。

## 2 对话与表演协议

### 2.1 对话 LLM 发起表演

在现有 `kind: chat` 回复中增加可选字符串字段 `performance`，表示本次表演要求。默认省略，保持普通回复协议和随机动作路径。

```json
{"kind":"chat","text":"","performance":"向主人展示一个合适的跑步动作。可以在展示时自然接话，不必先口头答应。"}
```

示例只说明协议，不固定 Bunny 的台词。要求由对话 LLM 自己撰写，通常一两句，程序只做类型、长度及来源检查。已有 `dialogue-v2` 外层认知协议保持不变。

主对话提示词说明：普通分类动作足够时沿用原方式；需要具体表演时提交语义要求，不能因为本轮没有具体动作 ID 就断言不会。身体上下文保留普通可选分类及必要状态，不再用关键词命中的十条具体动作限制她对表演能力的认识。普通分类清单只列当前确有合格随机候选的分类；运动、跳舞等能力仍可通过表演调用查询和选择。

主回复使用现有分类动作时，具体变体继续由程序随机选择。兼容旧动作标签的解析，不鼓励主对话编造具体 ID。`performance` 只能附在聊天回复中；`skip` 或正式任务操作不能顺带携带它，避免一份输出含有多组执行意图。

### 2.2 表演 LLM 返回编号和正文

```json
{"motion":17,"text":"自然生成的可选正文"}
```

- `motion` 为目录中的整数编号；`0` 表示没有合适动作。`text` 可以为空。
- 不返回文件名、路径、分类 ID、理由长文、条件台词或下一轮调度请求。
- 固定提示词要求依据语义选动作，必要时选择并说明接近的表达；找不到时如实表达当前目录的局限，不套用固定道歉。
- 表演正文是正常对话输出，避免提前声称动作已经完成，避免复述主回复中已说过的内容。主对话需要交代的语气和说话时机应写进 `performance`；程序不再另行补配一套人格或对话摘要。

表演输出增加窄协议校验及流式正文适配，共用现有脱敏、自然句切分、气泡和 TTS 通道。编号和其余字段不显示、不朗读。完整协议校验通过后才解析和派发动作；流式正文按现有规则直接展示，不等待动作回执。整包返回的引擎先校验再展示，不伪装流式。

因此，文字与动画尽量并行，但首次加载动画可能晚于第一句话。播放失败作为实际失败记录和反馈，不能把已经说过的正文改写成成功回执。已展示正文后发生协议错误时，不从坏输出中提取动作，不重放正文；沿用现有有界错误处理。

### 2.3 同一轮回应的衔接

主回复完成协议校验和语义接纳后即可开始表演调用，首次回复的 TTS 可以同时播放。无需等第一段话念完。空主回复直接进入表演调用，不创建空气泡或空 TTS。

表演仍归属原对话轮次，沿用其取消信号和来源检查；主回复产生后不提前执行 `turn.finish()`、`voiceTurn.complete()` 或释放整轮控制器。表演决定与必要派发结束后，再按原规则收尾。模型等待是异步的，新输入仍可立即抢占。实际动作播放由播放器继续管理，不占住对话轮次直到片段结束。

有效表演请求接纳后，通过通用对话调度器的 `consume()` 确认本轮输入已被解释处理，防止取消后再次合并进下一轮。该确认不结束当前轮次、不标记表演成功；主轮次仍可等待表演结果并随时取消。普通尚未被处理的输入保持原有保留和合并机制。

正常收尾后，宿主和渲染器仍保留正在播放的表演身份，供后续输入取消；不能只依赖已经释放的 `activeThought`。正常轮次收尾不等于用户打断，不应中途取消已经合法启动的片段。

首次正文和表演正文作为同轮的两个有序输出片段进入现有 TTS 队列。沿用播放代次、消息 ID 和 `responseOwner`，防止第一段的迟到结束回调、最终气泡或 `think: off` 覆盖第二段。切换到表演用途时不调用停止朗读，也不重新触发一套思考动作。

两段实际正文沿既有聊天记录机制归入同轮，空段不写成一条助手回复；表演要求作为内部调用参数，不伪装成新的主人消息。动作历史继续依据实际开始回执更新，不把模型选择本身记成已执行。

## 3 精简目录与编号映射

每次表演调用从 `AvatarCatalogRouter` 获取当前形象目录，形成不可变快照。VRMA 和数据形象包共用这一入口。

发给模型的每条信息采用以下形式，编号只在本次调用内有效：

```text
1 鼓掌
2 原地跑
3 坐着举手 坐姿
4 看手机 需道具
```

默认保留编号和名称；名称不足以区分时才保留简短含义，附加必要的姿态、转场、道具或循环条件。省去内部 key、URL、来源、文件名及重复说明。当前形象、姿态和道具可用情况作为目录的简短表头提供，不额外加载聊天资料。相同名字可保留为不同编号的变体，不按名字合并。

目录覆盖当前形象全部已启用且未删除的动作，不因 `autonomous: false` 或现有关键词分数隐藏运动、跳舞等表演。真实执行条件仍须标明：例如外部道具未具备时不能选择需要道具的动作。

宿主保存 `编号 → 实际动作 key` 映射以及本次形象、目录版本和轮次身份。返回值只接受 `0` 或范围内整数，不按名字猜测，不纠错到相邻编号，不用更新后的列表重新解释旧编号。

动作禁用、删除、重新导入或形象切换使相应快照失效；执行前复核当前动作状态。无关设置变化不应取消表演。若完整目录超过实际模型输入预算，应报告目录准备失败，不能静默截成前若干条再声称查过全部动作。

当前 235 条动作按上述字段直接精简，约 4900 字符；项目保守估算约 7300 token，实际值取决于描述压缩和模型分词。实现时以最终目录测量，不把内部完整对象直接发给模型。

## 4 新输入与迟到结果的取消

取消起点沿用既有 `asr-input-pipeline → onAcceptedPartial → interruptDialogue`，不新增声音大小、关键词或静音时长门槛，不等待新话语最终定稿。键盘新输入、用户停止以及场景、形象、锁屏等既有失效事件同样覆盖表演。

一次取消必须同时处理：

1. 中止表演模型请求，并让本轮身份失效。提供方忽略取消仍返回时，丢弃其全部结果。
2. 停止该轮已进入合成、队列或播放的语音；迟到正文不得再显示气泡、进入 TTS 或形成新承诺。
3. 撤销主进程中的待派发动作，并向渲染器传递取消身份。动作已进入异步资源加载时，在加载后、转场后和真正播放前再次核对；清除排队片段，不让旧请求漏播。
4. 已开始的额外表演平滑退出到与实际姿态相符的待机。若正在坐立转场，使用现有转场机制到达稳定姿态，并取消尚未开始的目标片段；不硬重置骨架或伪造站坐状态。
5. 保留已经发生的动作和中断记录，迟到回执不能恢复表演、覆盖新动作或取消新的轮次。

不将取消钩子简单放进所有 `stopSpeaking()` 调用：正常播放收尾或同轮两次调用之间的内部切换，不能误杀自己的表演。主进程以原轮次和请求身份约束输出；渲染器使用该次表演身份约束加载、转场和播放回调。

后续语音即使被判为环境话语或最终没有回复，也不复活已经取消的旧表演。既有调度器保留未完成主人输入的机制保持有效；若需要继续，必须由新的有效对话决策重新提出。

## 5 与现有随机动作的协调

采用现有播放器中的轻量占用状态，不建设新的动作队列。默认路径和额外表演共享执行入口、姿态和动作回执。

| 情况 | 身体表现 |
| --- | --- |
| 普通对话，没有表演请求 | 原分类随机变体、情绪配动作、思考、问候、任务事件及空闲待机继续运行 |
| 表演 LLM 正在选择 | 原普通动作和待机继续按现有条件运行，无须提前锁住身体 |
| 合法表演开始加载与播放 | 为该次请求保留身体，普通随机、思考、朗读回中性、任务庆祝等低优先事件不覆盖它 |
| 找不到动作，只返回正文 | 正文正常显示和朗读，身体继续普通模式 |
| 表演完成、失败或取消 | 释放占用，恢复当前姿态和工作状态对应的待机及原随机节奏 |
| 主人手动选动作或主动触摸交互 | 用户直接操作优先，取消旧表演占用及其迟到结果，沿原入口执行 |

同轮主回复若带普通分类动作，可以在表演选择期间先播放；额外表演就绪后接管，不再为同一个额外动作额外随机挑一条。低优先事件在占用期间不排队，结束后不补播过时动作。语音内容不受身体占用阻塞。

当前空闲逻辑主要是有概率轮换待机，并非随机遍历全动作库。本次保留其节奏和范围，不扩张成无人要求时随机跑步或跳舞；同时让对话 LLM 有权在语义需要时主动请求这些动作。

明确区分普通随机候选与具体表演选择。保留 `autonomous` 对原随机范围的作用，为经过有效表演决策的具体编号提供明确执行用途，不通过冒充 `manual` 或批量修改素材标记放开能力。该用途允许使用现有坐立桥接，姿态由实际转场回执更新；道具、禁用和当前形象检查继续生效。

普通一次性动作按现有片段播放，已有组合动作整体播放。表演选中循环片段时使用统一的短时展示，首期暂定 4 秒后平滑退出；原待机和主人手动预览的循环规则保持原状。该参数在真实视觉验收时确认，不为模型增加循环次数或时长字段。

主进程发起的动作及渲染器本地自动动作都必须检查占用，覆盖 VRMA 与数据形象包。复用实际开始回执和播放器结束事件，补齐结束、失败和中断的身份关联；这些记录只说明播放器状态，不证明姿势自然或表演效果合格。

## 6 实现分工与步骤

| 步骤 | 主要入口 | 交付 |
| --- | --- | --- |
| 1 协议和目录 | `reply-format.js`、`dialogue-actions.js`、`reply-stream.js`、`config.js`、动作目录模块 | 可选表演要求、空回复语义、编号快照、专用输出校验；普通回复保持兼容 |
| 2 表演调用 | 新增窄用途 `performance-request.js`，复用 `llm.js` 和现有正文呈现能力 | 固定提示词与精简输入、一次额外调用、取消和有界协议恢复，不复制 TTS 或自我系统 |
| 3 同轮衔接 | `index.js` 的回应、流式输出和既有打断入口 | 主回复与表演连续处理、消息与语音归属、空首次回复、整轮收尾 |
| 4 身体执行 | `embodiment.js`、`motion-library.js`、`avatar-action-catalog.js`、`avatar-catalog-router.js`、`renderer/app.js` | 具体表演用途、姿态桥接、占用与取消、加载后失效检查、循环展示及实际回执 |
| 5 验收和文档 | 相关测试、`AGENTS.md`、`docs/architecture.md` | 离线竞态覆盖、生活场景实机验收、同步新增机制与实测边界 |

前四步作为同一项能力贯通后验收，不发布仅增加模型调用而取消或执行链路尚未接通的半成品。协议、调度、执行与取消已接通，开发版验收结果及剩余边界见验收记录。

表演调用初始总时限为 20 秒，输出保持简短；主对话既有模型时限保持原值，整轮总预算显式包含按需增加的这一段。复用有上限的格式修正，修正共享时限，已显示或朗读的正文不得重复；不自动重试网络请求或循环再调度。超时或协议故障记录为本次调用未完成，不当成动作不存在；过期故障静默丢弃。

本次只扩展语音基线已有取消和呈现入口，不修改 ASR、AEC、VAD、分段、打断门槛、热词或 TTS 参数。实现前后对受影响的空回复、插话和语音队列完成针对性回归及真实语音验证。

## 7 验收条件

| 场景 | 必须观察到的结果 |
| --- | --- |
| 普通分类表达足够，主回复未请求额外表演 | 仅一次对话调度，普通随机动作不退化 |
| 跑跑看、跑步、语义改写及合成的含蓄运动请求 | 对话 LLM 自主提出表演要求，额外调用能看到完整目录并选中合适编号；不能依赖关键词特例 |
| 首次回复为空，第二次有动作或正文 | 正常发起表演，不被判为 `skip`，无空气泡和空语音 |
| 首次有正文，表演较快返回 | 两段按统一输出顺序朗读，不互相打断、重复或由迟到 UI 回调覆盖 |
| 表演正文为空，或确无合适动作 | 前者正常执行动作；后者自然说明或保持安静，均不伪造动作成功 |
| 模型等待中、返回边界、资源加载中、坐立转场中收到新话语 | 旧表演取消，未开始动作不再启动，旧正文及 TTS 不再出现；真实回声沿原机制过滤 |
| 模型、加载或语音回调故意忽略取消并迟到 | 不执行旧动作、不重现旧气泡、不串入新语音、不覆盖新轮状态 |
| 对话轮次已收尾，额外表演仍在播放时收到新输入 | 仍能定位并取消该次表演；正常收尾本身不会误取消它 |
| 目录重排、动作禁用删除或形象切换 | 不串号、不把同名动作误认为同一条；失效快照不执行 |
| 普通随机、任务事件、朗读回中性与表演竞争 | 表演期间不抢动作；释放后普通模式恢复，无排队补播 |
| 主人手动选动作、停止或主动触摸 | 用户控制及时生效，表演不能迟到抢回身体 |
| 坐姿选站姿动作、循环动作、数据形象包 | 按真实姿态桥接，循环有界退出，所有形象遵循同一取消和编号语义 |
| 无效编号、坏协议、调用超时、动作文件加载失败 | 不猜动作、不无限重试、不把暂时失败记成永久不会；新对话继续正常响应 |

离线重点覆盖协议和异步竞态；真实模型验收观察是否恰当地少用额外调用，以及能否按不同语义自主选择。记录主对话次数、额外调用次数、目录大小、选择耗时、实际开始与结束、取消后迟到结果是否被丢弃。不得把合成回执测试当成动画已经播出的证据。

实机验证先确认生活场景，使用合成对话，不读取私聊。先通过统一本机控制接口测试，再检查 UI 和真实语音；若需要补充表演调试工具，加入同一 MCP 注册入口。截图沿既有 CGDisplayStream 路径，使用安全测试画面，不调用目标软件接口。

## 8 审核要点

1. 普通随机表现维持默认，额外表演只由对话 LLM 按需发起。
2. 表演输入仅为固定规则、编号目录和一两句自配要求；首次允许空回复。
3. 表演正文收到后照常显示和朗读，不设置等待动画结果才说话的独立队列。
4. 新输入取消整轮额外表演，覆盖模型、正文、语音、动作加载与迟到执行。
5. 首期每次一个动作或已有组合动作；循环片段按完整周期短时展示。

## 9 周期与单次表演

表演重复策略独立于资产原来的 `loop` 处理标志，避免修改现有待机、锁脚与动作烘焙行为。`performance-playback-policy.js` 默认尊重已标记的周期动作；未知动作默认单次。11 个已核对来源及旋转接缝的走跑片段在 `performance-loop-overrides.json` 按 key 与 sourceId 配置周期；个人替换资源不继承这些例外。短时长或首尾相近只用于辅助审查，不能据此把侧步、坐立或完整故事自动当作循环。

动作库配置支持 `performanceMode: auto|once|cycle`，形象包支持可选 `once|cycle`。姿态转场及完整组合序列仍单次完成。`tools/audit-performance-loops.cjs` 只读输出实际时长、旋转接缝和文件摘要，便于资源改变后的复核。

周期表演由播放器读取实际片长，重复 `ceil(4000 / clipMs)` 个完整周期，至少1、最多128；长片段完整播一遍。半秒原地跑因此播放8次，共4秒。VRMA与两种数据形象运行时共享有限次数语义，最终只产生一次开始/结束；普通随机与手动原有播放行为保持。实际周期数和时长随身体回执进入历史、后续上下文及持久状态，完成看门狗使用实际总时长。

## 10 对话自主变身

每轮身体上下文提供全部已安装形象的编号、名称、类型及自定义标记，覆盖七个官方形象与个人形象。主对话沿现有动作协议返回 `avatar_select` 整数编号及可选短回复，直接调度本地身体能力；无需再增加一次选七个名字的模型调用或正式任务。一次变身与一次表演分别由对话自主决策，不引入编舞或连锁任务队列。

`avatar-capability.js` 冻结编号目录，执行前复核目录身份，再复用UI相同的 `applySettings`，有界等待当前形象真实 `body-ready`。确认成功后才显示和朗读本次变身回复；下轮身体状态提供新形象，已发生的旧形象表演仍保留其友好名称。选择当前已就绪形象不重新加载。

新输入取消同一对话轮次。尚在加载且仍归该请求拥有的选择回退旧形象；代次与形象设置修订号防止覆盖后续手动选择或切走又切回的操作。已经实际就绪的变身保留为发生过的效果，取消只抑制旧轮后续输出。目录失效、加载失败或超时均不能播报成功。
