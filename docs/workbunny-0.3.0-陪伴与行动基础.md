# workbunny 0.3.0：陪伴与行动基础

2026-10-25。依据 [concept.md](../concept.md)，本批按[自主迭代路线](workbunny-自主迭代路线-2026-10-25.md)实施。当前是长期产品目标的第一批基础升级；真实桌面验收尚因锁屏受阻，不把接口存在当成任务完成。

## 已实施的产品变化

| 部分 | 本批行为 | 边界 |
|---|---|---|
| 对话记忆 | 从最多 24 条 JSON 消息改为可增量积累的 SQLite 资料库，保存时间、来源与状态 | 不宣称已经验证数年生产运行；单次文字对话上限 12,000 字，近期上下文按预算截取 |
| 记忆形成 | 明确的“记住”、自述偏好、名字与生日可直接形成有来源记忆；每几轮后台整理候选和摘要 | 模型推断候选待确认，不能悄悄成为用户事实；后台整理不在回答之前串行执行 |
| 检索与上下文 | 中英文分词、中文二元词、主题别名、重要锚点、日期，结合近期对话和分段摘要 | 当前为本地词法检索，尚未加入 embedding；语义改写非常大的问题可能漏召回 |
| 纠正和遗忘 | 管理页可查看来源、确认、修改、删除；删除传播到派生摘要和助手回复，旧后台作业不能写回 | 为避免改写后的旧事实复活，采用保守来源链删除，可能同时移除较多关联助手回复；无关用户原文保留 |
| 人格与情绪 | 人格设定单独修订；当前时间、星期、时区、农历节日、最近互动时间、虚拟心情参与表达；语气有受约束随机变化 | 虚拟表现状态不等于真实生理或离线生活，不编造经历；随机不影响事实和操作权限 |
| 数据保全 | 记忆正文和摘要加密；提供带密码的可迁移加密备份与恢复，恢复人格设定 | 模型推理仍会收到必要上下文；“本地保存”不等于“从不外发” |
| 动作 | 全量审计 92 个 VRMA，运行时处理符号断点和循环接缝；修复快速切换的权重回弹 | 原资产保留；没有逐一目视验收每个角色与动作组合 |
| 鼠标互动 | 部位、近期点击、安静状态共同选择短句/表情/动作；不连续复读；频繁点击会安静些 | 短句通过当前 TTS 合成，首次生成后按角色与音色缓存；不声称已达到真人笑声效果 |
| 桌面行动 | 增加输入焦点文字插入、窗口截图、OCR、键鼠和逐步视觉规划；任务状态、停止与用户验收 | 通用窗口视觉操作仍限测试夹具；产品入口首先支持 WorkBuddy 与微信，尚待真实桌面验收 |

设置的“智力”页和菜单新增“记忆与关系”“桌面任务”。保留原来的角色、听力、智力、语音设置及各服务商配置；本批不把用户已有 Grok 选择强制改回默认值。

## 本地资料库设计

`~/Library/Application Support/workbunny/vault/companion.db` 是唯一新的聊天/记忆资料库，原 `memory.json` 在成功迁移后移除。用户在开发前要求清空旧记录，此次正式数据从空白开始，未导回历史聊天或测试数据。

- SQLite 使用事务、WAL、同步提交、外键、来源关系和按类型/状态/时间/检索词的索引；通过独立原生辅助进程运行，不绑定 Electron 的 Node 原生 ABI。
- 正文使用 AES-256-GCM，并按记录 ID/类型绑定认证；主密钥由 macOS Keychain 支持的 Electron safeStorage 封装。无法解锁时不创建明文替代资料库。
- 当前角色设定和已有 API 密钥仍在权限为 `0600` 的本机配置中；本批不宣称所有配置均已加密，也不将凭据纳入记忆备份。后续将分别迁移凭据存储。
- 检索词使用独立领域密钥的 HMAC-SHA256，截取 128 位并编码；不在磁盘保留明文全文索引。时间、类型、数量、关系结构和访问模式仍是可见元数据。
- 来源是可追溯图：用户原文 → 记忆/摘要 → 用过这些资料的助手回复。删除递归处理后代，后台结果携带 privacy epoch，主进程也清理本轮 RAM 上下文并取消旧生成。
- 加密备份使用单独密码经 scrypt 派生密钥，不依赖原 Mac 的 Keychain。恢复仅覆盖空会话；已有聊天需先备份并清空。用户应自行管理已导出的旧备份。
- 默认日志保留技术状态和耗时，不再写听到/说出的正文；上游模型错误不原样打印可能含密钥/提示词的响应。

成熟方案的源码/接口与依赖评估见路线文档。本批借鉴记忆分块和提取/更新机制，没有引入 Mem0、Letta 或 Cognee 运行时；也没有伪称做过这些框架的效果对比 benchmark。以后是否增加本地 embedding，以真实改写召回测试决定。

## 桌面操作与 WorkBuddy 分工

复杂工作仍由 WorkBuddy 完成。workbunny 增加的桌面服务只发布有边界的动作：观察目标窗口、选择一步、记录输入意图、发送键鼠、重新观察。操作范围不从屏幕文字中扩张，也不把模型的“已完成”直接当验收。

- 每步验证进程、窗口 ID、窗口位置与截图时效。切窗、锁屏、旧截图、目标消失或权限不足会暂停。菜单、任务页和 `⌘⇧Esc` 可停止；停止终止原生输入进程并废弃旧模型结果。
- 焦点输入提供 3 秒切换时间，通过 Unicode 键盘事件输入，不更改剪贴板。输入后等待用户核对，不自动按回车。
- OCR 使用 Apple Vision 识别截图，不读取辅助功能控件树。微信路径严格为截图识别与键鼠；没有微信系统工具、AppleScript、API、插件或重启逻辑。
- 本批微信实验范围固定在文件传输助手；发送前要求截图会话标题可识别，搜索列表里出现同名不算。未开启常驻自动回复、朋友圈或视频号自动互动。
- 前台对话继续使用用户选定模型；后台整理及视觉规划只使用目录确认倍率为 0 的 WorkBuddy 模型。若没有免费模型则暂停，不自动改用付费模型。
- 实测目录里 `hy3` 为 0 倍率，`hy3-x` 为 0.05，GUI 两者都叫 Hy3。桌面派发还要求看见免费标识。该门禁故意保守；真实 UI 是否能可靠提供这些证据仍需解锁后验收。
- WorkBuddy 本地 broker 的模型调用已可用，但没有发现 GUI task 派发/查询 pipe。随包 CLI 有独立后台 session 工作流，账号/免费模型契约尚待验证，见[接口调查](workbunny-WorkBuddy协作接口调查-2026-10-25.md)。不能把模型接口连通当成工作委托已完成。
- 自己的桌面任务写入本地台账，重启后未完成任务标为暂停，不自动重发可能已经送达的文字或消息。

## 取得的验证证据

1. **已有功能回归及新原生/动作测试：68 项通过**，涵盖 ASR、回合取消、语音、设置、模型列表、动作策略、原生协议、锁屏生命周期与动作清理；另有真 SQLite/记忆服务的隔离集成检查。
2. **真实记忆模型实验：3 个场景通过**。合成角色在 2020 年说出的猫名经过 80 条后续消息和重启，2026 年仍能回答；纠正后使用新名字；遗忘后不再说出旧名字。使用当前账号免费 Hy3、真实 SQLite 和 Keychain 封装；测试数据位于临时目录，结束清理，没有污染正式资料库。
3. **规模模拟：10,000 条消息、2,000 条带来源记忆**。新编码下 DB+WAL 约 44.4 MB，词法检索 p50/p95 为 6.89/8.92 ms，上下文组装 52.53/64.22 ms，重开 10.83 ms。四个跨年锚点召回成功。见[完整结果与限制](workbunny-memory-benchmark-2026-10-25.md)；这不证明真实十年运行可靠性或语义召回质量。
4. **新窗口交互**：隐藏 Electron 窗口通过记忆确认/编辑、保存失败恢复、离窗写入保护、备份密码清理、任务状态与验收、停止与输入取消测试，全部使用替身 API。
5. **OCR 与视觉模型**：Apple Vision 正确识别合成图片中三行中英文；真实免费 Hy3 也读出相同三行，约 3 秒。没有使用私人桌面截图。
6. **真实桌面测试未通过验收**：测试首先核对到登录窗口，系统确认锁屏，因此在发送任何输入之前停止。已增加原生锁屏门禁；没有操作微信，没有进行真实收发或工作派发。
7. 动作具体数据、修复阈值和目视边界见[动作验收](workbunny-动作质量验收-2026-10-25.md)。
8. **正式安装路径初测**：0.3.0 成功启动，92 条动作加载，资料库解锁；聊天仍为 0 条；ASR 收到真实音频并进入就绪；Grok/CHP 选择保留，WorkBuddy Hy3 连接测试 1,895 ms、返回 0 额度消耗。两个新面板无启动错误或横向溢出，角色设定保留五行。
9. **正式应用的新桌面权限尚未授予**：屏幕录制、辅助功能/输入控制为未授权，麦克风原授权仍有效。开发工具进程的权限不能代替正式应用的权限；解锁后需通过系统首次授权流程，固定签名身份继续保持。
10. **锁屏冷启动修复已实测**：初版最终重启时抓到 `SecKeychainFindGenericPassword` 阻塞主线程；修复为先读原生锁屏状态，锁屏时延后访问钥匙串并暂停监听。正式路径再次冷启动后界面可响应、92 条动作加载、记忆页显示“电脑解锁后载入记忆”，解锁入口可见且无横向溢出。系统解锁事件配合只读状态复查负责恢复；实际解锁后的系统钥匙串授权与恢复仍待复测。该状态下不以空记忆继续回答。

后台整理只在空闲时调度，前台说话、思考或桌面任务优先；新请求会取消后台提取，迟到结果不落盘且允许之后重试。任务多行输入使用 Shift+Return 软换行，避免在完整任务与限制写入之前意外发送；单段焦点输入拒绝控制字符。原生纯计划测试覆盖这一策略，真实 GUI 换行行为仍在桌面验收清单中。
