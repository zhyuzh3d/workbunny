# WorkBunny 数据形象包 v1

`.wbavatar` 是 ZIP 数据包。角色、动作、交互和所需资源作为整体安装与替换；包内不执行 JavaScript 或着色器，也不能引用网络或包外文件。VRM/VRMA 保持原有工作方式，形象包不进入 VRMA 动作列表管理。

## 包结构

根目录的 `manifest.json` 声明 `format: "workbunny.avatar-pack"`、`formatVersion: 1`、稳定的 `id`、三段式 `version`、`character`（`id`、`name`、`model`）、`actions`、`graph`、可选 `interactions`、`defaultIdle`、`requires` 和 `assets`。`assets` 列出每个非 manifest 文件的相对路径、字节大小及 SHA-256。宿主校验完整声明、文件类型、哈希、容量、图结构、动作引用和能力后才加载；安装先验证再切换，替换失败保留旧版。

`actions.json` 的 `categories` 声明 `id`、`label`、`description`；`actions` 声明稳定 `id`、所属 `category`、`label`、`use`、秒数 `duration`，以及可选 `loop`、`idle`、`autonomous`、`weight`。待机必须是可循环的 idle。语义选择、触摸和运行时使用同一份目录；包内道具不算缺失外部道具。

`interactions.json` 包含 `regions` 和 `pools`。区域定义 `id`、`label`、`pool` 与一个或多个挂到声明锚点上的 `hitVolumes`；可用球、胶囊、椭球或盒。池内每项为 `{ "action": "动作ID", "weight": 1, "speech": { "text": "你好呀！", "emotion": "happy" } }`；`speech` 可省略，`emotion` 可选 `happy`、`sad`、`angry`、`relaxed`、`surprised`。文本是待展示和朗读的普通内容，不是指令；宿主校验长度、内容和动作引用，负责拾取、节流、随机选择、确认动作播放后再展示及发声。旧包未声明台词时继续静默动作。

点击语音复用宿主的语音设置、静音、打断和音频缓存：动作标识、合成模型、音色、台词和语音风格共同确定缓存；切回相同组合可复用原音频。音色不可确认、合成失败或降级后的语音不会写入错误的缓存。远程 CHP 点击发声前刷新模型身份，避免服务端切换模型后错误命中旧缓存。

## 宿主能力

- `declarative-3d-v1`：自包含 GLB、节点锚点和数据轨道，支持变换、重力轨迹、形变、材质颜色、分节弹簧及双四元数蒙皮。模型不得依赖外部 URI。
- `soft-surface-v1`：宿主内置的连续软体表面预设，数据描述网格、颜色、表情、耳部姿态、节奏、重力及宿主支持的道具和特效。当前预设按软弹兔兔的表面坐标、双耳骨架和眼睛布局设计，并非任意拓扑均可直接使用；其他结构优先使用 GLB 运行时，或由宿主扩展新的通用能力后再声明版本。

软体角色可在 `graph.json` 中声明可选的 `palettes` 数组（每项为稳定 `id`、显示 `label`、表面 `base` 与内侧 `inner` 色值）及 `defaultPalette`。宿主按角色保存用户选择，只允许选择该包声明的颜色；没有这两个字段的旧包仍使用原有 `palette`。内置 bunny 提供葡萄紫、莓果粉、天空蓝、蜜橘黄、黑色和白色。

`requires.features` 必须列出实际使用的能力；未知能力会被拒绝，不会悄悄降级。严格格式和约束以 `src/main/avatar-pack-manifest.js`、`avatar-pack-reader.js`、`avatar-soft-surface-schema.js` 及共享校验器为准。`tools/build-soft-surface-pack.cjs` 是原创兔兔包的构建示例，不会把预览器脚本装入包中。

在设置中导入 `.wbavatar`；已导入包可以整体替换。内置软弹兔兔的升级包保存在用户目录，可以恢复发行包内置版本；用户导入的包可以删除。替换不是单个动作编辑，包制作者应保持动作 ID 稳定并递增版本。
