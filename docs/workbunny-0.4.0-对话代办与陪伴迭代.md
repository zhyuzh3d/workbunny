# workbunny 0.4.0：对话代办与陪伴迭代

2026-10-26。依据 [产品目标](../concept.md)，延续 [0.3.4 验收](workbunny-0.3.4-桌面协作与授权稳定性.md)。本轮目标是把自然对话、小秘书协作、长期记忆与可见的用户控制连起来。下面区分设计、隔离验证与正式应用验收；开发中的结果不当作已交付。

## 产品路径

用户口头或文字交代 → 同一次对话回复识别聊天或代办 → 确定 WorkBuddy / 微信与必要对象 → 发起真实界面操作 → 绑定实际进度 → 核对要求和交付 → 必要时继续原会话追问 → 汇报已知结果。

复杂工作由 WorkBuddy 做。Bunny 的执行代码处理界面、观察与协调，不另建开发团队或独立执行复杂工作的框架。“工作与日常”以进度和暂停为主，手动表单折叠为备用入口。用户说“继续刚才这件”时恢复同一任务；重启应用不会自动重放旧输入或旧发送。

## 边界与模块

| 模块 | 职责与关键约束 |
|---|---|
| `dialogue-actions.js` | 同一次模型响应的 JSON envelope：chat / action / skip。严格检查字段、重复键、截断与额外对象；只把 chat.text 解码后流入气泡和 TTS。操作 JSON 不朗读、不进入聊天正文。 |
| `voice-turns.js` | 一秒停顿可预请求；系统最终确认与三秒轮次提交前不执行操作。续说或识别修订使旧请求失效。 |
| `secretary.js` | 发起、进度、暂停、显式继续和独立验收。只处理当前用户请求，内部观察不发起新操作；同一请求只派发一次，迟到结果须通过 token/generation/privacy epoch 检查。 |
| `verification-transport.js` | 核对优先 Flash low；只有账号转发超限或空回答时，查询目录确认免费 Hy3 后重试一次相同证据。取消、普通网络错误、模型不符不触发隐式切换，不重试桌面动作。 |
| `desktop-service.js` | 复用受约束的界面操作。WorkBuddy 优先专用控件适配，微信只能截图与键鼠。写入意图先保存；草稿不同、窗口变化、发送不确定均停止。 |
| `monitor.js` / `workbuddy-observation.js` | 通过唯一 UUID 标记、会话、轮次与时间精确关联真实 WorkBuddy 记录，不能拿“最新任务”代替本任务。完成摘要仍是执行方报告。 |
| `task-journal.js` | 任务回执沿用本地加密资料库和来源链：用户消息 → 任务 → 助手回执。遗忘来源后级联删除；旧任务及迟到回执不能重建已忘内容。 |
| `delivery-evidence.js` | 文件交付只读取用户原始请求明确给出的绝对路径；报告里的路径须在其授权目录内。最多四个文件，限制字节和文本片段，拒绝符号链接、凭证和敏感目录。文件正文仍是数据，不是新指令。 |
| `vision-preview.js` | OCR 保留 PNG；远程视觉预览独立转 JPEG、保持比例和硬性字节预算，控制视觉请求体积。 |
| `memory-service.js` | 查询侧补充低权重中英同义词候选，保留原 HMAC 索引与加密格式；向 UI 返回实际注入预算内的长期记忆/摘要引用。 |

验收检查与执行方分离：简单回复可据绑定会话的实际回答验收；文件或开发任务须提供实际交付和可检查证据，不凭“已经完成”四个字通过。发现缺项可向同一 WorkBuddy 会话追问，默认最多两轮；会话不匹配、需要用户信息或无法安全继续时，保留状态并如实汇报。微信发送不确定时不以“再发一遍”作为修复。

明确的暂停、继续和进度短指令通过完整字符串匹配直接进入同一控制与语音提交门，不必等待大模型分类；带引述、否定、附加操作或没有旧任务时不匹配，其他自然表达仍通过一次对话请求决定。任务状态同时提供机器状态码和用户文案，避免历史暂停说明被误当成当前操作前提。

追问在按发送前持久保存新轮次、旧消息键、新提交时间和待确认状态。超时、停止或重启后，只精确查找新消息，不能再拿旧回复验收或重发追问。只有新消息被绑定后才允许下一轮。实际任务关联采用会话、UUID、原始消息时间/内容哈希；Monitor 的进程内数字序号不作为重启后的唯一依据。

## 模型与传输决策

用户当前设置的日常聊天模型继续独立保存。本轮真实环境为 WorkBuddy / `deepseek-v4.1-flash` / low；桌面规划使用 Flash high、2,048 token 预算。交付检查使用 Flash low、2,048 token 预算，核对交付范围、依据与明显矛盾，不重新执行整项专业工作。WorkBuddy GUI 的具体 effort 仍以其自身设置为准，不将代理 API 参数当作 GUI 的证据。

实际长报告触发 `E_PAYLOAD_TOO_LARGE`。进一步读取本机 WorkBuddy 5.9.2 的 `createWbRequestPipe/readBodyCapped` 源码，确认是内联 HTTP **响应体**上限 655,360 字节；SSE 每段的包装会放大推理输出。普通非流式请求经实测返回 `Non-stream chat request is currently not supported`，因此没有启用这个不支持的模式。保留 SSE 请求，移除重复证据、限制预算和职责；仅对未绑定会话的视觉任务附实际结果截图。默认 WorkBuddy 通道仍是整段响应后解析，不能将协议的增量解码能力说成该通道已经真正逐字流式输出。

Flash 缩短预算后仍可能过限；仅在这个明确错误或空回答时，独立核对可改用目录确认免费的 Hy3，一次为限。真实文件任务已走到该分支并记录 `model=hy3 / fallbackReason=E_PAYLOAD_TOO_LARGE`，工作执行模型与用户的聊天设置都没有被覆盖。另一次直接 Hy3 核对请求返回 usage.credit=0，是本次账号与目录快照，不承诺未来价格。备用不满足条件或仍失败则如实暂停，不以缺失回答验收。

最初的 XML 前缀方案在真实模型上经常出现“操作 JSON 后再补口语”，被严格校验拒绝。改为 JSON mode 后，聊天、操作与忽略共享一个响应，不增加前置分类请求。DeepSeek 官方说明 `response_format=json_object`、提示词应提供 JSON 示例，且正文仍可能偶发为空；xAI 也支持 JSON object。应用仍自行校验语义结构，格式模式不等于执行授权。[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[xAI Structured Outputs](https://docs.x.ai/developers/model-capabilities/text/structured-outputs)。

真实模型固定合成样本覆盖明确工作、微信发送、停止、查询进度、闲聊、方法咨询、引用、假设、缺收件人和缺项目位置。Flash 修订后样本为 14/14，响应约 1.5–2.6 秒；新增 resume 单例通过。Hy3 初轮 13/14，补充明确对象规则后对唯一失败例重测通过。这是调试集结果，不是盲测准确率或所有模型的可靠性承诺。

## 长期陪伴与数据掌握

“记忆依据”和“本轮想起”只显示真正装入本次上下文的 memory / summary，包含日期和来源；不把普通近期聊天、未确认候选或被预算裁掉的记录挂名为记忆。用户可以查看原始依据，进入已有编辑和删除流程。人物关系、地点和时间不唯一时应澄清，检索相似不等于事实相同。

检索评估及残余漏检见 [记忆检索评估](workbunny-0.4.0-记忆检索评估.md)。固定关系与跨语言边界集在 1,000 条合成干扰下仍有遗漏；没有把测试集全部命中等同于多年记忆已经解决。还评估了免费模型生成中英检索别名：出现假设事实、截断且没有带来边界集收益，因此未接入生产。保留可解释、可删除、无需新增大模型的查询侧改进。

修订证据继续保存在来源链中，但不再作为最近用户消息、旧对话片段或“刚刚聊过”的时间线注入。心情增加来源消息 ID；删除或更正涉及该来源时重置，重启校验悬空引用。系统语音从 stdin 接收正文，临时音频在成功、失败和中断后清理；遗忘或锁定也清除内存音频缓存，ASR 日志只记字数。

备份恢复改为线性拓扑依赖队列，在写入前拒绝循环和自引用；保持仅向空库恢复、批次失败清空半成品。6,600 条隔离加密记录导出约 163–411 毫秒、恢复约 0.9–1.0 秒，原始来源与长期记忆 sources 复核通过。没有在正式库上执行恢复或清空。

本地文件证据只接受本轮原文中明确文件操作关联的路径或文件列表。路径回显、引述命令、代码块和 JSON 数据不会新增读取授权；含空格/标点的引号字面量不拆成其他路径。对于明确要求创建/写入的文件，本地存在性、可读取状态和 SHA 是硬门槛；模型不能覆盖缺失证据，核对期间文件变化则停止确认。路径语义有歧义时保守不读，交由用户补充；这不是通用自然语言权限推断器。

## 已执行的工程验证

- 实际 `voice-turns`、协议门、Secretary、DesktopService、Monitor 和 observation 串联，native / 模型用可控替身，检查提交门槛、续说、数字 taskId、停止后的迟到结果、单次验收与汇报、重启不回放。
- 真 SQLite 隔离库验证来源递归删除、epoch 拒绝迟到写入、清空后不复活、新任务仍可保存；不使用正式私密数据。
- 真实 Electron nativeImage 验证高熵图像的 JPEG 预算（样本 152,783 字节）、PNG OCR 分流、比例和小图不放大。
- 隐藏 Electron 面板验证折叠备用入口、权限展开、自动/手动验收文案、暂停/继续、召回来源与错误提示。隐藏 fixture 不当作正式 UI 或应用操作验收。

## 正式应用试验记录

第一轮：普通文字对话正确自动选择 WorkBuddy，提交简单回复任务，WorkBuddy 返回了准确文字；交付检查出现 `E_PAYLOAD_TOO_LARGE`，应用如实暂停，没有宣称办好。当时先缩小截图并补上视觉发送后的真实 Monitor 绑定；后续源码检查确认上述响应体限制，不能将这个错误直接归因于 PNG 请求体。

第二轮：两轮清单任务已填入草稿，但严格的截图模型标签检查阻止了发送。只读诊断显示模型组合框确实为 Flash，而首页标题识别没有通过。已修复 Heading 值/标题/描述分别匹配、空值遮挡和标点空白差异，并增加不覆盖旧草稿的显式恢复接口。旧任务编号和未发送草稿均保留。

恢复时发现旧原生适配只遍历到深度 25，而该 WorkBuddy 会话的可见 UUID 位于深度 27；提高有界遍历深度，并保留节点数、耗时、唯一编辑器、窗口范围和会话标记的全部检查。另修正仅需追问时可以切回已绑定 WorkBuddy 的流程，后台等待仍不抢前台。

后续实际结果：

- 声学聊天测试：系统音色通过扬声器播放固定测试句，由真实麦克风、系统 ASR 和已安装应用接收；最后一段识别文字出现后约 3.3 秒开始回答，没有发起软件操作。这是合成语音声学测试，不等同于不同人的口音、设备或噪声环境验收。
- 同一清单任务：再通过麦克风说“继续刚才这件代办”（系统将末尾识别为“代腕”，自然意图仍正确识别），保留原 UUID 和同一 WorkBuddy 会话，发送一轮补充要求，精确绑定新消息。实际助手正文恰好三条，Bunny 独立核验 pass、记录自动验收并只汇报一次。父代理另行只读查看 WorkBuddy 实际助手区域，确认三条正文存在。最终识别到验收约 28 秒，包含两次检查、一次追问及 WorkBuddy 回答，不是聊天延迟。
- 微信：普通文字入口自动选择微信，向文件传输助手发送 `workbunny 对话代办测试 2026-10-26` 一次。最终截图有正确会话标题和完整绿色消息气泡，输入框为空；Bunny 独立核验、自动验收并汇报。父代理另行查看该真实截图确认。全过程只有截图、OCR、键鼠，没有微信 AX、AppleScript、API 或进程控制。入口到验收约 37 秒，包含两次多余聚焦点击，随后针对该问题优化输入协议。

后续补充的正式应用结果：

- 代码审查：WorkBuddy 真实读取源码并出具报告；开发期间源文件发生变化，Bunny 要求按新版本重读、更正位置与未证实结论，最多追问两轮后核对报告。报告仍需区分局部代码条件与整个应用是否会触发；父代理检查到集成锁定/遗忘路径会显式停止旧代理，因此没有把孤立类中 `ready()` 变化的推演说成已经复现的集成故障。
- 真实文件交付：发起前确认目标文件不存在，WorkBuddy 在私有临时目录创建 Markdown，Bunny 读取实际文件、指出一处函数引用不够明确并在同会话追问。最终文件恰好四行，首行 `# 来源链与隐私隔离`，正文含换行为 250 字符（含标题整个文件 261），列出 `createTaskJournal`、`memory.write` 和 200/256 的来源边界。父代理另外读盘核对，SHA-256 为 `c1aa9a5a1ed05b4e4f7eb2ccece414d4a51a1d7da77f2757164445f435490dc2`。任务由 Bunny 自动验收并汇报，核对模型因上述账号通道限制实际使用免费 Hy3；文件由 WorkBuddy 写入，不由测试脚本代写。
- 此次试验暴露中文标点紧邻路径导致误解析，也暴露不能只让模型决定“文件真实存在”的问题。已增加中文路径分隔、完整引号文件名、明确操作授权和本地硬门槛；隔离测试直接让远端替身声称 pass，缺失文件仍被拒绝，检查期间变更也不会被旧快照验收。
- 微信减少重复聚焦：后续发送新测试句，实际视觉决策步骤由五步变为两步（type+focus、send；底层仍先点击输入框、输入、点击发送）。单次入口到验收约 31.5 秒，对比前例约 37.4 秒；文本不同，这是流程样本，不是受控性能基准。父代理查看新气泡，确认完整且仅发送一次。
- 微信只读：直接说“只查看文件传输助手最后一条文字，不输入、不发送、不切换联系人”，Bunny 正确读出 `workbunny 输入提速测试 2026-10-26`，控制器步骤为空，实际没有键鼠输入或发送，约 19.1 秒核对完成。
- 陪伴互动：正式应用中触摸反应发出 `interaction=true` 后，语音已开始而 `currentMotion` 仍为 `shy_cute` / `tease_catwalk`，没有被立即切回待机；在已绑定的 WorkBuddy 后台监视阶段也可触摸，不必让长任务占走普通陪伴。

任务面板默认先给任务摘要、来源/目标和结果；完整条件与核对依据、截图分别折叠。核对中仍可暂停，微信状态不再显示 WorkBuddy 暂停说明，完成后不保留无关的暂停提示。模型生成的追问再次经过微信范围检查，并继续携带原任务范围与禁止事项。

## 接下来的优先顺序

1. 用未参与调试的长期记忆集继续评估人物关系、时间变化、否定与中英改写；当前边界集仍有漏召回。Apple 本地向量候选的实际评估见另文，未因“系统自带”就直接接入。
2. 把更复杂任务的输出文件、只读范围和验收条件做成明确的数据契约；目前保守的路径语法不覆盖所有自然表达，复杂成果仍需要人确认业务正确性。
3. 增加汇报的持久送达确认。当前先保存报告再发布可避免重复，但进程在两者之间退出时可能漏一次通知；报告仍保留在任务记录里。
4. 验证更多 WorkBuddy 版本、需要用户回应的中间状态及长时间监视；当前实机依据是 5.9.2。微信当前验收范围是文件传输助手的发送与只读查看，不等同于所有联系人、未读自动回复、朋友圈或视频号流程已验证。
5. 扩展 Apple Silicon Mac 的实际设备、麦克风与口音验收，完成 Developer ID 与公证分发。当前本机开发签名和合成声学试验不能替代其他机器的安装验收。
