# BOPER 键鼠模块开发计划

BOPER（BunnyOPER）统一承接 Bunny 的键鼠输入，整合 keymouse 的运动与键盘能力、kmbridge 的 HID 桥接能力。仅面向 Apple Silicon，最低设计目标为 macOS 13。VirtualHID 就绪后所有键鼠输入使用它，故障停发，不自动降级；微信直接操作始终要求 VirtualHID。

多字符文字优先准备系统剪贴板，再由 BOPER 发出粘贴快捷键；macOS 使用 Cmd+V。VirtualHID 模式下该快捷键由虚拟键盘发出。只有明确无法粘贴或确认未插入时，才考虑已验证的逐键输入策略。

状态：0.26.43 已在当前 Apple Silicon Mac 重装，安装者本机管理员授权的 root LaunchDaemon 已真实就绪，不依赖开发者账号或 Apple 开发者证书。MCP 场景查询/设置生活、安装/重复启用、跨版本重装恢复、完整桌面桥接收窗口、取消后复用和最终设置面板检查均通过。其他 macOS 实机验证及自动物理接管待完成。当前实现见 [architecture.md](architecture.md)，产品目标见 [product-requirements.md](product-requirements.md#boper-键鼠模块目标)，流程见 [flows.md](flows.md#boper-键鼠执行目标流程)。

## 已确定的架构决策

| 决策 | 具体做法 |
| --- | --- |
| 一套调度与控制 | 沿用现有 Task、Action、Operation 账本、GuiLease 和控制代次，不建立第二个任务队列或 GUI 调度器 |
| 一个输入执行者 | 同一 Bunny 主进程装配一个 BoperService，并只启动一个普通权限的原生输入进程；截图与软件检查不进入该进程 |
| 最小特权输出 | 一个 BOPER HID helper 直接整合 kmbridge 的 C++ 客户端，负责有限 HID 报告和自身设备复位，不运行轨迹、文字策略或 LLM |
| 一个后端选择 | 未启用虚拟模式时普通软件可用 CGEvent；VirtualHID 就绪后全局使用，运行异常不得换回 CGEvent |
| 一份输入契约 | 上层表达移动、点击、按键、文字等意图；后端明确报告能力差异，不把全局 HID 伪装成按 PID 定向输入 |
| 多字符先粘贴 | 普通权限文本组件写入本次获准正文，BOPER 发送 Cmd+V；不用目标应用的粘贴 API、AX 写值或脚本粘贴代替 |
| 正确性先于自然度 | 先保证精确内容、正确落点、按键释放与停止；轨迹和节奏在这些条件内自然变化，不主动制造错字 |
| 只构建 arm64 | BOPER、Bunny 及自有辅助组件只构建 arm64；官方驱动包原样保留，不为删除其他架构分片而破坏签名 |

BOPER 不接管截图、软件语义判断、联系人授权或任务验收。纯视觉链继续使用 CGDisplayStream 像素，禁止 ScreenCaptureKit、目标应用 AX、窗口与进程信息、内部协议和数据库。剪贴板仅用于准备本次已授权文字，不用于从微信或其他目标应用复制、读取内容。

## 审核发现的关键缺口

| 当前代码或原型事实 | 修订后的处理 |
| --- | --- |
| desktop.swift 在主线程处理原生请求 | 不把长轨迹或长文本循环塞入现有桥；独立输入进程执行期间持续接收停止 |
| 多个 DesktopService 有独立原生客户端，但共享 GuiLease | 不让每个客户端各建一套轨迹、按键状态或 VirtualHID 连接 |
| WorkBuddy 后台输入使用 CGEvent.postToPid | VirtualHID 没有同等定向能力；不能去掉 PID 后仍按后台流程输入 |
| HID 报告为异步提交 | 本地排队、驱动接收、应用读取与业务完成分开；停止不能撤回已进入系统队列的事件 |
| 原型增益更新用端点位移除以累计报告路程 | 曲线和反向修正会造成口径偏差；只用匹配区间的可靠输入输出量估计参数 |
| gui-admission 明确只在 Action 外参考 HID 空闲计时 | 保持准入职责，不改成 Action 内的人类干预检测器 |
| 微信清单目前笼统禁止 clipboard | 按主人最新指令细分：允许写入获准正文并快捷键粘贴，禁止从目标复制读取 |
| 原型 root socket 为 0666、无调用方认证，安装漏装 kmbridge | 不原样分发，从真实应用包、认证连接和干净安装开始验证 |

原型的 PID=0、stateID=1 支持其输入经过 HID 路径，但不支持“普通软件完全无法区分”的结论。字段 87 的设备归因可与 [Mac Mouse Fix 源码](https://github.com/noah-nuebling/mac-mouse-fix/blob/master/Helper/Utility/EventUtility.m#L98)核对，该未公开字段不作为跨版本运行前提。DriverKit 驱动运行在用户空间，参见 [Apple DriverKit](https://developer.apple.com/documentation/driverkit)。

微信读取 IORegistry 的能力与实际行为另行验证。无 Input Monitoring 或 HID entitlement 不能直接推出注册表属性不可读；沙盒探针不能代替微信运行时证据。这项调查不阻塞无关核心开发，也不以“不可识别”为 BOPER 的成立前提。

## 进程边界与状态归属

### 宿主负责授权和协调

BoperService 由现有装配入口创建，供所有 DesktopService 和任务路径共享，负责能力检查、GUI 使用权、输入会话、取消、结果映射和设置状态。进度仍写入原 Operation 账本。

宿主采用很薄的 Objective-C++ Node-API 绑定，核验固定 root 安装、探测认证 XPC、管理连接授权和停止，不承载运动循环，不在 renderer 暴露原始接口。安装者通过本机管理员授权安装 LaunchDaemon，不依赖开发者账号、Apple 开发者证书或账号配置。Node-API 避免绑定 V8 私有 ABI，仍须核对实际 Electron 的加载与签名结果，参见 [Node-API 文档](https://nodejs.org/api/n-api.html)。

这层绑定使管理调用处于真正的 Bunny 应用包上下文，并让 helper 验证 Bunny 宿主的委托，而非仅认出一个可被任意程序单独启动的输入可执行文件。P0 用真实 .app 布局验证，不用散落的 CLI 测试冒充装机结论。

### 普通权限进程负责执行

一个 BOPER 原生输入进程整合运动、闭环、完整键鼠状态、剪贴板文字准备和两种后端。它不读取目标软件身份，不调模型，不另建业务任务。

命令读取和控制响应持续运行，输入使用单一串行执行器与非阻塞定时推进。不能用长 sleep 循环占住控制线程。宿主到执行进程优先复用 JSONL 编解码和诊断原语，通过私有继承管道通信，不开放公共 socket，不复制截图重启重试逻辑。

每次只执行一个上层 Operation。等待 GUI 的工作仍由现有调度和 GuiLease 处理；BOPER 不积压跨任务操作，仅保留当前操作和很小的报告窗口。

### 特权 helper 负责设备输出

helper 直接整合 Karabiner 客户端，不再启动独立 kmbridge 子进程。只接收认证会话、有限键鼠报告、复位、停止和状态请求，不提供 shell、任意文件路径、剪贴板、截图、输入监听或目标应用接口。

采用安装者明确授权的标准 root LaunchDaemon 和认证 XPC。固定 helper 为 `/Library/PrivilegedHelperTools/cn.haminn.workbunny.boper-hid`，固定 plist 为 `/Library/LaunchDaemons/cn.haminn.workbunny.boper-hid.plist`；复制到 root 暂存目录后核验字节摘要和固定本地签名，再原子安装；启动失败恢复原组件及原服务。使用 macOS 13 已有的 NSXPCConnection.setCodeSigningRequirement，不依赖私有 auditToken 属性或查询 PID 路径鉴权；核对指定客户端身份、签名、连接用户及登录会话，不仅检查同 Team ID。参考[连接签名要求](https://developer.apple.com/documentation/foundation/nsxpcconnection/setcodesigningrequirement(_:))。旧 SMAppService 仅保留等待 completion 的迁移注销，不再注册新服务，不修改 AMFI/Gatekeeper 或系统证书信任。

输入连接必须由受认证的 Bunny 宿主为本次原生执行进程授权，单独启动相同输入程序不能自动获得特权。委托材料不放命令行、环境变量或公共文件；P0 同时验证脚本、调试启动方式不会把 Bunny 借作授权代理。若该方案验证失败，先修订这一边界，不临时叠加宽权限 socket 作为第二实现。

helper 只允许一个活动输入拥有者。共享 Karabiner 驱动与 daemon，管理 BOPER 自己的设备实例；复位或销毁不得影响其他 Karabiner 客户端。没有有效会话时停发，锁屏、登录界面或其他用户会话不得接收输入。

## 会话与后端状态

持久配置保存用户的虚拟模式启用意图和必要安装信息。实际后端、设备就绪与故障由运行状态产生，设置、任务和经验上下文读取同一份状态，不各自探测猜测。

| 状态 | 普通软件键鼠 | 微信直接操作 |
| --- | --- | --- |
| 未启用虚拟模式 | 满足授权时可用 CGEvent | 不执行，说明需启用 VirtualHID |
| 正在启用、待批准或待重启 | 不接纳新键鼠输入，说明待完成步骤 | 同样不执行 |
| VirtualHID 就绪 | 全部使用 VirtualHID | 使用 VirtualHID，保留对象及渠道授权 |
| 已启用但故障、断连或不兼容 | 停发、保留进度，不降级 | 同样停发、不降级 |
| 主人明确关闭或卸载虚拟模式 | 终止旧会话后，新普通任务可用 CGEvent | 继续不执行 |

发现已有兼容组件时复用，经授权建立 BOPER 会话后直接采用 VirtualHID，不提供按软件切换 CGEvent 的开关。启用、关闭或重连先终止旧会话，不在一次 Operation 中途换后端；故障重连只恢复接纳资格，不自动重放旧输入。

输入会话绑定当前 GUI 占用、控制状态、后端和设备实例，任一失效就关闭会话。用一个 inputSessionId 统一表示这层有效性，不另叠加功能重叠的 backendEpoch。沿用已有 operationId，reportSeq 只用于会话内报告的顺序、去重和回执。

GUI 移交前停止操作并释放本会话持有的键和按钮，状态不明时不能直接交给下一输入任务。清理本身有界；失败后释放业务占用，但 BOPER 保持故障且不签发新输入许可，不能以永久占住 GuiLease 代替设备隔离。宿主单实例锁及 GuiLease 保留，helper 的独占是设备边界，不成为第二套业务调度。

软件要求在现有清单用通用字段声明，例如 requiredInputBackend: virtual-hid。微信规则由清单提供，宿主在接纳与派发处执行；BOPER 不硬编码软件名、不查询微信 PID 或窗口。要求随相关动作的输入上下文传递，不污染跨软件 Task 中独立的其他工作，也不因改名、恢复或关闭经验检索而丢失。

## 输入契约与能力差异

上层使用同一套移动、点击、按下释放、拖动、滚动、组合键及文字意图。文字策略可生成多次底层报告，没有独立的业务生命周期。两后端共享操作语义、状态机、轨迹参数、取消和结果格式，保留必要的不同输出机制。

能力分别声明全局键鼠、定向输入、直接 Unicode、已准备输入法的逐键输入等。原按 PID 输入只在明确许可的结构化 CGEvent 适配器中迁移，不进入纯视觉协议；VirtualHID 提前返回不支持，宿主选择已有前台流程或其他获准通道。不得暗中用 CGEvent，也不得把后台正文发给当前前台软件。

对 WorkBuddyFill 等嵌入键鼠的原生大操作，拆出保留语义检查的准备、BOPER 输入和结果读取，只移出键鼠，不重写整条交办流程。草稿冲突、定向范围、未知提交与最终回读机制保留。文件粘贴等原有剪贴板准备仍守原授权，快捷键统一经过 BOPER；微信不借此开放文件或正文复制读取。

盘点并迁移直接 post、postToPid、组合键、附件和恢复等生产出口。Bunny 生成的键鼠脚本也遵守 BOPER 约束，不能作为替代注入通道。源代码及已注册工具边界可以校验，不宣称能全知拦截任意第三方程序的内部行为。

## 多字符先使用快捷键粘贴

### 正常路径

持有 GUI 使用权并确认目标输入区后：

1. 按需要点击或聚焦输入区；已有可靠焦点时不机械重复点击。
2. 普通权限组件将本次获准正文写入系统剪贴板，作为纯文本保留 Unicode、标点和换行。
3. 记录写入后的 changeCount，发出快捷键前核对未被其他操作替换。
4. BOPER 发送 Command 按下、V 按下与释放、Command 释放。VirtualHID 模式完全由虚拟键盘发出，不调用目标应用粘贴、AX 写值、菜单命令或脚本接口。
5. 保留回执，由 Bunny 按 Action 场景选择观察与核验时机，不逐字调用模型识别或逐字敲入。

剪贴板准备不等于目标已经执行粘贴。发送、提交和执行命令仍是独立语义动作，正文末尾有换行不额外按 Enter；同时须考虑目标可能自行处理粘贴内容，不能保证粘贴永远没有业务副作用。

### 剪贴板边界

系统剪贴板是共享资源。本次写入与快捷键沿同一 GuiLease 串行处理，仅读取 changeCount 等必要元数据，不为输入读取旧内容、聊天内容、历史或其他应用复制的内容。

写入会把系统剪贴板更新为本次正文，遵循普通复制粘贴语义。默认不备份、不自动恢复旧内容，避免读取无关隐私或覆盖主人后来复制的内容。原正文与剪贴板内容不进入普通日志或诊断上传。

changeCount 检查只能缩小竞态窗口，不能把检查与目标读取变成系统事务。检查失败就不按 Cmd+V、不强行覆盖主人新复制的内容；快捷键已发后发现异常，按结果不明处理。剪贴板写成功或内容仍相同都不能证明目标已插入。

按版本验证系统剪贴板访问行为。accessBehavior 从 macOS 15.4 起可用，旧系统不能无条件调用；用户批准和访问限制遵循系统规则，不自动改权限。VirtualHID 的 Cmd+V 是否满足接收方系统对用户来源粘贴的判断，要通过本地接收窗口验证，不能仅凭 PID=0 推定。参考 [Apple 剪贴板访问行为](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum)与[changeCount](https://developer.apple.com/documentation/appkit/nspasteboard/changecount)。

剪贴板写入、键鼠派发和目标效果分别写入现有 Operation 账本；即使键鼠未派发，也保留剪贴板已改变这一局部副作用。

### 无法粘贴时

仅在目标明确禁止粘贴、系统写入失败且未发送快捷键，或已确认目标未插入时，才选择逐键输入。部分插入或结果不明先核对，不立即重打一整段或再粘贴。

逐键路径复用一个键盘状态机：已验证布局的拉丁字符直接编排；中文通过获准系统输入法和视觉候选方法完成。首版重点保证粘贴中文、中文标点、中英混排与换行；逐键中文、复杂组合字符及 emoji 的支持逐项声明，不自研另一套输入法，不用 CGEvent 补齐 VirtualHID 缺口。

单字符是否用按键由意图和布局决定；导航、删除、组合键和提交始终是按键，不经剪贴板。任何策略不支持本次内容时提前说明，不静默跳字或报告完整成功。

## 状态与故障恢复

一个键盘状态机维护本会话持有的修饰键和普通键，一个鼠标状态机维护按钮。HID 报告使用完整一致的状态：移动和滚动不能意外释放拖动按钮，单键报告不能覆盖其他已按键。修正 Escape 映射，移除主动错字、漏字、换位和双敲。

执行器保存输入意图，helper 保存最后本地提交的设备状态，两者职责不同。报告有范围、格式、数量和时效上限；helper 不接收正文、路径、联系人或截图参数。

停止走独立控制路径，不等长轨迹或长文本结束。helper 保持有限会话存活租约，由仍持有有效 GUI 使用权的宿主续期；原生进程不能在宿主失联后自行无限续期。进程死亡、断线、租约到期、睡眠或用户会话变化使旧会话失效。

报告与截止时间使用适合睡眠恢复的单调时间依据。恢复后不突发补发积压轨迹，不靠修改系统时间延长权限；helper 的本地报告窗口有界，不向第三方异步库灌入完整轨迹或整段文字。

helper 在实际调用输出库前复核会话和报告序号，不能只在请求入队时检查。报告提交与复位共用一个有序出口；停止先使会话失效，拒绝后到旧数据，再按顺序释放，避免另一线程无序复位后又被旧 keyDown 覆盖。清理回执仅声明 P0 实际可观测到的层级，不等待不存在的目标应用释放 ACK。

| 事件 | 必须处理 |
| --- | --- |
| 停止、撤权或控制失效 | 关闭会话、拒绝后续报告，优先释放自身键和按钮；释放前不移交 GUI |
| 宿主或执行器崩溃、无响应 | 断线或看门狗关闭会话，helper 独立处理自身设备释放 |
| helper 或驱动失效 | 停止、不降级，保留未确认释放与派发信息；不重启目标软件或共享 daemon |
| 锁屏、睡眠、用户切换、显示布局变化 | 旧操作和坐标失效，恢复后重新观察并建立会话 |
| 派发后超时 | 部分执行或结果不明，不因建立新会话而重放 |
| 停止与完成竞争、回执迟到 | 只归属原会话和 Operation，不覆盖新状态，也不抹去真实输入 |

复位仅作用于本会话持有的虚拟状态，不松开主人真实按住的键或复位其他 Karabiner 客户端。输入法变化、未完成组合文字和已插入正文是待核对的环境变化，取消时不盲按 Escape、Enter、删除或输入法切换来清理。

停止保证的边界是本地停止接纳和继续提交、有限积压及尽力释放。已提交至系统或驱动的事件不能保证撤回；驱动消失时不伪造释放确认。看门狗不是故障后继续完成任务的第二个执行器。

## 自然运动与视觉时效

先保证平滑轨迹和有界纠偏，再优化 Sigma Lognormal 速度包络、Fitts 距离与目标宽度关系、有限相关扰动及停顿。短移动不强制大弧线；近目标噪声衰减，点击稳定，不以随机漂移制造拖动。

坐标统一为桌面逻辑点，截图像素只转换一次。运动绑定本次显示几何，覆盖 Retina、缩放、边界及已获准区域；布局变化立即停止。未被 CGDisplayStream 视觉链覆盖的显示器不能仅因底层可移动就开放。

增益与延迟可靠测量，不固定为本机 0.32 或 0.35。使用相同运动区间的输入输出量，剔除反向修正、屏幕限位和外部干扰样本。先采用保守前馈、限幅及有限收尾，不每帧用尚未生效的反馈学习，不预先叠加复杂自适应模型。

报告按实际时间推进，过期采样点可放弃，不在延迟后追赶式密集重放。超出误差上限、不收敛、外部指针明显偏移或接管信号出现时停止，不能追着主人鼠标移动。

现有 1500ms 预检不能简单覆盖整段拟人运动，也不能删除。分开移动阶段与按下或粘贴的提交条件：长移动后证据过期就保留“已移动、未点击”，交回现有视觉预检按需刷新，再提交按下。沿原 Operation 记录继续，不把移动成功当业务成功。

自然度只改变允许的轨迹和时间，不改变目标、正文、快捷键或顺序。ProcessType 与 QoS 按上游和实测选择，Nice=-5 不作为默认硬要求，不以抢占语音线程解决积压。

## 主人接管与权限

保留显式停止、语音停止、锁屏和控制代次。HID 空闲计时只用于 Action 外的 GUI 准入，不用于 Action 内区分真人和 Bunny。

自动物理接管独立验证，不仅依赖事件时间或字段 87，也不把所有 Karabiner 设备排除为“自己”，从而漏掉主人经其他映射设备的输入。需要输入监听时放在普通权限进程，单独说明与授权，只保留控制元数据，不保存键盘内容。

显式停止和失联停发是首版必备；可靠自动接管是无人值守验收条件。未达到时限定为有明确交接的受监督试验，不暗中扩权限或关闭原保障。

屏幕采集、CGEvent、VirtualHID、后台服务和可选输入监听分别判断。VirtualHID 不反复查询 CGEvent 或 AX 权限；设置、生命周期与真实错误触发按需刷新，实际输入边界保留必要检查。helper 不充当绕过 TCC 的屏幕或输入读取代理。

## 安装和 Apple Silicon 兼容

自有模块以 arm64、macOS 13 为基线，按固定驱动组合逐版验证。支持范围取 Bunny、BOPER、驱动和系统的共同范围，不从本机结果或最新 README 推断任意包兼容。

| Apple Silicon 系统 | 验证重点 |
| --- | --- |
| macOS 13 Ventura | 最低 API、真实 .app 注册、认证 XPC、键鼠与快捷键粘贴 |
| macOS 14 Sonoma | 系统授权、后台服务、设备恢复 |
| macOS 15 Sequoia | 扩展批准、锁屏睡眠、输入法和剪贴板 |
| macOS 26 Tahoe | 当前系统回归，不外推其他硬件和缩放 |
| Bunny 与驱动支持的更高版本 | 逐版实测后加入，先标候选，不预先承诺未来系统 |

不开发 Intel、Universal 2、Rosetta 验收或双架构包。官方 pkg 即使有其他架构分片也原样保留。旧系统语音能力沿原实现检测，不为键鼠开发修改受保护语音基线。

固定自有协议、Karabiner 源码提交和客户端协议、pkg 哈希、签名、公证和最低系统。包、daemon、设备驱动版本与客户端协议分别核对，不要求版本字符串相等；本机组件和参考 pkg 的版本差异先查清。参考 [Karabiner 官方说明](https://github.com/pqrs-org/Karabiner-DriverKit-VirtualHIDDevice#usage)。

安装先发现和复用已有兼容驱动，仅缺失时安装独立 VirtualHIDDevice，不安装整套 Karabiner-Elements。批准、重启、helper 授权和键鼠 readiness 全满足才显示就绪。

应用和自有 helper 升级是可回滚事务；共享驱动升级单独处理，不能假设回滚应用即可回滚驱动。不无条件重启共享 daemon、删除 org.pqrs 目录或卸载其他软件依赖的驱动。不兼容时停发并说明，不进入重装循环。

装机前终止自身活动输入并核对旧 keymouse 归属，避免两个执行者并存，保留恢复路径。卸载默认仅移除自身组件。正式分发验证签名、公证、资源清单及受控启动；本地开发签名不冒充正式分发验收。

## 分阶段实施与验收

阶段按最小可用链路推进，不到最后才发现注册、中文或取消不可行。只操作获准范围，不自动退出、重启或重新登录微信。

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| P0 最小链路 | 真实应用布局中的薄绑定、普通执行进程、认证 helper；本地短移动、Cmd+V 中文粘贴和停止 | 证明委托认证、粘贴、设备隔离与停止可行，最低 API 可用，不依赖公共 socket 或目标接口 |
| P1 核心执行 | 两后端、完整键鼠状态、会话、有限报告窗口、独立停止、宿主租约和真实回执 | 并发、崩溃、超时、迟到、断线和锁屏通过；故障不降级，未知输入不重发 |
| P2 Bunny 接入 | 全部出口迁移、后台能力处理、GUI 和文字策略、设置安装、经验和打包 | 原任务与对话可响应，粘贴用 BOPER 快捷键；微信限制一致；干净安装及升级失败可恢复 |
| P3 自然度与边界 | 延迟感知轨迹、增益修正、布局、文字能力、滚动拖动及显示配置 | 准确性与停止不退步，轨迹、耗时或成功率改善，不支持项如实声明 |
| P4 实机验收 | 兼容 macOS、本地编辑器、恢复及指定联系人微信实操 | 支持声明有对应系统证据，自动接管满足无人值守条件，候选产物本身验证通过 |

开发和本地验收初估 6 至 10 人日，跨系统实机准备与等待另计，P0 后重估。仅实际影响关键路径的问题扩大研究，IORegistry 调查保持独立、有界，不为“不可检测”结论无限研究。

### 验证重点

- 用虚拟时钟、指针及报告接收器验证顺序、收敛、限幅、状态和取消，不写逐行镜像实现的测试。
- 本地接收窗口验证实际事件与粘贴正文，以及不同系统访问策略下的正常处理；ASCII、中文姓名、标点、日期、中英混排、换行及声明支持的字符准确一致。
- 覆盖剪贴板被替换、拒绝粘贴、部分插入、快捷键已发但回执丢失，确认不会自动再粘贴或重打。
- 模拟宿主与执行器终止、helper 卡住、睡眠、设备重建及租约失效，测量本地停发和释放延迟，记录不可撤回边界。
- 验证 GuiLease 竞争、移交、晚到请求及会话失效；输入、截图恢复和语音不相互卡住。
- 验证 VirtualHID 提前拒绝后台 PID 输入，前台路径重新取得 GUI 与焦点，不误输其他软件。
- 轨迹记录区域内成功率、逻辑点误差、P50/P95 耗时、过冲和取消延迟，不以端点达成量冒充点击成功率；固定 6ms 不称为通用硬件物理下限。
- 第一轮顶层试验命令至少间隔 1 秒；单次轨迹内部报告按合理设备节奏发送。
- 微信最后实操，仅指定联系人与范围，并按项目规定做有截止时间的外部元数据观测。异常停发留证，采样盲区和未证实的退出原因如实保留。

构建、本地窗口、具体系统实测和业务完成分开记录，未实测的不标通过。全部生产出口迁移后才称 BOPER 是唯一键鼠层；不支持的后台方式由 Bunny 调整获准方法，不以取消权限或控制冒充兼容。
