# 0.6.0：场景边界与增量记忆

2026-10-27。本轮根据个性化记忆设计实施，先建立可持续迭代的数据根基。这里区分已实现的程序行为与仍需完善的产品能力；安装路径验证另记。

后续已推进至 [0.7.0：长期记忆与三场景压缩](workbunny-0.7.0-长期记忆与三场景压缩.md)，新增独立压缩版本、冷区轮转与显式困惑核对，并修复原生库拒绝 `archived` 状态的兼容缺口。下文的“最近200条”整理描述是上一阶段的范围，不能用作当前版本能力说明。

## 已实现

- 默认生活；私聊可见全部，生活可见生活与工作，工作只见工作。共通身份与各场景补充设定分开，设置和菜单都可切换。
- SQLite 查询、检索、来源读取和计数在排序及 LIMIT 之前过滤。业务 domain 与 visibilityFloor 独立；派生项继承最严格来源，WorkBuddy 分类不能降低私聊来源范围。密文内校验范围，旧无范围数据保守为私聊。
- 切换场景取消旧模型回复、语音队列、召回依据和旧 ASR 代次，清空旧监视卡片。不可见的代理任务与持续关注暂停，切回不会自动重发。
- 联系人别名、任务、关注事件和汇报保存范围；WorkBuddy 带 Bunny 标记的任务须精确映射持久记录，未知或已删除的标记隐藏。无 Bunny 标记的外部 WorkBuddy 工作信息按用户指定规则归工作；已完成的启动前历史不回放。
- 原生库新增单调递增摄入序号。相同毫秒、系统时间回拨、删除最大记录都不会让后续消息落在整理水位之前；备份恢复保留序号、水位、范围及来源图。
- 最近上下文按完整回合和预算选择，默认最多八轮；不把旧回合的半句限制截断后送入模型。超长旧回合仍保留原文，可经相关检索定位。
- 小憩按六个合法 domain/floor 分区增量处理，原文不删除；候选事实、标签、来源摘录与水位原子提交。模型等待不占写事务；前台对话开始即暂停后台。
- 本地每日05:00到期检查，启动/解锁/运行期可补跑；手动提供“小憩”“整理记忆”。无新增不调用模型。每分钟最多三次、滚动24小时默认最多一百次，调用前持久记账；仅使用目录当次确认免费的后台模型，不切换高倍率模型。
- 整理记忆先补小憩，再保守归档各分区最近200条中的完全重复普通记忆；保留来源和原文，跳过固定、受保护条目。
- 明显密码、私钥和接口密钥在普通输入入口拦截；不将识别出的秘密写入普通历史或朗读。接口密钥继续走现有本地设置。
- 表达状态由有来源事件、平滑衰减与统一生活时钟形成，不增加情绪判断模型请求。各可见层级独立限速和保留事件，私聊事件不会挤走工作表达依据；只投影当前允许且仍存在的来源，不改变任务履约标准。
- 正式连接测试与对话共用完整协议请求层；仅格式失败可在同一总时限内修复一次。WorkBuddy调用尊重剩余超时，额外请求参数不再吞掉用户选择的思考强度。后台提取为推理与完整JSON共同保留输出预算，空正文和预算耗尽能区分并保住进度。

## 验证方式

场景矩阵、原生迁移、来源继承、密文范围篡改、完整回合预算、ASR旧代次、任务与关注跨场景取消、备份恢复以及整理作业均有隔离检查。整理另用真实SQLite、临时资料库、测试密钥和替代提取器验证；这与真实模型抽取质量、真实微信入站自动回复的验收不同。

本机9000条合成记录（每场景3000条）的单次观测：检索p95约5.2–14.0ms，上下文组装p95约15.6–32.0ms。范围、预算、完整回合和热门私聊词不挤掉工作候选的检查通过；这不是多年真实数据或对话质量的证明。复测入口：`tools/benchmark-memory-scenes.js`。

## 本轮边界与后续顺序

1. 摘录是可溯源导航，模型推断仍是待确认候选；不宣称已经自动理解多年资料。
2. 当前dream是有限范围的保守去重，尚未实现全池冷区轮转、语义合并、有效时间归并和完整困惑处理。
3. 独立小本本与密码保管入口仍待实现。输入拦截是补充保护，无法识别任意口述秘密；macOS系统识别也不等于所有环境均已验证完全离线。
4. 工具/经验版本注册、用户速写、主动澄清和更丰富的个性化反馈在后续阶段推进。不会让整理器执行记忆里的代码，或让Bunny替代WorkBuddy的复杂工作职责。

后续以独立样本和真实应用回执继续推进；先验证范围、恢复与性能，再增加语义自动化。
