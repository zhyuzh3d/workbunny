# WorkBuddy 软件技能

## 任务提示词与网页交付

交办提示词围绕具体目标、必要上下文、成果形式和可观察的验收条件精心设计，兼顾效率和质量。把多轮指代和确认过的细节补全为准确目标，必要的格式、路径、数值、逐字内容及限制不可遗漏。主人原文与来源只留在 Bunny 私有记录，不附入 WorkBuddy 正文或复制到制作背景；不堆无关历史、其它软件操作手册、收件人或重复限制。WorkBuddy只做本轮工作，宿主负责按实际授权回传结果。这些是Bunny整理与操作的经验，不作为每次交办的固定前后缀。正文不重复Bunny内部授权说明、宿主分工或其它软件的泛化禁令；只保留会影响本轮结果的具体目标、背景、约束和验收。首次、续办和自动修订都按本轮需要组织，不机械附加生命周期说明；真实约束不能为求简短而省略。

任务背景按WorkBuddy实际执行需要组织，不转述Bunny的语音识别、纠错、意图分类、路由或内部推理过程。能结合有效上下文确定的要求直接整理为准确目标；金额、日期、对象等必要条件仍有歧义时核实该条件，不加泛化的识别免责声明。主人要求研究识别过程或逐字写入的文字属于实际任务材料，须准确保留；原始请求和感知来源仍由Bunny私有记录保存。

制作网页小游戏、交互网页等网页作品时，按实际用途区分最终可访问的网页入口与供本地打印、离线阅读或归档的 HTML 文件。本地文件用途按文件验收；网页入口按本任务适用的既有偏好和明确公开授权验收，即使网页形式是在执行中才选用也一样。普通文件请求或操作经验不能自动变成公开权限。主人明确只做本地、不发布或只要代码时，遵从该要求。

主人已明确允许使用 WorkBuddy 的公开网址能力，且该授权覆盖本任务时，结合可分享入口的交付偏好，将取得真实网站链接及核验实际可访问纳入制作目标和验收；不交付只能在本机运行、无法分享的网站。保留已有有效授权，不因后选网页形式而遗漏。交付偏好本身不是公开授权，也不据此付费、注册登录、代替主人接受条款或公开私密资料、密钥及内部资源。缺少必要权限或发布条件时保留成果，说明准确缺口，不绕过限制。

公开链接必须真实对应本轮作品，能在本机之外独立访问；核对实际页面、关键内容与适用交互，回收完整 URL、分享码及必要访问条件。网址格式正确、本地预览、HTTP 200、登录页、截图或口头承诺均不足以证明公开交付。入口或访问证据缺失时在原任务继续补齐，不能把未验证的网址或其它作品当作本轮成果。


先把主人多轮对话整理为完整任务说明，正文只提供本轮目标、必要背景、约束、成果形式和验收条件，不发送原始聊天或“主人原文”段落。首次、续办及自动修订采用同一原则；原始交办和来源仅留在 Bunny 私有记录。新工作默认新建通用任务，不关联应用、空间或项目；只有主人明确指定，或Bunny结合目标与可靠经验确认归属时才选择，并保留选择依据。优先使用 WorkBuddy 专用 AX 控件，失效时使用截图和键鼠。

输入前确认工作位置、模型和空草稿。提交后绑定唯一会话与消息标记，增量观察真实工作记录；结果不明时不重新发送。确认原提交未生效后，按框架记录依据，保留原文、会话和轮次，选择有效方法续完原草稿。当前草稿与任务无关时先保留。

最终答复属于执行证据。回收实际结论与产物，针对缺项在原会话继续检查；正常完成后极简汇报实际结果。主人指定微信渠道时只向该渠道交付，无法发送时保存待交付。

遇到恢复性故障，先重新观察并尝试可用替代方法。经验是可修正的方法，不是授权。

WorkBuddy只负责制作本轮产物，主人要求的微信交付由Bunny回收后执行。工作空间需要明确对应证据，执行软件名称不能作为选择同名集成项目的依据；无对应就继续无空间任务。

视觉兜底统一使用 screen.observe 的 frameId 和预览尺寸。文字按钮用 screen.action 的 label 与视觉模型定位；无文字图标与空白区域才使用 targetType 和预览图整数 pixelX/pixelY。操作后重新观察，画面引用失效就重新定位，不沿用旧坐标。


## 新任务、应用与工作位置

独立工作使用全新任务身份与关联标记；用户补充已有工作时才续办原会话。不能继承当前 Buddy 应用或上次空间。先识别当前页面：应用页切回通用页，已有会话则切到新任务页，保留原会话和应用各自的草稿；通用新任务页确有无关草稿时保留内容并说明具体阻塞，不清空、不假装仍在交办。空编辑器的提示文字不等于用户草稿。输入前按任务上下文复查最终位置；未明确关联的任务选择“不使用工作空间”。

用户指定 Buddy 应用或项目，或你根据可靠经验决定使用时，把名称和依据放入 workContext；不要因为正文提到项目名、执行软件名或当前界面选中某处就关联。指定位置不可确认时重新观察或补证，不悄悄转到其它项目。

## 可见交办、效率与恢复

专用接口找不到唯一导航对象，只说明该方法当前证据不足，不等于任务失败或已经提交。未输入、未提交且原草稿已保留时，可以转到仅按显示像素及视觉模型确认身份和区域的当前截图，结合任务确认工作位置、新编辑区、空草稿和实际输入条件，再沿同一交办继续；不要反复调用同一失效接口耗尽恢复预算。已有输入或提交迹象时先核对原稿及实际会话，不借换方法重新填充或重发。


WorkBuddy 的模型推理接口与桌面任务交办是不同能力。当前本机 5.9.3 的认证 IPC 实测开放模型请求与授权能力，未开放桌面任务创建；随包 CLI 入口的独立帮助调用缺少运行模块，不能据此声称它已经能完成桌面交办。版本变化后可重新探测。不能用单纯模型回答或独立隐藏 CLI 会话冒充 WorkBuddy 应用中可见的任务。

优先尝试不抢全局输入的后台定向控件：用真实进程和窗口身份、唯一控件、原文读回和唯一消息标记核对。不支持或失效时根据回执换方法；需要视觉键鼠时根据当前截图复查目标，输入前后受干扰则重新定位、保留同一任务和已有草稿。明确未发出的动作可以恢复；提交结果未知时先读取原会话记录，不能新建另一份或重复发送。任务必须在 WorkBuddy 界面可见，且用真实会话/消息记录绑定后才认定已接收。后台跟进已有会话不依赖当前前台应用。


本机 5.9.3 的实测恢复经验：AXSetValue 可能只改变可见编辑文字，发送按钮仍禁用，不能认定软件已接纳输入。优先用定向到真实 PID 的键盘输入并完整读回；不能依赖后台 Cmd+A，一旦需要恢复草稿，应核对原文后使用受支持的文本选区，或回到有焦点校验的前台输入。编辑器会把软换行序列化为 FEFF+换行+FEFF；只能规范化这种已确认的边界哨兵，不得任意删字符、裁剪空白来凑匹配。实际会话与唯一标记绑定后才算交办成功；启动桌面执行器的旧回执不等于已提交，恢复必须沿用原操作。

缩窗或收起侧栏后，工作空间选择器仍可能贴着编辑器左下方；不要沿用窗口横向百分比或旧截图坐标。先结合当前画面与 inspect 返回的编辑器、弹出控件、候选数量定位；多个候选或结构不全时补充关键证据，必要时调整窗口布局后重新核对。不能把 homeReady 单独当作工作位置确认，也不能重复同一失效检查来声称恢复。保留草稿和原操作，明确说明还缺哪个事实。此定位经验仍需按实际版本修订。

纯制作任务只交给 WorkBuddy 本轮制作目标、必要上下文和验收要求；历史提及的微信或其它渠道不是新的交付授权。没有明确交付渠道时不能补入文件传输助手或其它收件人。

草稿已写入而尚无提交动作时，恢复应核对同一窗口、完整原文、模式/工作位置和可提交条件，只继续这一份草稿，不重新填写或新建。若发送按钮禁用，不用重写同文去强行启用；先明确还缺的条件。若提交可能已发出，首页仍有草稿或暂未看到新消息都不足以单独证明未提交；先核对精确回执，证据不足则保留原稿与未知记录。

## 视觉交办操作经验

先结合 workContext/workRoute 与当前画面确认工作位置；未关联项目时选择“不使用工作空间”，不继承旧空间。问答、文档、PPT、调研等不依赖代码项目的任务通常使用办公模式；开发与项目修改先核对本轮明确项目。没有唯一必要项目时保留现场并说明缺口，不把未选择空间的开发页当作可提交。

独立交办在新任务页选择本次许可的模型，将宿主提供的 outboundText 完整原文输入一次并提交；不代替执行者回答任务。已有非空草稿先保留。指定免费 Hy3 时结合当前画面中的真实选中项与免费价格核对；所选档位已经核实时继续，不重复选择。界面明确存在推理强度控件时才按本次参数设置，不能把规划模型参数当成客户端设置的证据。

输入区位置须来自当前画面。已有唯一输入区却尚未聚焦时可用 type 的 focus 坐标合并点击与输入；已聚焦且证据仍有效时不重复点击。动作可连续安排已确认的位置和短等，未知后续界面先观察。原文提交后只观察真实回复与进度，未知提交先核对，不能再次填写或发送。

纯视觉观测、区域、身份和键鼠均通过显示像素与视觉大模型；本节的操作方法不要求窗口/进程信息或 AX。WorkBuddy 的结构化适配是独立可选能力，不能成为纯视觉兜底的定位基础。
